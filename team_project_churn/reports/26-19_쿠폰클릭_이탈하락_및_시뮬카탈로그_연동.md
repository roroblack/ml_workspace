## 1. 쿠폰/액션 클릭 → view 이벤트 → 이탈률↓ (수정)

### 1.1 문제
`ChurnActionPanel`에서 **`sns_view`만** 클릭 시 `logViewEvent`(인게이지먼트)를 기록했고, **할인 쿠폰(`discount`/`discount_related`)은 클릭 핸들러가 없어** 쿠폰을 눌러도 이탈률이 안 내려갔다.

### 1.2 수정
- 할인 쿠폰 배지를 **클릭 가능한 버튼**으로: "🎟️ N% 할인 쿠폰 받고 상품 보기 →".
- `onCouponClick`: 클릭 시 **해당(연관) 상품 `logViewEvent`** 기록 → 세션 이벤트에 view 추가 → 다음 4초 폴링의 `/api/churn/predict`가 인게이지먼트 반영 → **이탈률 하락**.
- 동작 루프(이탈방지 닫힘): `쿠폰 노출 → 클릭 → view 이벤트 → 재예측 → churn↓`. (sns_view와 동일 메커니즘을 할인 쿠폰에도 적용.)
- `pnpm check`(tsc) 0에러.

> 이벤트 영속: `logViewEvent → tRPC events.logEvent`(db.ts 인메모리 폴백) → `getSessionEvents`가 되읽음 → 다음 예측에 포함. DB 없이도 루프 성립.

## 2. 시뮬 사이트 seed 카탈로그(54k) 연동

### 2.1 문제 (확인됨)
로컬 시뮬(localhost:3000) 상품목록이 **정적 `productData.ts`(25개)** 만 사용 → `neon/seed/products.csv`(**54,571개**)가 화면에 반영 안 됨.

### 2.2 수정 (백엔드 카탈로그 API + 프론트 재배선)
**백엔드**(`catalog_store` + `sim_external_router`):
- `catalog_store.search_products(limit, category, brand, q)` + `brands()` + `total_products()` 추가(seed CSV 인기순 n_events).
- `GET /api/catalog/products?limit=&category=&brand=&q=` → **total 54,571**, 인기순 상품(product_id·brand·price·category·n_events·name).
- `GET /api/catalog/facets` → 카테고리 20 + 브랜드 30(드롭다운).

**프론트**(`fastApiClient` + `ProductList`):
- `getCatalogProducts(opts)`·`getCatalogFacets()` 추가.
- `ProductList`: 정적 `SAMPLE_PRODUCTS` → **백엔드 카탈로그 fetch**(카테고리/브랜드/검색 서버사이드 필터). **백엔드 미연결 시 정적 25개 폴백**(가짜값 아님, 실제 폴백).
- `handleProductClick`: 동적 카탈로그/정적 모두 `filteredProducts`에서 조회해 view 이벤트 기록.

### 2.3 검증
| 항목 | 결과 |
| --- | --- |
| `/api/catalog/products?limit=3` | **total 54,571**, 인기순(grattol n_events 141,650 …) ✅ |
| `/api/catalog/facets` | 카테고리 20 · 브랜드 30(UNK·masura·irisk·runail…) ✅ |
| `pnpm check`(tsc) | 0에러 ✅ |
| 로컬 시뮬 3000 / | HTTP 200 ✅ (HMR 반영) |

→ 이제 **localhost:3000 상품목록이 REES46 54,571개**(인기순, 카테고리/브랜드 필터)로 뜬다. 미연결 시 25개 정적 폴백.

> ⚠ 데이터 특성: REES46 화장품은 **상품/카테고리 이름이 없음**(category_code 결측) → 상품명은 `Product {id}`, 카테고리는 `category_{id}`로 표시. 브랜드·가격·인기(n_events)는 실값. (이름 표시가 필요하면 별도 매핑 필요 — 26 카테고리 매핑 논의 참조.)

## 2.5 카테고리 이름 매핑(화장품) + 푸시에 추천 4상품 (추가 요청)

### 문제/배경
웹서치 확인: REES46 화장품은 **category_code가 거의 결측**(525중 18, 그나마 vacuum·glove 등 비화장품 노이즈) → 공식 카테고리명 없음. 사용자 합의: **"임의 매핑이어도 됨"**(실제 category_id에 그럴듯한 화장품 카테고리·브랜드 임의 매핑).

### 매핑 생성 (`simulation_site/neon/make_category_names.py`)
- 525개 category_id를 **인기순(n_events)** 정렬 → 네일/메이크업/스킨케어 품목 36종 풀에서 배정 + **실제 top_brand** 결합.
- 산출 `seed/category_name_map.csv`. 예: `네일 폴리시 · Bpw.Style`, `젤 네일`, `네일 팁 · Masura`, `매니큐어 세트 · Grattol`.
- 결정적(랜덤X) — 재실행해도 동일.

### 백엔드 반영 (`catalog_store`)
- `_name_map()` 로드 → `display_name`을 매핑 이름으로 override. `name_of(cid)` 공개.
- 적용 범위: **시뮬 상품목록**(`category_name`) · **facets 드롭다운**(실 카테고리/브랜드) · **대시보드 추천 카테고리**(`dataset_reader.recommendations`가 `name_of` 우선).
- 검증: 추천 parquet의 18자리 category_id ↔ seed 매칭 확인 → `name_of` 해석 OK.

### 푸시에 카테고리 + 추천 4상품 (`sim_usecase` + `ChurnActionPanel`)
- 신규 `recommend_for(tc, k=4)`: 관심 카테고리 → 유사 카테고리 1개 + 그 카테고리 **상품 4개(브랜드·가격)** 반환.
- `decide_action` 액션 payload에 `recommendation{category_name, items[4]}` 포함, 메시지에 카테고리명 노출.
- `ChurnActionPanel`: 카테고리명 + **상품 4개 그리드(브랜드·$가격)** 렌더, 각 상품 **클릭=view 이벤트 → 이탈률↓**.
- 검증: `/api/churn/predict`(cart×2 미구매) → `discount_related` "…+ '베이스·탑코트' 추천상품" + items[uno $10.23·grattol $6.25·…]. `pnpm check` 0에러.

## 2.6 시뮬에 이탈 지표 3종 표시 (7일 churn · 하자드 · bounce)

### 요청
시뮬 위젯이 **3종 이탈값을 서버에서 받아 표시**: ①기존 7일내 churn ②하자드 적용 ③bounce(30분).

### 백엔드 (`sim_usecase.churn_three` + `/api/churn/predict`)
| 지표 | 산출 | 모델/소스 |
| --- | --- | --- |
| **7일 이탈(집계)** | v2 22피처 집계 → 활성모델 `loader.score` | prep_*_v2.joblib(LightGBM/CatBoost…) |
| **실시간 하자드** | `session_hazard.session_risk`(세션 시퀀스 위험) | 도메인 하자드(학습0·설명가능) |
| **Bounce(30분)** | `session_bounce_model.joblib`(`{pipeline,feat,gap_sec:1800}`) | 시퀀스 8피처 모델 |

- `churn_three()`가 셋을 한 번에 산출 → 응답에 `churn_breakdown:[{key,label,probability}]`. 헤드라인/액션은 **하자드** 기준(기존 동작 유지). 모델 없으면 해당 값 `null`.
- bounce 피처(`step·dt_prev_log·n_*_sf·price_*·is_first`)는 기존 `_session_feature_row`와 동일 → 그대로 채점.
- 검증: cart 포함 세션 → **7일 28.5% · 하자드 55.0% · Bounce 45.2%** 동시 반환 ✅.

### 프론트 (`FloatingChurnWidget`)
- `churn_breakdown` 수신 → 헤드라인 % 아래 **3종 막대+퍼센트**(라벨·색상 위험도별) 렌더. 4초마다 갱신.
- `pnpm check` 0에러.

## 2.7 시뮬 버그·UX 수정 4건 (상세버그·아이템명·로그스크롤·SNS조건)

| # | 문제 | 원인 | 수정 |
| --- | --- | --- | --- |
| 1 | 상품 클릭 시 **"Product not found"** | `ProductDetail`이 정적 `getProductById`만 조회 → 54k 카탈로그 id 없음 | 백엔드 `GET /api/catalog/product/{id}` 신설 + `getCatalogProduct()` fetch(정적 폴백). 상세에 **상품 ID 함께 표시** |
| 2 | 아이템이 **ID만** 표시 | REES46 상품명 결측 | 화장품 품목명 풀 49종(웹서치) → 인기순+브랜드 결정적 매핑(`catalog_store.ITEM_POOL`). 예: `Grattol 젤 폴리시`, `Runail 글리터 젤` |
| 3 | 이벤트 로그 **아래 항목 잘림** | flex 자식 ScrollArea에 `min-h-0` 없어 안 줄어듦(전형 flexbox 스크롤 버그) | `ScrollArea`에 `min-h-0` 추가 → 내부 스크롤 동작 |
| 4 | **SNS 제안이 둘러보는 중 계속** + 추천상품 클릭 시 이동 안 됨 | SNS 조건이 `p≥0.6`(하자드 높으면)이라 항시 발동 / 추천 클릭에 네비게이션 없음 | SNS 조건을 **첫 접속(n_events=0) 또는 마지막 이벤트 후 idle≥30s**로 변경(`action_from_events`가 idle 계산). 추천상품 클릭 시 **상세페이지 이동**(`setLocation`) |

검증: 상품명 `Grattol 젤 폴리시`·단건 조회 OK / SNS = 방금활동(idle 2s)→**none**, 무활동(idle 120s)→**sns_view(idle_high)** / `pnpm check` 0에러.

> SNS 트리거는 사용자 정의대로: ①처음 접속 ②이전 이벤트 후 장시간 무활동(이탈 상승). 활동 직후엔 미노출. 임계 `SNS_IDLE_SEC=30s`.

## 2.8 Churn 헤드라인·하자드 점검·게이지·쿠폰 구매 루프

### ① Churn Rate 헤드라인 = 3종 중 최댓값
`FloatingChurnWidget`이 `churn_breakdown` 3종(7일·하자드·bounce)의 **max**를 헤드라인으로 표시(사용자 요청). 검증: 3종 {7일 13.2·하자드 14.5·bounce 78.3} → 헤드라인 **78.3%**.

### ② 하자드 오르내림 — 점검 결과 "정상"
- 동일 입력(고정 타임스탬프) 3회 호출 → 23.3→23.9→24.5% **단조 상승**(오르내림 X). 백엔드 하자드는 **idle(마지막 이벤트 후 무활동)이 길수록 이탈↑** 설계대로 동작.
- 프론트에서 오르내려 보인 건 **새 view가 기록되면 idle 리셋→하자드 하락→다시 상승**하는 정상 루프. 헤드라인을 max로 바꾸면 7일·bounce(idle 무관)가 섞여 더 안정적으로 보임.

### ③ 3종 막대 게이지 안 차던 버그
원인: 막대 색을 `getChurnColor(v).replace('text-','bg-')`로 **동적 생성** → Tailwind JIT가 해당 클래스를 못 만들어 배경색 누락(빈 막대). → **정적 `getBarColor`**(bg-green-400 등 리터럴) 반환으로 수정.

### ④ 추천상품 클릭 → 상세이동·쿠폰가 구매·재참여 시 사라짐
- 추천상품 클릭 = view 기록 + **`/product/{id}?coupon=N`** 으로 이동(`ChurnActionPanel`).
- `ProductDetail`이 `?coupon` 읽어 **원가 취소선 + 할인가 + '🎟️ N% 쿠폰 적용'** 표시, **할인가로 장바구니 담기/구매**(`finalPrice`).
- 액션(장바구니/조회 쿠폰)에 **idle 게이트(`CART_IDLE_SEC=5s`)** 추가: view 발생(재참여)으로 idle 리셋되면 제안이 **다시 안 뜸**. 검증: idle 1s→none, idle 20s→discount_related.

> 운영 메모: 백그라운드 재기동이 **옛 백엔드가 8090 점유→새 uvicorn 바인딩 실패(좀비)** 로 한 차례 stale 응답을 줬음. 포트 점유 프로세스를 모두 종료 후 재기동해 해소(검증값은 클린 백엔드 기준).

## 2.9 대시보드 3종 앙상블·액션/근거 + 쿠폰 등급 4단계 (미리포트분 정리)

### 쿠폰 등급 — "다 5퍼" 문제 수정
- 원인: `coupon_grade(p)`가 **hazard만** 기준 → cart 세션은 hazard가 억제(mult 0.55)돼 p<0.5 → 항상 5%.
- 수정: ① **4단계** 80%↑→20%(긴급)·65–80%→15%(경고)·50–65%→10%(주의)·else 5%(관심). ② 등급 기준을 **3종(7일·하자드·bounce) 최댓값**(= 헤드라인 Churn Rate)으로. → 검증: 고이탈 cart 세션 max 77.5% → **15%(경고)** 발급(예전 5% 고정 해소).

### 대시보드 개인 진단 — 3종 앙상블 현황 + 액션/근거
- 백엔드 `diagnose_user`에 **category 추천 앙상블 + bounce 앙상블** 블록 추가(모델별 시드 + 합산). bounce 멤버=산출물 5종(GRU·LGBM·XGB·Cat·Transformer), category=부스트3+Transformer.
- `_diag_action`: churn 높을 때만 **수행 액션 + 근거** 반환(낮으면 None).
- 대시보드 `live_diagnosis`:
  - **🎯 Churn Rate = 3종 최댓값**(액션 수행 기준) 헤드라인 추가.
  - **🎯 수행 액션 + 근거**: Churn Rate ≥ 50%면 등급별 쿠폰(10/15/20%) + 근거(7일·하자드·세션/바운스·무활동일) 표시, 낮으면 "액션 없음".
  - **🧩 3종 앙상블 표**(7일 이탈·카테고리 추천·Bounce) 모델별→합산.
  - **EMA**: 첫 render = 시드(고정값), 이후 = **실시간 활동 반영(이전값 가중 ALPHA=0.7)**. category는 (1−ChurnRate), bounce는 ChurnRate에 비례 반응.
- 검증(유저 613590885): 7일 70.4%·하자드 63.2%·category앙상블 65.4%·bounce앙상블 63.2% → 액션 **15% 쿠폰**(근거 "7일 70%·하자드 63%·7일 무활동").

### 쿠폰 버튼 클릭 무반응 수정
`ChurnActionPanel.onCouponClick`이 view만 기록하고 이동이 없어 "아무것도 안 나옴" → **첫 추천상품으로 쿠폰 적용해 이동**(`/product/{id}?coupon=N`), 추천상품 없으면 `/products?coupon=N`.
