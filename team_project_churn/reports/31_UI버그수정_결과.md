# 31. [UI 수정] 회원가입·스크롤·그래프/모델수 버그 (가지마)

체크포인트: 가지마 `feature/backend` `6a64553`. 사용자 보고 3건 처리.

| # | 증상 | 원인 | 수정 |
| --- | --- | --- | --- |
| 1 | 이름 입력했는데 "user_id 입력하세요"·회원가입 안됨 | 폼 미사용으로 필드 분리 리런 + user_id 필수인데 이름칸만 입력 | **`st.form`으로 묶음**(회원가입·로그인) + "아이디 필수, 이름 아님" 명확화. MySQL 미연결 시 "MySQL 연결 필요" 명확 메시지 |
| 2 | 아래 내용 있을 때 스크롤 안 됨 | `main.css .block-container`가 **전역**으로 `max-width:560px·display:flex·중앙정렬`(랜딩용)이라 대시보드 위쪽이 잘리고 스크롤 막힘 | 대시보드에서 `block-container`를 **전체폭·일반흐름**(`display:block·min-height:auto`)으로 복원 CSS 주입 |
| 3a | 선형 그래프가 안 보임 | ROC/PR 라인은 관리자 진단탭에만 있었음 | **개요 탭에 ROC·PR 선형그래프 추가**(전 역할) |
| 3b | 모델이 7개인데 적게(6) 나옴 | Transformer는 `val_auc`만 있어 `auc` 요구하는 비교표에서 제외 | 비교표·AUC막대에 **Transformer(val, 시퀀스 표기) 포함 → 7모델** |

## 검증
```
comparison_table 모델수: 7 (CatBoost·XGBoost·LightGBM·RandomForest·LogReg·Transformer·DecisionTree)
chart auc_bar/roc/pr 빌드 OK · app import OK
```

## 참고
- 회원가입 실제 저장은 **MySQL 연결 필요**(SQLite 미사용 합의). 미연결 시 명확 안내. 로그인은 미연결이어도 진입(로그 저장만 생략).
- 로그인 버그 점검 결과: 로그인은 uid 기본값+키로 동작했으나 일관성 위해 동일 form화.
- 커밋 규칙 준수: 가지마는 `feature/backend`에만(6a64553), main 미접근.
