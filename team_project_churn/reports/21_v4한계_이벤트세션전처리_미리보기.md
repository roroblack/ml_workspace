## 1. 결론 — 현재 v4로는 불가 (구조상)
- v4의 전처리 소스(`models_bayes_one.py`)는 **raw 이벤트를 읽지 않는다.** 이미 만들어진 **코호트 10피처(`train_cohort_tabular.parquet`)를 받아 scaler/log/imbalance 변환만** 한다.
- 따라서 v4는:
  - **바운스 ❌** — 코호트(recency≤7, 전체의 **8.6%**)가 조기 바운스·휴면 유저를 제외. 집계피처라 세션/Δt 신호도 없음.
  - **초단위 세션 이탈 ❌** — 라벨이 7일 무활동, 피처가 일/주 집계.
  - **아이템/카테고리 추천 ❌** — 입력에 product/category/brand 컬럼 자체가 없음.
- raw→피처 생성 소스는 v4에 없고 상류 `v2_5m/src/prep_5month.py`에 있음. **v4는 능력을 추가할 자리가 없다.**

## 2. 제안 전처리 = 이벤트/세션-단위 (실데이터 결과)
REES46 2019-Nov 실데이터로 **이벤트/세션 단위 전처리**를 돌려 30행 미리보기 생성.

- 이미지: `preprocessing_project/v4_model_prep/output/_preview/session_event_preview.png`
- 표(CSV): `.../session_event_preview.csv`

### 새로 생기는 컬럼(현재 v4엔 없음)
| 컬럼 | 의미 |
| --- | --- |
| `dt_prev_s` / `dt_next_s` | 행동 간 시간간격(초) — 초단위/실시간 핵심 |
| `bounce` | 세션 1이벤트=1 (바운스 포착) |
| `churn30` | 다음 활동까지 30분+ =1 (초단위 세션 이탈 라벨) |
| `event_type`·`category_id`·`brand`·`price` | 아이템/카테고리 추천 신호 |

### 미리보기에서 읽히는 것 (실데이터)
- **BOUNCE 행**: view 1회 후 이탈(`bounce=1, churn30=1`). 현재 v4 코호트에선 제외되는 유저가 **여기선 한 행으로 잡힘**.
- **CART-ABANDON 세션(1a345e)**: cart 5회 → 368초 정지 → 이탈. **Δt 23초→368초 "이탈 가속"** 이 그대로 보임(v4 집계는 평균으로 뭉갬).
- **PURCHASE 세션(f873d1)**: cart→cart→purchase, Δt 52→124초 몰입 후 구매, 구매 직후 세션 종료.

## 3. 5m 호환 (추가형)
- 5m 정본(코호트 tabular + 주별 seq + `churn`)은 **불변**.
- 신규 = **전체 모집단 기반 + 세션 라벨(`churn30`) + 이벤트/아이템 피처** → 새 디렉토리(`processed_eventseq`)·새 model_type(`session_churn`)으로 **추가만**. [17-6-5] 4원칙 준수 → 호환 유지.
