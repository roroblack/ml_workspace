# 16. 데이터 전처리 기법 정리 + 베이지안 최적화로 찾은 최적 전처리

목적: 본 프로젝트에서 쓴 전처리 기법을 모두 정리하고, **베이지안 최적화(optuna TPE)** 로 전처리 조합을 탐색해 최적안을 도출한다. 코드: `preprocess_bo.py` / 결과: `outputs/preprocess_bo.json`.

---

## 1. 사용된 데이터 전처리 기법 (전체 정리)

| 분류 | 기법 | 적용 위치 |
| --- | --- | --- |
| 식별자 제거 | CustomerId·Surname / user_session 등 제거 | Bank, REES46 |
| 결측치 처리 | Bank: 0건 / REES46: `dropna`(CustomerID·event_time), 카운트 `fillna(0)` | 전 데이터 |
| 이상치 처리 | Bank: **IQR 점검**(제거 X, 의미있는 극단값 보존) / REES46: 취소건·Quantity≤0·UnitPrice≤0 제거 | Bank, REES46 |
| 범주형 인코딩 | **One-Hot**(Geography·Gender, `drop_if_binary`) | Bank |
| 수치형 스케일링 | **StandardScaler**(정형), 시퀀스는 **feature별 표준화** | Bank, sample, 시퀀스 DL |
| 로그 변환 | `log1p(price)`, `log1p(time_gap)` (스텝 피처) | REES46/게임 시퀀스 |
| 시계열 라벨링 | 관찰/결과 기간 분리, **결과기간 무활동=이탈**(recency) | REES46, 게임, sample |
| 시퀀스화 | 일·주별 이벤트(view/cart/purchase) 카운트 → `[N, T, F]`, **0 패딩** | 시퀀스 DL |
| 집계 피처(RFM) | recency·frequency·monetary·active_days·다양성 | REES46, sample |
| 층화 분할 | `train_test_split(stratify=y)` (8:2) | 전 데이터 |
| 불균형 처리 | `class_weight="balanced"`, DL `BCEWithLogitsLoss(pos_weight)`, (SMOTE 실험) | 전 데이터 |
| 표본추출 | 사용자 표본(CPU 고려) | REES46, 게임 |
| **누수 방지(공통)** | 스케일러·인코더는 **train에만 fit**, 그 외 transform만 | 전 데이터 |

## 2. 베이지안 최적화 설정

- 데이터: **Bank Churn** (10,000행 × 10피처, 이탈률 20.4%) — 전처리 선택지가 가장 풍부.
- 목적함수: **5-fold Stratified CV ROC-AUC** (전처리는 **fold마다 fit** → 누수 차단, imblearn Pipeline).
- 샘플러: **TPE**, 40 trial.
- 탐색 공간(전처리 + 모델):

| 요소 | 후보 |
| --- | --- |
| 인코딩 | one-hot / ordinal |
| 스케일링 | standard / minmax / robust / none |
| 이상치 | none / IQR clip |
| 불균형 | none / class_weight / SMOTE |
| 모델 | logreg / rf / gbm |

---

## 3. 결과 — "전처리보다 모델이 지배한다"

- **baseline**(one-hot + standard + 이상치 없음 + GBM): CV AUC **0.8662**
- **best**(one-hot + minmax + 이상치 없음 + class_weight + GBM): CV AUC **0.8662** → **baseline 대비 +0.0000**

### 전처리 요소 중요도 (optuna)
| 요소 | 중요도 |
| --- | --- |
| **model** | **0.997** |
| encoding | 0.002 |
| imbalance | 0.0005 |
| outlier | 0.0001 |
| scaler | 0.000 |

### 요소별 최고 CV AUC
| 요소 | 옵션별 best AUC |
| --- | --- |
| 모델 | **gbm 0.866** / rf 0.854 / logreg 0.769 |
| 인코딩 | onehot 0.8662 / ordinal 0.8637 |
| 스케일링 | minmax·none 0.8662 / standard 0.8658 / robust 0.8637 |
| 이상치 | none 0.8662 / IQR 0.8658 |
| 불균형 | none·class_weight 0.8662 / **SMOTE 0.8648(↓)** |

### 해석
- **전처리 조합을 아무리 바꿔도 AUC는 0.864~0.866으로 거의 고정.** 결정적인 건 **모델(GBM)** 이고, GBM은 **트리 기반이라 스케일링·이상치·인코딩 방식에 거의 둔감**합니다.
- **SMOTE는 오히려 미세하게 손해**(0.8648) → 이 데이터엔 class_weight/임계값이 더 적절.
- 즉 **"최적 전처리 = 최소 전처리 + one-hot + GBM"**. 스케일링/이상치/오버샘플링은 GBM에선 불필요.

---

## 4. 최적 전처리 결론 (실용 권고)
1. **모델을 GBM(또는 부스팅 계열)으로** — 가장 큰 레버(AUC +0.10 vs logreg).
2. **범주형 = one-hot**(ordinal보다 근소 우위), 트리 모델이면 **스케일링 생략 가능**.
3. **이상치 제거 불필요**(IQR clip이 오히려 약간 손해), 의미있는 극단값 보존.
4. **불균형은 SMOTE 대신 class_weight / 임계값 조정**.
5. logreg/스케일 민감 모델을 쓸 때만 StandardScaler가 의미 있음.

> 주의(데이터 의존): 본 결론은 **Bank(소규모·범주 적은 정형)** 기준. **REES46처럼 범주가 많고(카테고리 463)·시퀀스가 있는** 데이터에서는 **타깃/빈도 인코딩·시퀀스 구성·집계 피처**가 더 큰 영향을 줍니다.

## 5. 추가 개선 방향
전처리는 천장(AUC ~0.866)에 도달 → **다음 레버는 전처리 밖**에 있습니다.

1. **피처 엔지니어링(ROI 최상)**: 상호작용(나이×활성도), 구간화(나이/잔액 bin), 도메인 파생(잔액 0 여부, 상품수×활성). 전처리 조합 튜닝보다 효과 큼.
2. **모델 고도화**: **XGBoost/LightGBM/CatBoost**(범주형 네이티브), **스태킹/보팅 앙상블**. (현재 미설치 → `pip install`)
3. **모델 하이퍼파라미터 베이지안 튜닝**: 전처리보다 **모델 HPO**가 추가 향상의 핵심.
4. **임계값 최적화 / 비용기반 결정**: 불균형(20%)에서 recall·F1·기대비용 기준 운영점.
5. **설명가능성(SHAP)**: 개별 이탈 사유 → 리텐션 액션 연계(발표 임팩트).
6. **데이터 확장**: 정적 표 → **행동·시계열 피처**(REES46 시퀀스). 라벨이 순서형이면 시퀀스 DL이 가치(앞 리포트 13 참조).
7. **범주형 인코딩 고도화**(범주 많은 데이터): 타깃 인코딩(CV 누수 차단)·임베딩 — 단 Bank엔 무의미, REES46/고카디널리티에서 유효.
