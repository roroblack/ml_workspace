## 2. 백엔드 라이트 클린아키 — 레이어 매핑 (풀→라이트)
| 클린아키 레이어 | 풀(제안) | **라이트(채택)** | 비고 |
| --- | --- | --- | --- |
| interfaces/http | routes+controllers | **routes/** (컨트롤러 인라인) | 라우트별 파일 유지 |
| application | usecase 6파일 | **usecases.js 1파일** | 함수 분리 |
| domain | 엔티티 5파일 | **usecases.js에 병합** | 도메인 얇아 별도 불필요 |
| infrastructure/mysql | repo 4파일 | **repositories.js 1파일** | 테이블별 함수 |
| infra/{neon,files} | 2파일 | `neon.sim.js`·`artifacts.js` | 외부경계 분리 유지 |
| validators / migrations | 유지 | **유지** | 계약검증·스키마이력 |

→ 풀 ~30 → **라이트 ~14 소스**(+db 3 +루트 4). 추적성·테스트성 유지, 플럼빙만 축소. (구현은 §4 우선순위)

## 3. 이 구조 평가 (솔직)
### 잘된 점 ★
1. **관심사 분리 명확**: data / db(공통) / src(ML) / backend(API) / dashboard / simulation / models / outputs — 각자 한 가지.
2. **`api_client.py`로 UI가 backend REST만 호출**(직접 DB X) — 단일 진실원·보안·계층 정합의 **정답**. 이전 db_service 직결 대비 개선.
3. **`export_model_run.py`**(manifest + eval artifacts) — 발표 그래프(검증 산출물)의 출발점. 필수 추가.
4. **simulation_site 분리 + 자체 neon 스키마** — 쓰기 많은 시뮬 로그를 운영 DB와 분리. 옳음.
5. **sample/preprocessing_project를 백업으로 강등** — 정본 혼동 제거.
6. **outputs/evaluation/** — eval 전용 위치, 차트 API 직결.

### 짚을 점(보완) ⚠
1. **DB 계층 2개**(`db/` SQLite·Postgres / `backend/db/` MySQL) → **운영 정본 = `backend/db/schema_mysql.sql` 하나**로 선언, 최상위 `db/`는 로컬·파이썬 검증 전용 명시(스키마 드리프트 방지). §1에 표기.
2. **통합 표면 큼(2일 마감)**: Streamlit+Vercel+Neon+MySQL+Node = 연동점 5개. **발표 경로(대시보드+backend+eval 차트) 먼저**, simulation 실시간은 "여유 시".
3. **실시간 추론 주체 명시 필요**: dashboard에서 predictor(torch) 빠짐, backend는 추론 X → 점수는 **`src/` 모델 사이드카(배치/실시간)가 만들어 `/models/submit`·`/predict`로 제출**하는 흐름을 CONTRACT.md에 못박기.
4. **data/에 v2 정본(`processed_eventbase`) 추가** — 최종 모델 입력 정본은 이쪽(27피처). §1 반영.

## 4. 권고 우선순위 (마감 6/23)
