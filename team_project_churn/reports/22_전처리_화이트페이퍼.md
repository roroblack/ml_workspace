# 22. 전처리 화이트페이퍼 — "지금 전처리가 한 줄 한 줄 무슨 짓을 하는가"

목적: 전처리를 **블랙박스가 아니라** 실제 소스 코드 한 단계씩 추적해 누구나(팀원·발표자·본인) **무엇이 들어가고 무엇이 버려지는지** 명확히 알게 한다. 모든 단계는 실제 소스파일 위치를 명시한다.

---

## 0. 전처리 소스파일 지도 (어디에 무슨 코드가 있나)
| 단계 | 소스파일 | 한 줄 요약 |
| --- | --- | --- |
| ① raw→피처+라벨+주별시퀀스 | `preprocessing_project/v2_5m/src/prep_5month.py` | **핵심 전처리.** 2,069만 이벤트 → 유저당 10피처 + churn 라벨 + 주별 시퀀스 |
| ② 코호트+ML/DL 최적 | `.../v2_5m/src/bayes_5m.py`, `finalize_5m_opt.py` | recency≤7 코호트 추출 + 스케일러 영속화 |
| ③ 모델별 변환+HP | `.../v4_model_prep/src/models_bayes_one.py` | ①의 결과(10피처)에 scaler/log/imbalance + 모델HP 베이지안 |
| ④ 이벤트/세션(시간보존) | `.../v3_event_additive/src/build_event_sequence.py`, `.../v4_model_prep/src/demo_session_preview.py` | 행동 1건=1행, 시각·상품·Δt 보존 |

> **요점**: "전처리"라 부르는 변환의 90%는 **①prep_5month.py**에 있다. 아래는 그 파일을 코드 순서대로 해부한다.

## 1. `prep_5month.py` 단계별 해부 (① 핵심 전처리)

### STEP 0. 설정 (코드 상단)
- `MONTHS` = 5개 zip. `EVENTS=[view,cart,purchase]`(시퀀스 채널), `ALLTYPES`에 remove_from_cart 포함.
- `BLOCKS`: train 관찰 `2019-10-01~2020-01-25`, 결과창 `01-25~02-01`(7일) / test 관찰 `02-01~02-22`, 결과창 `02-22~03-01`.
- `NWK`: 관찰주수 train≈17, test≈3.
- **여기서 정해지는 것**: 시간 분할(누수 차단), 시퀀스에 remove_from_cart 빠짐.

### STEP 1. 월별 순차 로드 (메모리 안전)
```
for m in MONTHS:
    df = read_csv(zip, usecols=[event_type,price,user_id,event_time], dtype=다운캐스트)
    df.event_time = to_datetime(..., "%Y-%m-%d %H:%M:%S UTC")
    df = df.dropna(subset=[event_time,user_id])
```
- **들어가는 것**: event_type, price, user_id, event_time.
- **이미 버려지는 것**: `product_id`, `category_id`, `category_code`, `brand`, `user_session` ← **usecols에서 제외**. 즉 ①단계는 **상품·카테고리·브랜드·세션을 처음부터 안 읽음.**
- 결측 event_time/user_id 행 제거.

### STEP 2. 블록별 관찰/결과 분리
```
obs = df[obs_start ≤ event_time < obs_end]      # 피처 만들 구간
out = df[outcome_start ≤ event_time < outcome_end]  # 라벨 만들 구간(7일)
```

### STEP 3. 정형 부분집계 `agg_tabular(obs)` — 유저당 1행으로 압축
```
g = obs.groupby(user_id)
n_events = size, sum_price = sum(price), max_time, min_time, ndays = nunique(date)
n_{view,cart,remove_from_cart,purchase} = 타입별 건수
purch_amt = purchase 행의 price 합
```
- **여기가 "평균으로 떨어진다"의 정체**: 한 유저의 수백 건 행동이 **합계·개수·최대/최소 시각**으로 압축됨.
- **이 단계에서 증발**: 행동의 **순서, 각 행동의 시각, 그때 본 상품/카테고리/브랜드, 행동 간 간격(Δt)**. (원본 zip엔 남아있음 — 여기 표현에서만 사라짐)

### STEP 4. 주별 시퀀스 `agg_weekly(obs)` — 시간의 일부만 보존
```
week = (event_date - wk0) // 7
groupby(user_id, week, event_type).size()  # view/cart/purchase만
```
- **보존**: 주 단위 view/cart/purchase 카운트(시간의 거친 흐름).
- **버림**: remove_from_cart, price, 카테고리, **일/시/분/초 디테일**(주 단위라 초단위 이탈 불가).

### STEP 5. 월별 누적 합산
```
tab = concat(월별부분집계).groupby(user).agg(sum; max_time=max; min_time=min)
```
- 5개월 부분집계를 유저별로 합쳐 관찰기간 **전체** 집계 완성. (← recency≤7로 자른 게 아님이 여기서 분명)

### STEP 6. 파생 피처
```
recency_days = obs_end - max_time           # 최근성
tenure_days  = max_time - min_time          # 활동 스팬
avg_price    = sum_price / n_events         # 평균 단가
```

### STEP 7. 라벨 Y (결과창 기준, 누수 차단)
```
active = 결과창에 이벤트 있는 user 집합
purch  = 결과창에 purchase 있는 user 집합
churn             = (user ∉ active) → 1   # 7일 무활동 이탈(주 라벨)
churn_no_purchase = (user ∉ purch)  → 1   # 7일 무구매(보조)
```
- **시간 외삽**: 미래(결과창)로 라벨, 과거(관찰)로 피처 → 누수 없음.

### STEP 8. 저장
```
{train,test}_tabular.parquet   # user_id + 10피처 + churn + churn_no_purchase
{train,test}_seq.npz           # X[N, 17 or 3, 3] + churn
meta_5m.json
```

## 2. ②③④ 단계 요약 (나머지 전처리)
- **②bayes_5m/finalize**: ①의 tabular에서 **recency≤7 코호트**만 골라 `*_cohort_tabular.parquet` 생성(전체의 8.6%). ML 최적(log1p+minmax)·DL 최적 본 + `ML_opt_scaler.joblib` 저장.
- **③models_bayes_one(v4)**: `train_cohort_tabular.parquet`(10피처)을 읽어 **scaler{none/std/robust}·log1p·imbalance{none/classweight/smote}** 중 최적을 optuna로 찾고 모델HP 공동탐색 → `prep_{Model}.joblib`. **여기는 raw를 안 읽음. 10피처 재변환만.**
- **④build_event_sequence/demo**: raw를 **다시** 읽되 이번엔 `product_id/category_id/brand/user_session`까지 읽어 **행동 1건=1행**(시각·상품·Δt·bounce·churn30 보존). ①에서 버린 시간·상품 정보가 여기서 살아남음.

## 3. "무엇이 살리고 무엇이 버리나" (정확판 — 표현형별)
> 정정: `remove_from_cart`·`price`는 **tabular엔 살아있다**(아래). **seq에서만** 빠졌다. `category/brand/product/session`은 **prep_5month이 통째로 안 읽어서 진짜로 사라졌다** — 이게 진짜 구멍이고, **신규 `build_features_v2.py`가 이를 메운다.**

| 정보 | ①prep_5month tabular(10) | weekly seq | ③v4모델 입력 | **★build_features_v2(신규)** | ④event/세션 |
| --- | --- | --- | --- | --- | --- |
| `n_remove_from_cart` | ✅ 피처임 | ❌ 채널 빠짐 | ✅(상속) | ✅ +`remove_ratio` | ✅ |
| `price` | ✅ avg_price·purch_amt | ❌ | ✅ | ✅ +min/max/std/purchase_avg | ✅ 행별 |
| **category_id** | ❌ **안 읽음** | ❌ | ❌ | ✅ n_cat·top·last·entropy | ✅ 행별 |
| **brand** | ❌ **안 읽음** | ❌ | ❌ | ✅ top·loyalty·last·n | ✅ 행별 |
| **product_id** | ❌ **안 읽음** | ❌ | ❌ | (옵션) | ✅ 행별 |
| **user_session** | ❌ **안 읽음** | ❌ | ❌ | ✅ n_sessions·events/sess | ✅ 행별 |
| 행동 시각(초)·순서·Δt | ❌ 합/최대만 | △ 주단위 | ❌ | ❌(집계) | ✅ |
| 휴면·바운스 유저 | △ 있음 | — | ❌ 코호트 91%제외 | ✅ 전체(+코호트 플래그) | ✅ 전체 |

- **즉 카테고리/브랜드/상품/세션을 버린 건 "필요 없어서"가 아니라 초기 prep_5month이 RFM만 만들려고 usecols에서 뺐기 때문**(설계 한계). 중요 신호 맞고, `build_features_v2.py`에서 **전부 살림**.
- "원본 zip에 있으니 괜찮다"는 **변명이었음**(모델 담당은 전처리 산출물만 씀). 그래서 **산출물(v2 parquet) 자체에 살려서** 넣음.

## 5. 적용한 데이터 전처리 "기술" 전체 (형변환·압축·인코딩 등)
| 기술 | 무엇을 | 왜 | 어디(코드) |
| --- | --- | --- | --- |
| **dtype 다운캐스트** | int64→int32, float→float32, 문자열→category | 메모리 1/2~1/4(2천만행 OOM 방지) | prep_5month·build_features_v2 `DT` |
| **datetime 파싱** | `'2019-11-01 00:00:02 UTC'` 문자열 → `datetime64` | 시간차·주차·Δt 연산 가능 | `pd.to_datetime(..., format=)` |
| **결측 처리** | event_time/user_id 결측 행 제거 · brand 결측 45%→`'UNK'` · category_code 98%결측→**미로딩** | 누수/오류 방지, 무의미 컬럼 배제 | `dropna`, `fillna('UNK')`, usecols 제외 |
| **시간외삽 분할** | 관찰(과거)→피처 / 결과(미래 7일)→라벨 | **데이터 누수 차단** | `OBS`/`OUTC` 윈도우 |
| **클리핑** | 카운트 `clip(0,None)`, (가격 음수·0 존재→정제 대상) | 음수 카운트·이상치 방지 | models_bayes_one `np.clip` |
| **log1p(counts)** | 왜도 큰 카운트 피처 로그 변환 | 선형/거리모델의 분포 정규화 | transform `np.log1p` |
| **스케일링** | StandardScaler/MinMax/Robust | 선형·거리기반 모델은 스케일 민감(트리는 불필요) | transform |
| **범주 인코딩** | category_id/brand: 트리=native cat, 선형=one-hot/target, DL=embedding | 고카디널리티(~500/280) 처리 방식이 모델마다 다름 | 모델 단계(§6) |
| **불균형 처리** | class_weight='balanced' / SMOTE | 이탈 82% 불균형 보정 | imblearn Pipeline |
| **확률 보정** | isotonic calibration(holdout fit) | risk 임계값 신뢰성(Brier/ECE) | `CalibratedClassifierCV` |
| **임계값 최적화** | F1 최대 임계값 탐색 | 0.5 고정 대신 운영점 | models_bayes_one |
| **압축 저장** | 시퀀스 `np.savez_compressed`(0이 96%→~40배↓), 표 `parquet`(컬럼압축) | 디스크·IO 절감 | prep/build_event_sequence |
| **분산 누적 std** | sum·sumsq·n으로 전체 표준편차 | 월별 합산만으로 전역 std | build_features_v2 (T5) |
| **cross-month nunique** | 월별 distinct (user,값) 쌍 누적→합산 | 전체기간 고유 카테고리/브랜드/세션 수 | build_features_v2 (T6) |

## 6. 모델별 — 뭐가 필요해서 살리고, 뭐가 불필요해서 버리나 ★
(우리가 "모델별 전처리 최적화"를 하는 이유. v4 베이지안 결과와 일치)
| 모델군 | 살림(필요) | 버림/불필요 | 왜 |
| --- | --- | --- | --- |
| **DecisionTree/RandomForest** | raw counts·recency·tenure·category(분기) | 스케일·log1p **불필요** | 트리 분기는 **단조변환 불변** → 스케일/로그 영향 0 (v4: scaler none/robust가 최적) |
| **XGBoost/LightGBM/CatBoost** | counts·recency·**last_cat/brand(네이티브 범주형)**·비율 | 스케일·log·one-hot **불필요** | GBDT 스케일불변 + LGBM/CatBoost는 **native categorical**이 인코딩보다 강함 (v4 부스팅 최강 0.79) |
| **LogReg(선형)** | **스케일(필수)**·log1p(왜도)·인코딩(one-hot/target)·SMOTE/classweight | raw 고카디널리티 직접투입 불가 | 선형·스케일 민감·계수 가정 (v4: minmax+classweight 최적) |
| **Transformer/GRU(시퀀스)** | 시퀀스형·정규화(log/zscore)·**category embedding**·Δt·시각 | tabular 집계 **불필요** | 순서·시간 정보를 직접 학습 (v4: norm=log 최적) |
| 공통(전 모델) | **recency_days(지배 신호)**, churn 라벨 2종 | category_code(98%결측) | recency가 이탈 최강 신호(17-7-0) |

> 정리: **트리/부스팅 = raw+범주native(스케일 버림), 선형 = 스케일+로그+인코딩+불균형(살림), 시퀀스 = 정규화+임베딩+시간(살림)**. build_features_v2가 이 모든 재료(category/brand/Δt재료/비율)를 **한 정본에 살려두고**, 각 모델이 필요한 것만 골라 쓴다.
