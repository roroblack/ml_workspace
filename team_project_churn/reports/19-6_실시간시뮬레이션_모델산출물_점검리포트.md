작성일: 2026-06-22

참고 문서: `19-2_최종_백엔드_설계도.md`, `19-3_모델팀_산출물_및_I_O_계약서.md`, `19-4_대시보드팀_파일구조_및_API_계약서.md`

## 1. 결론

현재 받아온 산출물만으로도 **CatBoost, LightGBM, XGBoost 중심의 실시간 시뮬레이션 데모는 가능**하다. 이유는 현재 백엔드 실시간 추론 로더가 `models/churn/{model_key}/model.*` 원본 모델 파일보다 `models/preprocessors/prep_{Model}_v2.joblib` 서빙 번들을 우선 사용하기 때문이다.

다만 문서 계약과 실제 런타임 기준이 완전히 같지는 않다.

- `19-3` 문서 기준: 모델 원본 파일은 `models/churn/{model_key}/model.*`에 둔다.
- 현재 백엔드 기준: 실시간 추론은 `models/preprocessors/prep_{Model}_v2.joblib` 번들을 읽는다.
- 현재 manifest 기준: `artifact_path`도 대부분 `models/preprocessors/prep_{Model}_v2.joblib`를 가리키고 있다.

따라서 발표/데모 안정성을 기준으로 하면 **서빙 번들을 공식 운영 artifact로 인정**하는 것이 가장 안전하다. 원본 모델 파일은 재학습/검증/백업용으로 보관하고, 실시간 API가 실제로 읽는 파일은 `prep_*_v2.joblib`로 통일하는 편이 좋다.

## 2. 실시간 시뮬레이션까지 필요한 산출물 전체

### 2.1 실시간 추론 필수

| 구분 | 필요 파일/값 | 현재 용도 |
|---|---|---|
| 서빙 번들 | `models/preprocessors/prep_CatBoost_v2.joblib` 등 | 백엔드가 실시간 churn 확률 계산에 직접 로드 |
| feature order | 번들 내부 `feature_order` | 입력 피처 순서 고정 |
| 모델 또는 calibrator | 번들 내부 `model` 또는 `calibrator` | `predict_proba`로 churn=1 확률 산출 |
| threshold | 번들 내부 `threshold` | 확률을 위험등급/예측값으로 변환 |
| 피처 스키마 | `models/churn/{model_key}/feature_schema.json` | 팀 간 입력 컬럼 확인, 문서/검증용 |
| 모델 설정 | `models/churn/{model_key}/model_config.json` | 모델명, horizon, label, 설정 확인 |

현재 실시간 로더 위치:

- `SKN32-2nd_GAJIMA_Dev/backend/app/infrastructure/model_inference/python_model_loader.py`

현재 로더는 `MODELS_DIR / "preprocessors" / f"prep_{name}_v2.joblib"`를 읽는다.

### 2.2 실시간 시뮬레이션 사이트 필수

| 구분 | 필요 파일/값 | 현재 용도 |
|---|---|---|
| 상품 seed | `simulation_site/neon/seed/products.csv` | 시뮬레이션 사이트 상품 목록 |
| 카테고리 seed | `simulation_site/neon/seed/categories.csv` | 카테고리 목록, 카테고리별 대표 정보 |
| 브랜드 seed | `simulation_site/neon/seed/brands.csv` | 브랜드 목록 |
| 유사 카테고리 | `simulation_site/neon/seed/category_similarity.csv` | 세션 내 관심 카테고리 기반 추천 |
| 이벤트 payload | `session_id`, `user_id`, `event_type`, `product_id`, `category_id`, `brand`, `price` | `/sim/event` 호출 입력 |
| 세션 피처 | `recency_days`, `tenure_days`, `ndays`, `n_events`, `n_view`, `n_cart`, `n_remove_from_cart`, `n_purchase`, `avg_price`, `purch_amt` | 이벤트를 즉시 모델 입력으로 변환 |

현재 시뮬레이션 API 위치:

- `SKN32-2nd_GAJIMA_Dev/backend/app/interfaces/http/sim_router.py`
- `SKN32-2nd_GAJIMA_Dev/backend/app/application/sim_usecase.py`
- `SKN32-2nd_GAJIMA_Dev/backend/app/infrastructure/files/catalog_store.py`

핵심 흐름:

1. 프론트/시뮬레이션 사이트가 `GET /sim/products`, `GET /sim/categories`로 상품/카테고리 목록을 받는다.
2. 사용자가 상품을 보거나 장바구니에 넣거나 구매하면 `POST /sim/event`를 호출한다.
3. 서버가 이벤트를 세션 메모리에 누적한다.
4. 서버가 누적 이벤트를 10개 피처로 변환한다.
5. 서버가 active 모델 또는 기본 `CatBoost` 번들로 churn 확률을 계산한다.
6. 서버가 `risk_level`, `recommended_action`, `recommendations`를 반환한다.

### 2.3 대시보드/발표 시각화 필수

| 구분 | 필요 파일 | 현재 용도 |
|---|---|---|

| 요약 지표 | `metrics_summary.json` | KPI 카드, 모델 비교 |
| 유저별 예측 | `eval_predictions.parquet` | 점수 분포, 샘플 유저, 추천 보강 |
| PR curve | `pr_curve.json` | PR-AUC 시각화 |
| ROC curve | `roc_curve.json` | ROC-AUC 시각화 |
| Threshold curve | `threshold_curve.json` | threshold별 precision/recall/F1 |
| Confusion matrix | `confusion_matrix.json` | 분류 결과 요약 |
| Calibration | `calibration_curve.json` | 확률 신뢰도 |
| Lift chart | `lift_curve.json` | 상위 N% 타겟 효율 |
| Score distribution | `score_distribution.json` | churn score 분리도 |
| SHAP summary | `shap_summary.json` | 설명 가능성 |
| Business value | `business_value.json`, `value_at_risk.json` | 회수 가능 매출/위험 매출 |

## 6. 추천 기능 구현 관점

현재 추천은 두 갈래로 구성 가능하다.

### 6.1 실시간 세션 추천

현재 `/sim/event` 기준으로 이미 가능하다.

필요값:

- 이벤트의 `category_id`
- `simulation_site/neon/seed/category_similarity.csv`
- `simulation_site/neon/seed/categories.csv`

흐름:

1. 사용자가 상품을 조회/장바구니/구매한다.
2. 이벤트에 `category_id`가 포함된다.
3. 서버가 세션에서 가장 많이 등장한 카테고리를 찾는다.
4. `category_similarity.csv`에서 유사 카테고리 top-k를 반환한다.

이 방식은 모델별 `eval_predictions.parquet`에 `top_category`가 없어도 동작한다.

### 6.2 유저별 추천/대시보드 추천

`eval_predictions.parquet` 기반으로 유저 추천을 보여주려면 아래 컬럼이 있으면 좋다.

- `user_id`
- `y_score`
- `risk_level` 또는 `y_pred`
- `top_category`
- `top_brand`
- `revenue`

현재 상태:

- CatBoost: 가능
- XGBoost: 가능
- LightGBM: `top_category`, `top_brand`, `revenue`가 없어서 보강 필요

권장:

- 추천/비즈니스 화면은 CatBoost active 결과를 기준으로 먼저 만든다.
- LightGBM/XGBoost는 모델 비교 화면 중심으로 사용한다.
- 모든 최종 3개 모델에서 동일한 추천 화면을 만들고 싶다면 LightGBM `eval_predictions.parquet`에 추천 보강 컬럼을 추가한다.

## 8. 최종 운영 기준 제안

이번 프로젝트에서는 다음 기준이 가장 안전하다.

1. 발표 최종 모델은 `CatBoost`, `LightGBM`, `XGBoost` 3개로 둔다.
2. 실시간 시뮬레이션 active 모델은 `CatBoost`를 기본값으로 둔다.
3. 백엔드 운영 artifact는 `models/preprocessors/prep_{Model}_v2.joblib`로 통일한다.
4. `models/churn/{model_key}/model.*`는 재학습/검증/백업용 원본 모델 파일로 둔다.
5. 추천 기능은 우선 세션 이벤트의 `category_id` + `category_similarity.csv` 방식으로 구현한다.
6. 유저별 추천/비즈니스 시각화는 CatBoost 또는 XGBoost의 `eval_predictions.parquet`를 기준으로 만든다.
7. LightGBM은 모델 비교에는 바로 사용하고, 추천/비즈니스 화면까지 동일하게 쓰려면 보강 산출물을 추가 요청한다.

## 9. 모델팀 전달용 짧은 요청 문구

현재 백엔드는 실시간 추론에서 `models/preprocessors/prep_{Model}_v2.joblib` 번들을 사용합니다. 따라서 데모 런타임은 현재 번들로 가능합니다. 다만 산출물 계약과 재현성을 위해 아래 파일을 추가로 주시면 좋습니다.

- CatBoost: `models/churn/catboost/model.cbm` 또는 원본 모델 파일
- LightGBM: `models/churn/lightgbm/model.txt` 또는 `model.joblib`
- LightGBM 평가 보강: `shap_summary.json`, `business_value.json`, `value_at_risk.json`
- LightGBM `eval_predictions.parquet` 보강 컬럼: `top_category`, `top_brand`, `revenue`

최종 발표 모델은 `LightGBM`, `XGBoost`, `CatBoost` 3개로 정리하고, 실시간 시뮬레이션 active 모델은 우선 `CatBoost` 기준으로 진행하는 것이 가장 안정적입니다.
