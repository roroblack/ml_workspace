# 17-0. 실시간 이탈확률 리플레이 (한 유저 로그 → 실시간 위험도)

> 후속: [17-1 여러 모델 비교](17-1_실시간_모델비교.md) — 슬라이딩 윈도우에서 ML vs DL 성능 비교 + recency 변화의 수치화.
>
> **데이터셋 표기(17-x 공통)**: 본 시리즈는 **REES46 2019-Nov 표본**(`sample_project`, 8,000명, 초단위 원시 이벤트)을 쓴다. 초단위/세션 분석이 정식 주별 집계로는 불가하기 때문이다. 이는 REES46가 맞으나, 최종 이탈모델용 **정식 5개월 학습셋 `retail_rees46_multi/`(80,000명·18주)와는 별개의 데모 파생본**이다. (PROJECT_RULES §1 참조)

## 1. 무엇을 했나

한 유저의 **전체 이벤트 로그를 "지금 실시간으로 발생하는 스트림"으로 가정**하고,
시간을 하루씩 흘리며 **매일 직전 14일 창으로 시퀀스를 다시 만들어 LSTM 이탈확률을 재계산**했다.

- **핵심 설계**: 이벤트가 있는 날뿐 아니라 **활동이 없는 "침묵일"도 매일 평가**한다.
  → 침묵이 쌓이면 14일 창의 최근 칸이 0으로 비어 **이탈확률이 단조 상승**, 활동을 재개하면 **급락**.
- **누수 차단**: 시점 t에서는 t까지 발생한 로그만 사용(미래 이벤트 차단). 스케일러는 학습 통계로 transform만.
- 위험등급: low(<0.35) / medium(0.35~0.65) / high(≥0.65).

> 이것이 곧 운영 아키텍처(05-x)의 **실시간 DL 예측 루프**를 한 유저로 재현한 것 — Streamlit이 매 이벤트/주기마다 호출하는 그 계산이다.

## 2. 결과 — 위험도가 "살아 움직인다"

### 사례 A. 회복형 — 유저 568958175
![A](../sample_project/outputs/realtime/568958175_daily.png)

- 11-09 첫 활동 후 **9일 침묵** → 확률 0.16 → **0.94(high)** 까지 상승.
- 11-21 활동 폭발(하루 83건, 다음날 356건) → **0.22로 급락**, 이후 끝까지 활동 유지 → **0.09(low) 생존**.
- 해석: *위험 경보가 떴지만 재방문으로 회복한 고객* → 침묵 5~9일 구간이 **리텐션 개입의 골든타임**이었음.

### 사례 B. 이탈형 — 유저 535857202
![B](../sample_project/outputs/realtime/535857202_daily.png)

- 초중반 침묵→활동을 반복하며 회복(11-16 medium까지 올랐다 11-17 활동으로 0.07 복귀).
- **11-20 마지막 활동 후 침묵 누적** → 11-23 medium, **11-25 high 진입** → 11-30 현재 **0.95(이탈 임박)**.
- 해석: *결국 이탈로 굳어진 고객* → high 진입(11-25)은 마지막 활동(11-20) **5일 뒤**, 즉 조기 경보가 작동.

### 두 사례 대비

| | 유저 568958175 | 유저 535857202 |
| --- | --- | --- |
| 시작 → 현재 | 0.16(low) → **0.09(low)** | 0.20(low) → **0.95(high)** |
| 최고 | 0.94 (11-20, 침묵 9일) | 0.95 (11-30) |
| 결말 | 활동 재개 → 생존 | 침묵 누적 → 이탈 |

## 3. 무엇을 확인했나 (모델 검증 관점)

1. **모델이 recency를 정확히 학습** — 침묵 1일당 확률이 매끄럽게 상승(0.2→0.4→0.6→0.9), 활동 시 즉시 하락. 라벨 정의(결과기간 무활동=이탈)와 모델 행동이 일치.
2. **조기 경보 가능** — high 진입이 실제 마지막 활동보다 **수일 앞서** 발생 → 리텐션 액션 타이밍을 준다.
3. **단건 누적 피처가 아닌 "시퀀스 모양"을 본다** — 같은 누적 이벤트 수여도 *최근 분포*에 따라 확률이 달라짐(11-16 vs 11-17). 시퀀스 DL을 쓰는 이유의 실증.
4. **리포트 11 결론과 정합** — recency 지배형 라벨에서 LSTM도 recency를 핵심 신호로 사용. (단 정형 GBM도 recency를 잡으므로 *이 라벨에선* 성능 우열은 근소 — 11장 참조)

## 4. 이 결과로 이어서 할 것

1. **임계값·타이밍 정책화**: "medium 도달 시 리마인드, high 도달 시 쿠폰" 을 침묵 일수와 연동(예: 침묵 5일=medium 부근). 비용 기반 임계값 최적화.
2. **Streamlit 실시간 대시보드 연결**: 이 일별 궤적을 `simulate_events.py`로 DB에 흘려넣고 대시보드가 동일 곡선을 실시간 렌더 → 데모 시나리오 완성.
3. **세션/순서형 라벨로 확장**: 현재는 일별 카운트. 세션 단위 step feature + category 임베딩을 넣으면(리포트 16의 임베딩은 *정형*에선 무용했지만 *시퀀스*에선 유효 가설) 순서 신호를 더 잡을 수 있음.
4. **배치 스코어링**: 전체 유저에 대해 매일 tick을 돌려 "오늘 high 신규 진입자" 리스트를 산출 → 운영 리텐션 큐.
