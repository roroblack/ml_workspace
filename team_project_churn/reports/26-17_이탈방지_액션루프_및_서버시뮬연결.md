# 26-17. 이탈방지 액션 루프 + 서버↔시뮬 연결 (구현 리포트)

근거: 사용자 아키텍처/액션 명세, 05-6-4(시뮬=얇은 프론트), BUG-002(가짜값 금지)

## 1. 구현 범위 (옵션3)
(B) 이탈방지 액션 시스템 [코어] + (A2) 해시키 상호인증 + 서버주소 탐지 + (A3) Neon 업로드 스크립트.

## 2. (B) 액션 시스템 — 백엔드 ✅
`application/sim_usecase.py` `decide_action(p, feats, recs)` + `action_from_events(p, events)`. `POST /api/churn/predict` 응답에 **`recommended_action`** 추가.

| 시나리오(trigger) | 조건 | action_type | payload |
| --- | --- | --- | --- |
| **첫 접속·장기미접속**(recency_high) | 이벤트≤1 or p≥0.6 or recency≥5, cart=0·purchase=0 | `sns_view` | `sns_url`, `as_view_event` |
| **담고 미구매**(cart_no_purchase) | n_cart>0, n_purchase=0 | `discount_related` | `discount_pct=10`, `related[]` |
| **조회만**(view_only) | n_view≥3, cart=0·purchase=0 | `discount` | `discount_pct=5` |
| 그 외 | 구매 등 | `none` | — |

**검증(/api/churn/predict 4 케이스):**
| 입력 | action_type / trigger |
| --- | --- |
| view 1건 | `sns_view` / recency_high ✅ |
| view+cart | `discount_related` / cart_no_purchase ✅ |
| view×4 | `discount` / view_only ✅ |
| purchase | `none` / ok ✅ |

## 3. (B) 액션 시스템 — 시뮬 프론트 ✅
`client/src/components/ChurnActionPanel.tsx`(신규, App.tsx 마운트): churn 예측의 `recommended_action`을 4초 폴링해 우하단 카드로 렌더.
- `sns_view` → "SNS 인기상품 둘러보기" 버튼 → 클릭 시 **`logViewEvent('sns_promo'...)` = view 이벤트 기록** → 다음 예측에서 인게이지먼트↑ → 이탈률↓.
- `discount_related` → 할인 배너 + 연관 카테고리 칩.
- `discount` → 할인 배너.
- `none`/미연결 → 패널 숨김(가짜값 금지). `pnpm check` 0에러.

## 4. (A2) 해시키 상호인증 ✅
`interfaces/http/sim_external_router.py`: 환경변수 **`SIM_SYNC_KEY`** 설정 시 `X-Sync-Key` 헤더 일치 요구(미설정=하위호환 통과). 양쪽 env에 공유키를 두면 시뮬↔백엔드 상호인증.

## 5. 서버주소 탐지 ✅ (사용자 요청)
`backend/scripts/show_server_addr.py` → **LAN IP 자동 탐지**(예: `192.168.0.5:8090`) + 시뮬 `VITE_FASTAPI_URL`에 넣을 값 출력.
- ⚠ **`ipconfig`/LAN IP는 사설**이라 인터넷(Vercel)에서 직접 못 닿음. 같은 와이파이 데모면 OK. 인터넷 노출은 **포트포워딩(8090) 또는 터널(cloudflared)** 필요 — 스크립트가 안내.

## 6. (A3) Neon 업로드 ✅(스크립트)
`simulation_site/neon/upload_neon.sh`: `DATABASE_URL`(Neon) 받아 `schema_neon.sql`+`catalog_import.sql`(\copy로 categories/brands/products/similarity CSV) 적재 + 행수 검증. **실행은 사용자**(Neon 접속정보 필요).

## 7. 연결 구조(사용자 명세) 매핑
- 서버가 시뮬 주소 앎 → 시뮬 `.env`의 `VITE_FASTAPI_URL`(서버주소)로 시뮬→서버 호출(현 push 구조, 05-6-4 정합).
- 해시키 상호인증 = `SIM_SYNC_KEY`/`X-Sync-Key`.
- 시뮬 Neon에 카탈로그 CSV = `upload_neon.sh`.
- 시뮬 로그→서버 = `/api/events`(기존). 서버 실시간 churn→대시보드 = 기존 prediction_log/대시보드.
- 서버가 현재 이벤트 기반 액션 제공 = `recommended_action`(본 구현).

## 8. 한계 / 잔여
