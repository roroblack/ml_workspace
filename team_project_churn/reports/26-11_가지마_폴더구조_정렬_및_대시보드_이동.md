## 2. 대시보드 이동·재구성 (19-4)
`app/`·`app.py`·`assets/`·`styles/`(+빈 `face_recog/`)를 제거하고 **`dashboard_streamlit/`** 으로 규격 재배치.
```
dashboard_streamlit/
├── app.py                    진입(랜딩)
├── pages/01_face_login.py · 02_dashboard.py   (네이티브 멀티페이지)
├── services/  api_client · auth_service · dashboard_service · prediction_service
│            · recommendation_service · chart_service · face_auth
├── components/ layout · kpi_cards · charts · risk_table · error_state
├── assets/logo.svg · styles/main.css · .streamlit/config.toml
├── mocks/ (dashboard_summary·top_risk·models + charts/*)  ← 실 eval 데이터 기반
├── .env.example · requirements.txt · README.md
```
- **표시 계층 전용**: 데이터는 `services/api_client` → FastAPI REST. `DASHBOARD_USE_MOCK=true` 또는 백엔드 미가용 시 `mocks/` 폴백(19-4 §4·§10).
- **DB 직접 접속 제거**: 기존 `app/db.py`(MySQL 직결)는 `reports/reference/db_legacy/db_client.py`로 보관. 얼굴 등록/로그인은 백엔드 `/auth/face/*` 경유.
- **진단 15시각화**: `chart_service`가 `data/processed/evaluation/*`를 직접 읽어 렌더(19-4 §1의 "개발 허용" 경로). 운영 전환 시 `dashboard_service.get_model_chart()` chart JSON으로 교체 가능.
- 단일 통합 대시보드(개요/고객조회/실시간바운스/추천 + 관리자: 진단·로그), `role` 기본 customer.

## 3. 백엔드 보강 — 얼굴 인증 REST (19-4 §7.1)
대시보드 DB 직결 제거에 맞춰 백엔드에 인증 계층 추가:
- `infrastructure/mysql/face_repository.py` — `face_user`(임베딩 float32 bytes)·`face_login_log`(최신 200 유지)
- `domain/face_match.py` — 코사인 매칭(threshold 0.45)
- `application/auth_usecase.py` · `interfaces/http/auth_router.py` · `schemas/auth_schema.py`
- 엔드포인트: `POST /auth/face/register` · `POST /auth/face/login` · `GET /auth/me` · `GET /auth/logins`
- 임베딩 추출(insightface)은 **클라이언트(대시보드)**, 저장·매칭·로깅은 **백엔드**.
