## 0. 아키텍처 결정 원칙 (05-3 반영) ★v4 신규

DB·Vercel·Streamlit·얼굴로그인은 **확정된 요구사항**이다. 단, "형식주의(풀 DDD)"는 만들지 않고 아래 3원칙으로 **최소·올바르게** 구축한다.

| 축 | 결정 | 원칙 |
| --- | --- | --- |
| **API (Vercel)** | 구축하되 **얇게(Thin)** | API 책임 = **전송·DB I/O·인증/검증만**. ML 추론·전처리 로직 금지. 엔드포인트 최소. 무거운 추론은 **배치 적재**(`prediction_log`)로 우회(서버리스 콜드스타트/용량 회피) |
| **클린아키텍처 수준** | **실용적 L2+** | 폴더·함수로 계층 분리(frontend/api/db_client/model service). `domain/entity`·`Protocol`·DI 같은 **L3 형식계층은 생략**. 대신 경계 합의·단일책임·호출 방향 한쪽 유지 |
| **인프라** | **DB = 단일 진실원천, 파일 = 보조** | 이벤트·라벨·예측·로그는 DB. **모델 바이너리는 `models/`+`model_registry` 경로**. **대용량 시퀀스는 npz/parquet+경로**(DB JSONB 지양) |

**불변 규칙**: 스케일러/인코더/이벤트ID 매핑은 **train 구간에서만 fit**, Colab/Streamlit/Vercel은 동일 artifact를 **transform만**.

**정합성**: 이는 "12 리포트(개념만)"와 모순이 아니라 **단계 진화**다 — 12는 *형식주의 경고*, v4는 *결정된 요구의 올바른 구현 수준*.

### 0.1 PR / 리뷰 체크리스트
- [ ] API에 ML/전처리 로직 없음(전송·DB I/O·인증만)
- [ ] DB URL 등 비밀은 서버 env에만(화면/브라우저 노출 0)
- [ ] 모델 바이너리는 `models/`+`model_registry` 경로, DB 직접 적재 X
- [ ] 대용량 시퀀스는 npz/parquet+경로(DB JSONB 지양)
- [ ] 전처리 artifact는 train에만 fit, 전 런타임 transform만
- [ ] DB 스키마 변경 시 문서·팀 합의 동반

## 1. 전체 아키텍처 구조도

프리뷰에서 Mermaid가 안 보이는 문제로 **ASCII 구조도**로 작성.

### 1.1 DB 중심 전체 파이프라인

```
                          [REES46 원본 CSV]
                                  |
                                  v
                    +-----------------------------+
                    | 01. DB 적재/정제 스크립트   |
                    | ingest_rees46_to_db.py      |
                    +--------------+--------------+
                                   |
                                   v
              +------------------------------------------+
              | DB 서버 (Neon Postgres / 14리포트)       |
              | - raw_rees46_events                      |
              | - user_session_events                    |
              | - feature_user_snapshot                  |
              | - sequence_snapshot (메타+경로)          |  ← 대용량 시퀀스는 파일 경로 참조
              | - model_registry / prediction_log        |
              | - face_user / face_login_log             |
              | - retention_action_log                   |
              +-------------------+----------------------+
                                 / \
                                v   v
        +------------------------+   +------------------------------+
        | Colab 학습 노트북      |   | Streamlit 프론트엔드         |
        | - EDA/라벨 검증        |   | 얼굴 로그인 + 고객 대시보드  |
        | - ML / DL 시퀀스 학습  |   | - 이벤트 입력/조회           |
        +-----------+------------+   +---------------+--------------+
                    |                                |
                    v                                v
        +------------------------+      +-----------------------------+
        | 모델/지표 산출물       |      | Vercel API (Thin)           |
        | models/*.pth,*.joblib  |      | 전송·DB I/O·인증만        |
        | outputs/*metrics.json  |      | /api/events /predictions ...|
        +-----------+------------+      +--------------+--------------+
                    |                                  |
                    +------------------+---------------+
                                       v
                              +----------------+
                              | DB 서버 갱신   |
                              | 예측/지표/로그 |
                              +----------------+
```

> **API는 얇게**: 위 Vercel API는 추론을 직접 돌리지 않는다. 예측은 Colab/배치가 미리 계산해 `prediction_log`에 적재하고, API는 그 결과를 읽고/쓰는 전송 계층만 담당(서버리스에 큰 `.pth` 로딩 회피).

### 1.2 실시간(시뮬레이션) 예측 흐름

```
[고객/관리자 Streamlit 접속]
        v
[얼굴 등록 또는 얼굴 로그인]  --> face_user 조회/중복검사, face_login_log 저장
        v
[로그인 성공] --> role 분기(고객/관리자)
        v
[대시보드] --> DB에서 최근 이벤트/예측/추천 조회
        |
        +--> 신규 이벤트 입력 또는 시뮬레이션(※ 라이브 사이트 없음 → 로그 재생/입력 시뮬레이션)
                v
        [Vercel API(Thin) 또는 DB client] --> realtime_event_log 저장
                v
        [최근 N개 이벤트 시퀀스 생성(학습과 동일 정렬/스케일/패딩)]
                v
        [DL 시퀀스 모델 예측] --> prediction_log 저장
                v
        [Streamlit 대시보드 갱신: 이탈확률·위험등급·행동그래프·개선안]
```

> "실시간"은 라이브 트래픽이 아니라 **입력/로그 재생 시뮬레이션**임을 발표에서 명시.

### 1.3 입력/출력 기준

| 구분 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| 원본 적재 | REES46 CSV | DB import, 타입 정리, 중복 제거 | `raw_rees46_events` |
| 라벨/세션 생성 | raw 이벤트 | 세션화, 라벨 생성 | `user_session_events`, `feature_user_snapshot` |
| ML 학습 | DB feature table | Colab ML 학습 | ML 모델, metrics, 중요도 |
| DL 학습 | DB sequence 메타 + 파일 시퀀스 | Colab LSTM/Transformer 학습 | `.pth`, DL metrics, loss curve |
| 실시간 이벤트 | Streamlit 입력/시뮬레이션 | Thin API 또는 DB client | `realtime_event_log` |
| 실시간 예측 | 최근 이벤트 시퀀스 | DL predictor | `prediction_log`, 대시보드 |
| 얼굴 로그인 | 얼굴 이미지/캡처 | InsightFace embedding 비교 | `face_user`, `face_login_log` |

**운영 원칙**: 팀 공유 기준 데이터 = **DB 테이블**. 모델 바이너리·대용량 시퀀스 = **파일(`models/`, npz/parquet)+DB 경로/메타**. CSV/NPZ는 적재·캐시·아티팩트 용도.

## 3. DB 서버 설계

DB 선택: **기본 Neon(서버리스 Postgres)**, 부가기능 필요시 Supabase — 근거·비교는 [14 DB 서버 추천](14_DB서버_추천_리스트.md).

### 3.1 DB 중심 원칙 (파일 경계 명확화)

| 데이터 | 저장 | 비고 |
| --- | --- | --- |
| 원본/실시간 이벤트, 라벨, 예측, 로그인 | **DB 테이블** | 팀 공유 기준 |

### 3.2 핵심 테이블 초안

```sql
CREATE TABLE raw_rees46_events (
    id BIGSERIAL PRIMARY KEY,
    event_time TIMESTAMPTZ NOT NULL,
    event_type VARCHAR(32) NOT NULL,
    product_id VARCHAR(64),
    category_id VARCHAR(64),
    category_code TEXT,
    brand TEXT,
    price NUMERIC(12, 2),
    user_id VARCHAR(64) NOT NULL,
    user_session VARCHAR(128),
    source_file TEXT,
    ingested_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE realtime_event_log (
    event_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    session_id VARCHAR(128),
    event_type VARCHAR(32) NOT NULL,
    product_id VARCHAR(64),
    category_code TEXT,
    price NUMERIC(12, 2),
    event_time TIMESTAMPTZ NOT NULL,
    source VARCHAR(32) DEFAULT 'streamlit',
    value_json JSONB,
    received_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE feature_user_snapshot (
    snapshot_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    snapshot_time TIMESTAMPTZ NOT NULL,
    recency_hours DOUBLE PRECISION,
    view_count INTEGER,
    cart_count INTEGER,
    purchase_count INTEGER,
    session_count INTEGER,
    sequence_len INTEGER,
    label INTEGER,
    feature_json JSONB,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- v4: 시퀀스 원본을 JSONB로 통째 넣지 않고, 파일 경로/메타만 저장(대용량 성능)
CREATE TABLE sequence_snapshot (
    snapshot_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    snapshot_time TIMESTAMPTZ NOT NULL,
    seq_len INTEGER NOT NULL,
    n_features INTEGER NOT NULL,
    storage_format VARCHAR(16) DEFAULT 'npz',   -- npz | parquet
    artifact_path TEXT NOT NULL,                 -- outputs/sequences/...
    row_index INTEGER,                           -- 파일 내 행 위치(선택)
    label INTEGER,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE model_registry (
    model_id BIGSERIAL PRIMARY KEY,
    model_name VARCHAR(128) NOT NULL,
    model_type VARCHAR(64) NOT NULL,
    artifact_path TEXT NOT NULL,
    feature_schema_version VARCHAR(32),
    metrics_json JSONB,
    is_active BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE prediction_log (
    prediction_id BIGSERIAL PRIMARY KEY,
    model_id BIGINT REFERENCES model_registry(model_id),
    user_id VARCHAR(64) NOT NULL,
    session_id VARCHAR(128),
    churn_probability DOUBLE PRECISION NOT NULL,
    risk_level VARCHAR(16) NOT NULL,
    top_factors_json JSONB,
    recommended_action TEXT,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE face_user (
    user_id VARCHAR(64) PRIMARY KEY,
    display_name VARCHAR(100),
    role VARCHAR(32) DEFAULT 'customer',
    face_embedding_encrypted BYTEA,
    face_threshold DOUBLE PRECISION DEFAULT 0.45,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE face_login_log (
    login_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64),
    success BOOLEAN NOT NULL,
    similarity DOUBLE PRECISION,
    failure_reason TEXT,
    login_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE retention_action_log (
    action_id BIGSERIAL PRIMARY KEY,
    prediction_id BIGINT REFERENCES prediction_log(prediction_id),
    user_id VARCHAR(64) NOT NULL,
    action_type VARCHAR(64),
    action_message TEXT,
    status VARCHAR(32) DEFAULT 'suggested',
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

## 5. 모델별 추가 전처리

DB가 기준이어도 모델별 입력 형태가 달라 추가 변환 필요.

| 모델/화면 | 추가 전처리 | 이유 |
| --- | --- | --- |
| LogReg/GBM/LightGBM | 결측 처리, 컬럼 순서 고정, train 기준 scaler/encoder | 2D 정형 |
| XGBoost | class weight / scale_pos_weight | 불균형 대응 |
| MLP | float32, tensor dataset | PyTorch 입력 |
| LSTM | 시간순 정렬, `SEQ_MAX_LEN` 자르기/패딩, mask | 시퀀스 길이 통일 |
| Transformer | + position/time-gap feature, attention mask | padding 제외 |
| 실시간 예측 | DB 최근 이벤트 → 학습과 동일 변환 | feature drift 방지 |
| 대시보드 그래프 | 시간 집계, 위험등급 bucket, 최근 예측 join | 요약 생성 |

**불변 규칙(0장 재확인)**: 스케일러/인코더/이벤트ID 매핑은 train 구간에서만 fit, 그 외 transform만.

## 6. Streamlit 얼굴 로그인 & 대시보드

`opencv_face_login` 참고: `InsightFace FaceAnalysis("buffalo_l")`, 512차원 임베딩, 코사인 유사도, 임계값 `0.45`.

### 6.1 얼굴 로그인 흐름
```
[등록] ID 입력 → 중복 DB 조회 → 얼굴 검출 → 가장 큰 얼굴 → 512d embedding → L2 normalize → 암호화 후 face_user 저장
[로그인] 얼굴 검출 → embedding 정규화 → face_user 후보와 cosine similarity → ≥ threshold 성공 → face_login_log 저장 → role 분기
```

### 6.2 고객 대시보드
| 영역 | 내용 | DB/API |
| --- | --- | --- |
| 내 이탈 위험 | 이탈 확률·위험 등급 | `prediction_log` |
| 최근 행동 그래프 | view/cart/purchase 시계열·세션 길이 | `raw_rees46_events`, `realtime_event_log` |
| 실시간 이탈률 | 최근 예측 기준 위험 고객 비율 | `prediction_log` |
| 개선안 제시 | 쿠폰·장바구니 리마인드·추천·재방문 알림 | `retention_action_log` |
| 최근 추천 이력 | 추천 액션과 상태 | `retention_action_log` |

## 7. Vercel API 구조 (Thin)

Streamlit은 장기 실행이라 Vercel 서버리스와 궁합이 나쁨 → **A안: Streamlit은 로컬/Streamlit Cloud/Render, Vercel은 Thin API만**.

**Thin API 원칙(05-3)**: API는 **전송·DB I/O·인증만**. ML 추론·전처리 금지. 무거운 추론은 Colab/배치가 미리 계산 → `prediction_log` 적재 → API는 읽기/쓰기만.

### 7.1 엔드포인트
| Endpoint | Method | 입력 | 출력 | 책임 |
| --- | --- | --- | --- | --- |
| `/api/events` | POST | 이벤트 payload | `event_id` | `realtime_event_log` 저장 |
| `/api/events/recent` | GET | `user_id`,`limit` | 최근 이벤트 | 조회 |
| `/api/predictions` | POST | 예측 payload | `prediction_id` | `prediction_log` 저장 |
| `/api/predictions/latest` | GET | `user_id` | 최신 예측 | 고객 대시보드 |
| `/api/dashboard/summary` | GET | 기간/권한 | 집계 | 관리자 대시보드 |
| `/api/auth/login-log` | POST | 로그인 결과 | `login_id` | 얼굴 로그인 로그 |

### 7.2 환경변수
`DATABASE_URL`(풀링), `DB_SSL`, `ACTIVE_MODEL_ID`, `PRED_THRESHOLD_LOW/HIGH`, `API_SECRET`.

## 11. 주의사항
- REES46 최종 소스(게임 데이터 제외).
- DB를 모두가 바라보므로 **스키마 변경은 문서·팀 합의와 함께**.
- 얼굴 embedding은 생체정보 → 원본 이미지 저장 최소화, **암호화 저장**.
- DB 비밀번호는 **서버 env에만**(브라우저/Streamlit 노출 금지).
- **대용량 시퀀스는 npz/parquet+경로**(DB JSONB 지양) — v4에서 `sequence_snapshot`을 경로 참조형으로 변경.
- "실시간"은 **시뮬레이션**(입력/로그 재생)임을 발표에 명시.
- 범위: 본 v4는 **확장 비전**. 6/23 제출 핵심(전처리·학습 결과서·모델)은 오프라인 파이프라인([05-0])으로 먼저 확정 권장.
