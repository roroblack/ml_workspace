## 2. 근본 원인 (왜 R3~R6가 안 됐나)
- v4의 입력이 **①prep_5month의 집계 tabular(평균) + ②코호트(8.6%)** 라서, **시각·상품·Δt·바운스·휴면**이 입력 단계에서 이미 없음([22] STEP3·STEP1).
- 즉 v4 모델 코드를 고쳐도 안 됨 → **입력(전처리)을 시간보존형으로 바꿔야** 함.

## 3. 개선 설계 — "1 원천 → 2 뷰" (5m 호환 추가형)
```
REES46 raw(2,069만, 전부 보존)
        │  build_eventbase.py  (신규 정식 전처리: 전체 모집단, 시간·상품·Δt 보존)
        ▼
  [event_base]  행동 1건=1행: user_id,session,event_time,event_type,product_id,category_id,brand,price,dt_prev/next,bounce
        ├──(집계)──▶ [뷰A] tabular_v2  (10피처 + last_cat·dt·dwell·loyalty…)  → GBM/부스팅 (5m churn 호환)
        └──(시퀀스)─▶ [뷰B] session_seq (행동 시퀀스 + churn30 라벨)        → GRU/Transformer (바운스·초단위·추천)
```
- **뷰A**는 5m의 10피처를 **상위호환**(추가 컬럼만) → v4 7모델 그대로 + 추가피처 재실행.
- **뷰B**는 시간보존 → 바운스/초단위/추천. churn(7일)도 같이 산출해 5m과 라벨 정합.

## 4. 5m 호환 보장 2원칙 (반드시)
1. **시간경계 재사용**: build_eventbase는 prep_5month와 **동일 관찰/결과 분할** 사용 → 라벨·누수 동일.
2. **코호트 정렬 플래그**: 전체 모집단이 기본이되 `--cohort` 옵션으로 5m과 **동일 user_id 집합** 산출 → 직접 비교·앙상블 가능.
- 저장은 신규 디렉토리(`processed_eventbase/`)·신규 라벨(`churn30`)·신규 model_type(`session_churn`). 기존 processed_5m/v4 불변.

## 5. 보존도 설계 (R6 — 시간·상품 증발 방지)
- event_base는 **절단·인코딩 없이** 원본 그대로 행 보존(parquet).
- 모델 입력 시퀀스만 길이/어휘 제한이 생기므로:
  - 길이: 세션 전체 + (긴 유저는) 시간버킷 요약 병행(잘림 최소화).
  - 카테고리: top-K 확대 + 계층(category_id→상위) 폴백으로 UNK 최소화.

## 6. 단계별 작업 계획
| 단계 | 산출 | 비고 |
| --- | --- | --- |
| T1 | `build_eventbase.py` → `processed_eventbase/event_base.parquet`(+화이트페이퍼 갱신) | 시간보존·전체모집단·2원칙 |
| T2 | 뷰A `tabular_v2`(추가피처) + 뷰B `session_seq`(churn30) | 1원천 2뷰 |
| T3 | v4 7모델 **tabular_v2로 재실행** + Brier/ECE 추가 | R1 강화, 17-7-1 §4 |
| T4 | **세션 스코어러**(GRU/Transformer) 학습 → 초단위 이탈율 | R3·R4 |
| T5 | 추천(룰+학습) `aux_rec`+세션모델 연결 | R5 |
| T6 | (17-7-1 완성) cat/brand/seq 임베딩 → **DL→GBM 스태킹** | R9 |
| T7 | 백엔드 `/models/submit` 연동 + Streamlit 시연 | 실시간 데모 |
| 공통 | 각 단계 **화이트페이퍼 갱신 + 결과 데이터셋 폴더 백업 + 호환테스트** | R2·R7·R8 |

## 7. 평가 프로토콜 (정합)
- 분할: 시간외삽(Feb). 주지표 **PR-AUC + AUC**, 보정 **Brier/ECE**(isotonic), F1/비용 임계값.
- churn(7일)과 churn30(세션)은 **다른 과제 → 같은 라벨끼리만 비교**. baseline=현행 XGBoost 0.7904.

## 8. 범위 선택 (사용자 결정)
- **(A)** 전처리 기반만: T1~T2 (시간보존 event_base + 2뷰, 바운스·추천 데이터 확보)
- **(B)** A + T3 (7모델 v2 재실행, Brier/ECE)
- **(C)** B + T4~T5 (세션 스코어러·추천 → 초단위/실시간 시연)
- **(D)** C + T6 (17-7-1 스태킹·임베딩 완전 충족)

> 권고: **A→C 순차**(시연까지 가장 빠른 가치). D(스태킹)는 그 위 고도화.
