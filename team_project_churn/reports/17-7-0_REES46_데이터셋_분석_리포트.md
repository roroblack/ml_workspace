## 6. 이탈예측 관점의 함의 ★
1. **recency 지배 구조**: 활성일수 중앙 1일·이벤트 중앙 2건 → "최근 활동/무활동"이 가장 강한 신호. → 트리/부스팅(GBM)·Last-cat 휴리스틱이 강함([17-6-2]와 일치). 순수 시퀀스 DL은 추가신호 없으면 열위.
2. **클래스 불균형**: 단발성 유저 다수 → "결과기간 7일 무활동=이탈" 라벨이 **이탈 쪽으로 크게 치우침**(코호트 표본 실측 이탈률 ~**88%**). → class_weight·임계값·PR-AUC 평가 필요.
3. **코호트·누수 방지**: 무작위 분할 금지. **시간 외삽**(과거 관찰 → 미래 결과창)으로 분할해야 누수 없음([17-5] train Oct~Jan / test Feb).
4. **화장품 도메인 특화 라벨**: 재구매율 90%·구매간격 중앙 **7일** → "장기 이탈"은 **재구매 주기(예 30~45일) 무구매**로 정의하면 도메인 적합(보조라벨 `churn_no_purchase`와 연결).
5. **시퀀스 vs 정형**: 짧은 시퀀스 + recency 지배 → **정형(RFM) + 부스팅이 1차 최강**. 시퀀스 DL은 **행동 간 Δt·dwell·category 임베딩**을 넣은 하이브리드/스태킹일 때만 가치([17-7-1]).
6. **카테고리 신호**: `category_code` 98% 결측 → `category_id`(~500종) 임베딩 또는 빈도/타깃 인코딩으로 사용.

## 7. 전처리 권고 (다음 단계 연결)
- 식별자 외 정제: price 음수·0 클리핑, brand 결측='UNK', category_code 대신 category_id 사용.
- 라벨: 단기(7일 무활동) + 도메인(재구매주기 무구매) 2종 유지([17-5]).
- 분할: 시간 외삽(누수 차단). 표본/코호트(recency≤7)로 CPU 보호.
- 피처: RFM + 행동 + **Δt/dwell/last_cat + category_id/brand 임베딩**(추가형 v3) → 부스팅 스태킹([17-7-1]).
