## 0. 요약

모델팀이 **LightGBM 평가 artifact를 새 스키마로 교체**하면서 백엔드(구 스키마 키 직접 접근)가 깨져 진단 차트가 전부 폴백됐다(B1). 동시에 대시보드 진단 함수 리팩터 과정에서 **호출부가 옛 함수명을 참조**해 페이지 전체 NameError(B2). 그 외 운영지표 ₩0(좀비 백엔드), 모델 드롭다운 1개, 시뮬 게이지/쿠폰/상세페이지 UX 버그를 함께 수정했다.

근본 패턴: **(a) 산출물 스키마 변경에 리더가 견고하지 못함**, **(b) 리팩터 시 호출부 누락**, **(c) 백엔드 재기동 좀비**.

## 2. 근본 원인

- **B1 (핵심)**: 백엔드 리더가 `a["threshold"]`처럼 **키를 직접 인덱싱**해 산출물 스키마가 바뀌면 즉시 KeyError. artifact-first 원칙상 백엔드는 산출물 변형에 **견고(robust)** 해야 함. id로 부르면 빈 차트(파일 없음)라 에러가 안 나서 그동안 가려져 있었고, 대시보드가 **이름**으로 부르며 드러남.
- **B2**: 함수 분리 리팩터 시 호출부 grep 누락(동시편집).
- **B3·B4**: 운영/드롭다운이 **DB 등록 상태**(active 1개)에 묶여 있었음 — 실제 비교 대상은 **산출물 보유 모델 전체**.

## 3. 적용한 수정

**B1** `eval_artifacts.py` — 신·구 스키마 동시 지원(하위호환):
- threshold: `thresholds`(복수) 지원 + f1 자동계산. calibration: `mean_predicted_value`/`fraction_of_positives` 매핑.
- lift: list 형태 파싱. revenue-recovery: 새 CM 구조 → 항목별 가치 막대(TP 회복가치·FP 비용·FN 손실·추정 순가치).
- `all_metrics`/`model_metrics`: list형 metrics_summary → 첫 항목 정규화.

**B2** 호출부를 `history_diag` + `st.fragment(live_session_diag,...)`로 교체.
**B4** 드롭다운을 `dsvc.get_model_names()`(`/dashboard/models`, 7종)로.
**B5** 정적 `getBarColor`(리터럴 `bg-green-400` 등) 반환.
**B6** `coupon_grade` 4단계 + `/api/churn/predict`가 정책값으로 등급 산정.
**B7** `onCouponClick` → 첫 추천상품 쿠폰 적용 이동.
**B8** `/api/catalog/product/{id}` 단건 + `ProductDetail` fetch(폴백).

## 5. 재발 방지

- artifact 리더는 **키 직접 인덱싱 금지** — `.get()` + 스키마 분기 + `isinstance` 가드.
- 백엔드 재기동은 **포트 점유 프로세스 전부 종료 후**(좀비 방지) — 옛 백엔드가 8090 잡으면 새 uvicorn 바인딩 실패로 stale 응답.
- 함수 리팩터 시 호출부 grep 필수.
