# 19-11. Neon 레거시 분리 계획서 및 완료 기록

## 0. 결론 (요약)

**Neon(PostgreSQL)은 채택하지 않았고, 레거시 분리가 완료됐다.**
- 운영은 **MySQL 단일 + 백엔드 인메모리 세션 + 파일 기반 카탈로그**로 확정.
- 백엔드는 **Neon에 런타임 연결하지 않는다**(검증: `psycopg2` import 0, Neon 커넥션 0).
- Neon 전용 도구는 `simulation_site/neon/legacy/`로 **물리 분리**(보존), 활성 카탈로그 소스(`neon/seed/`)는 유지.

---

## 1. 배경 — Neon은 왜 계획됐나

초기 설계(v6-4)는 **2-DB 구상**이었다:
- MySQL = 운영 데이터(레지스트리·예측·얼굴 등).
- **Neon(Postgres)** = Vercel 배포 시뮬의 **이벤트 로그/카탈로그** 외부 저장(시뮬↔백엔드가 로컬 직결 불가하다는 가정).

## 2. 왜 분리(미채택)했나

| 가정(v6-4) | 실제(v7) |
| --- | --- |
| 시뮬=Next.js/Vercel, 로그=Neon | 시뮬=**React+Vite+Express(로컬)**, 백엔드 `/api/*` 직결 |
| 이벤트 영속=Neon | **백엔드 인메모리 세션**(`sim_usecase._SESSIONS`) 실시간 점수 + 필요 시 MySQL `sim_event_log` 폴백 |
| 카탈로그=Neon 테이블 | **파일(`neon/seed/*.csv`) 직접 읽기**(`catalog_store`) |
| Vercel↔백엔드=Neon 경유 | **Cloudflare 터널**(`VITE_FASTAPI_URL`)로 직접(26-18) |

→ Neon을 두면 **2-DB 운영 복잡도·시크릿·동기화 비용**만 늘고 이득이 없어 단일 MySQL로 확정.

## 3. 분리 완료 상태 (검증)

| 항목 | 결과 |
| --- | --- |
| 백엔드 런타임 Neon 연결 | **없음** — `grep psycopg2`/Neon 커넥션 0 |
| `NEON_URL` | `config.py`에서 **옵션 플래그**(기본 None). `health`가 `bool(NEON_URL)`만 노출 → 시뮬 이벤트 모드(B/A) 자동판별용. 하드 의존 아님 |
| 시뮬 서버 | postgres/drizzle-pg 의존 **없음** |
| 카탈로그 | `catalog_store`가 `neon/seed/*.csv` **파일 직접**(Neon 미사용) |

## 4. 백업 보존 (재적재 가능)

- **활성 카탈로그 소스**(유지): `neon/seed/` — products·categories·brands·category_similarity·category_name_map (REES46 54,571 상품). 백엔드가 직접 사용.
- **Neon 전용 도구**(레거시 분리·보존): `neon/legacy/`
  - `upload_neon.py`·`upload_neon.sh` (seed → Neon 적재), `schema_neon.sql`, `catalog_import.sql`.
  - 재적재: `python neon/legacy/upload_neon.py "postgresql://...neon.tech/db?sslmode=require"` (SEED 경로는 `../seed`로 보정됨).

## 5. 수행한 분리 작업 (이번)

1. Neon 전용 4파일을 `simulation_site/neon/legacy/`로 이동(코드/문서 참조 0 — 무영향 확인 후).
2. `upload_neon.py`의 `SEED` 경로를 `../seed`로 보정(활성 소스 그대로 적재 가능).
3. `neon/legacy/README.md` 추가(비활성·재적재 절차 명시).
4. 05-7-1·05-6-4의 dangling 참조(「Neon 레거시 분리 계획서」)를 본 문서로 연결.

## 6. 잔여(의도적 보존)
- `NEON_URL` 옵션 플래그 + `health.neon`: 제거하지 않음 — 시뮬이 이벤트 흐름 모드(B=Neon 영속 / A=direct)를 자동 선택하는 스위치. 미설정 시 A(direct)로 정상 동작하므로 **분리에 지장 없음**.
- 폴더명 `neon/`은 역사적 명칭(현재는 seed 카탈로그 소스 컨테이너). 리네임은 `catalog_store` SEED 경로 변경을 동반하므로 별도 결정.

## 7. 재도입 절차(필요 시)
1. Neon DB 생성 → `neon/legacy/schema_neon.sql` 적용.
2. `neon/legacy/upload_neon.py <DSN>`로 seed 적재.
3. 백엔드 `NEON_URL` 설정 → `health.neon=true` → 시뮬이 B(neon) 모드로 전환(이벤트 영속).
