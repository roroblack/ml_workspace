## 1. 보존정책 분류
| 분류 | 의미 | 정리 방식 |
| --- | --- | --- |
| **영구(Permanent)** | 운영 마스터·정적 참조. 키/upsert로 무한증가 없음 | 정리 없음(갱신만) |
| **갱신(Replace)** | 항상 최신 1건만 유지 | 재기록 시 이전 삭제 |
| **TTL(기간보존)** | 로그·이력. 보존기간 초과분 삭제 | 스케줄러가 주기 DELETE |
| **RAM(세션)** | 메모리 상태 | LRU + idle 타임아웃 |
| **레거시** | 미사용(구버전) | 삭제/분리 대상 |

## 3. 메모리(RAM) 보존 — `sim_usecase`
| 저장소 | 정책 | 비고 |
| --- | --- | --- |
| `_SESSIONS`(시뮬 세션) | **LRU 최대 500** + **idle 30분 만료**(`SESSION_IDLE_SEC`) | 점수 권위 |
| 세션당 `events` | **최대 300이벤트**(최근만) | `MAX_EVENTS` |
| `_LAST_SIM`(유저별 최신 시뮬 점수) | **LRU 최대 1000** | 대시보드 `/sim/user-score`가 읽음. churn_rate(정책적용)·3종·policy_mode 캐시 |
| `_ACTIVE_USER`(진단 대상 유저·갱신주기) | **갱신(단일 1건)** | 대시보드 설정 → 시뮬 동기화. 휘발(재기동 시 초기화) |
| `_CHURN_POLICY`(Churn Rate 정책) | **갱신(단일)** + **파일 영속**(§3-1) | 재기동에도 유지 |
| `_mem`(MySQL 미연결 폴백) | predictions 1만·sim_events 5천 trim · 모델캐시 lru(8)·tabular lru(1) | DB 없을 때만 |

## 4. 레거시(분리/삭제 대상)
- **Neon(PostgreSQL)**: 미채택 → `simulation_site/neon/legacy/`로 분리·보존(런타임 의존 0). 상세 [19-11](19-11_Neon_레거시_분리_계획서_및_완료기록.md). `sim_event_log`는 **MySQL 폴백**으로 유지(Neon 분리 무관).
- **구 `app/db.py` 잔재 테이블**(운영 미사용 → DROP 권장): `churn_prediction`·`login_log`·`recommendation_log`.

## 5. 구현 메커니즘
- **시간 기반 TTL**: `retention.cleanup_db()` → 테이블별 `DELETE WHERE <ts_col> < NOW() - INTERVAL <days> DAY`.
- **스케줄러**: FastAPI `lifespan` 백그라운드 — **기동 1회 + 6시간마다**(`CLEANUP_INTERVAL_SEC`). 삭제는 `asyncio.to_thread` → 요청 경로 지연 0.
- **세션 sweep**: 같은 스케줄러가 `sweep_sessions()`로 idle 세션 제거.
- **정책 영속**: `set_churn_policy()`가 `churn_policy.json` 기록, 기동 시 `_load_churn_policy()` 복원.
- **수동 실행(ops)**: `POST /internal/cleanup`. insert 경로에선 DELETE 안 함.

## 7. 주의 — FK·휘발성
- `retention_action_log.prediction_id → prediction_log`: prediction_log(90일) < action(365일). 현재 `prediction_id`는 NULL 적재라 충돌 없음. 채울 경우 FK `ON DELETE SET NULL` 또는 prediction 보존 ≥ action.
- `ensemble_member.ensemble_id → ensemble_result`: ensemble TTL 적용 시 member 선삭제.
- **휘발 상태 주의**: `_ACTIVE_USER`·`_LAST_SIM`·`_SESSIONS`는 재기동 시 초기화(설계상 정상). `_CHURN_POLICY`만 파일로 복원됨.
- 삭제 실패(FK/일시오류)는 무시하고 다음 주기 재시도(크래시 없음).

## 8. 확장(대규모 시)
- 초대용량 로그: **월 RANGE 파티셔닝 → 오래된 파티션 DROP**.
- 멀티워커: 세션·`_LAST_SIM`·`_ACTIVE_USER`를 **Redis 외부화**(현재 인메모리는 단일워커 전제).
- 스케줄러: **APScheduler/외부 cron** 견고화.
- (옵션) Neon 재도입 시 `sim_event_log` 외부 분리 — [19-11] §7 절차.
