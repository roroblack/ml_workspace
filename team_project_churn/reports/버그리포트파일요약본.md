## BUG-001 — 얼굴 인증 프론트↔백엔드 계약 불일치

**문제**
대시보드(프론트)는 얼굴 이미지를 multipart로 업로드하고 백엔드가 임베딩하길 기대했는데, 백엔드는 클라이언트가 직접 만든 512차원 임베딩 벡터를 JSON으로 받도록 구현돼 있었다. 또한 중복 ID 확인 엔드포인트(`/auth/face/check-id`)가 백엔드에 아예 없었다.  
결과: 로그인·등록 요청 모두 **404 / 422**로 전면 차단.

**원인**
계약 문서(19-4)에 임베딩 주체(클라이언트 vs 백엔드)가 명시되지 않아, 백엔드와 프론트가 서로 다른 방식으로 구현했다.

**해결**
- 백엔드를 multipart 이미지 수신 + 서버 측 임베딩 방식으로 수정
- `GET /auth/face/check-id` 엔드포인트 추가
- 계약 문서 19-4 §7.1 정정

## BUG-002 — 시뮬 사이트 Home 렌더 크래시 (OAuth Invalid URL)

**문제**
시뮬레이션 사이트가 서버에서 HTTP 200을 반환함에도 브라우저에서 흰 화면이 표시됐다. React가 렌더 중간에 크래시했기 때문으로, 콘솔에는 `TypeError: Invalid URL`이 기록됐다.

**원인**
Manus 템플릿 코드의 `getLoginUrl()` 함수가 환경변수 `VITE_OAUTH_PORTAL_URL`로 `new URL()` 객체를 만드는데, 이 변수를 설정하지 않아 `new URL("undefined/app-auth")`가 예외를 던졌다. 이 함수가 `useAuth` hook의 기본 인자에서 매 렌더마다 호출됐기 때문에 어떤 화면에서도 크래시가 발생했다.

**해결**
`getLoginUrl()` 진입부에 환경변수 미설정 시 `"/"` 로 폴백하는 가드 추가.

```ts
if (!oauthPortalUrl || !appId) return "/";
```

## BUG-003 — LightGBM model.txt CRLF 개행 → 로드 불가

**문제**
`models/churn/lightgbm/model.txt`를 LightGBM 네이티브 로더로 불러올 때 `Model format error, expect a tree here` 오류가 수백 줄 출력되며 Python 프로세스 자체가 abort(강제 종료)됐다. `try/except`로도 잡을 수 없다.

**원인**
Windows 환경에서 텍스트 모드로 파일을 저장하면서 모든 줄 끝에 `\r`(CR)이 추가됐다. LightGBM C++ 파서는 LF 기반 토큰 분해를 하므로 각 줄의 `\r`이 트리 헤더(`Tree=N`)를 깨뜨렸다.  
(현재 백엔드 서빙 경로는 `model.txt`를 사용하지 않으므로 운영 영향은 없었으나 잠복 지뢰 상태였다.)

**해결**
- 파일에서 `\r` 문자를 모두 제거해 LF로 정상화
- `.gitattributes`에 `models/**/model.txt -text` 추가해 CRLF 재유입 방지

## BUG-004 — 대시보드 모델 진단 탭 크래시 (언랩 누락)

**문제**
대시보드 모델 진단 탭에서 `AttributeError: 'str' object has no attribute 'get'` 오류가 발생해 탭 전체가 렌더되지 않았다.

**원인**
백엔드 `/models/active` 응답의 구조는 `{ ok, data: { "models": [...] } }` 인데, 프론트 코드가 `data` 자체를 리스트로 가정해 순회했다. 이 경우 `data`(dict)를 순회하면 키 문자열 `"models"`가 `m`으로 들어와 `m.get()`이 실패한다.

**해결**
`data["models"]`를 명시적으로 언랩하고, 이후 모델 식별자를 `model_id`(정수) 대신 `model_name`(문자열)으로 사용하도록 수정. dict/list/str 각 타입 방어 처리 추가.

## BUG-005 — 얼굴 로그인 흐름 점검 (개선 4건)

**문제**
로그인 자체는 동작했으나, 점검 결과 아래 4가지 문제가 발견됐다.

| 코드 | 내용 | 심각도 |
|---|---|---|
| M1 | 클라이언트(대시보드)에서 insightface를 직접 로드해 임베딩 이중 수행 (백엔드 임베딩 일원화 원칙 위반, ~300MB 추가 메모리) | 중간 |
| M2 | `api_client.py` 기본값이 잘못된 포트(8080)·키·USE_MOCK=true라 `.env` 누락 시 가짜 로그인 발생 가능 | 중간 |
| L1 | 로그인 점수 표시 시 백엔드 similarity가 없으면 하드코딩된 `0.954`(95.4%)를 표시 | 낮음 |
| L2 | `current_user_embeddings`가 세션에 세팅되지 않아 클라이언트 코사인 매칭 분기가 죽은 코드로 존재 | 낮음 |

**해결 (모두 2026-06-23 적용)**
- M1: `face_utils.py`에서 insightface 완전 제거 → OpenCV Haar 검출 전용으로 교체
- M2: 기본값을 `8090 / anchor-dev-key / USE_MOCK=false`로 정정
- L1: `or 0.954` 폴백 제거 → similarity 없으면 None 표시
- L2: 죽은 코사인 매칭 분기 및 미사용 파라미터 삭제

## BUG-006 — 백엔드 insightface 콜드스타트 → 얼굴 로그인 Read timeout

**문제**
첫 번째 얼굴 등록/로그인 시 백엔드 API 호출이 10초 타임아웃으로 실패했다.  
재시도하면 동작했다.

**원인**
백엔드에서 insightface buffalo_l 모델(검출·인식·랜드마크·성별 등 5개 서브모델)을 첫 호출 시 lazy 로드하는 데 약 6.8초가 걸렸다. 백엔드 uvicorn이 단일 워커로 동작 중이라 이 6.8초 동안 모든 요청이 블록됐고, 대시보드 타임아웃(10초)을 초과했다.

**해결**
- `backend/app/main.py` lifespan 훅에 백그라운드 사전 로드(prewarm) 추가: 서버 기동 시 `asyncio.to_thread(embedder._get_app())`으로 미리 로드
- `FaceAnalysis`에 `allowed_modules=["detection","recognition"]`으로 불필요한 서브모델(landmark·genderage) 제외 → 로드 시간 단축
- 대시보드 `.env`의 타임아웃을 10초 → 30초로 여유 확보

## BUG-008a — 시뮬 상품페이지 진입 시 dev 서버 전체 다운

**문제**
시뮬레이션 사이트에서 상품 상세 페이지(`/product/:id`) 또는 상품 목록 페이지에 진입하면 사이트 전체가 "꺼졌다"(dev 서버 프로세스 종료).

**원인**
`client/index.html`에 umami 애널리틱스 스크립트가 환경변수 플레이스홀더(`%VITE_ANALYTICS_ENDPOINT%`)가 치환되지 않은 채 잔존했다. 브라우저가 이를 상대경로로 해석해 `/product/%VITE_ANALYTICS_ENDPOINT%/umami` 요청을 보내면, Express dev 서버가 `decodeURIComponent('%VI...')` 시 `URIError`를 던지고 이것이 미처리 예외로 **Node 프로세스 자체가 종료**됐다.

**해결**
1. `index.html`에서 미치환 플레이스홀더 스크립트 제거
2. `main.tsx`에 동적 주입 로직 추가 — `VITE_ANALYTICS_ENDPOINT`가 실제 `http(s)://` URL일 때만 스크립트 삽입
3. `server/_core/index.ts`에 URI 디코드 실패 시 프로세스 종료 대신 **400 반환** 가드 추가

## BUG-008b — 차트 스키마 불일치·대시보드 리팩터·시뮬 UX 배치 (8건)

**문제 요약**
모델팀이 LightGBM 평가 artifact를 새 스키마로 교체하면서 발생한 연쇄 버그와 대시보드 리팩터 중 발생한 버그, 시뮬 UX 버그를 묶은 배치 리포트.

| 번호 | 증상 | 원인 |
|---|---|---|
| B1 | LightGBM 선택 시 진단 차트 전부 500 에러 | 모델팀이 artifact 키를 변경했는데 백엔드가 구 키를 직접 인덱싱 |
| B2 | 대시보드 전체 `NameError: live_diagnosis is not defined` | 함수 분리 리팩터 후 호출부 이름 미수정 |
| B3 | 회복 예상 매출 ₩0.0 | 좀비(구) 백엔드 프로세스가 8090 포트를 점유 |
| B4 | 모델 드롭다운에 모델 1개만 표시 | DB 활성 모델(1개) 기준 조회 → 산출물 보유 전체(7개)로 교체 필요 |
| B5 | 시뮬 이탈 게이지 막대가 표시 안 됨 | Tailwind CSS 동적 클래스 생성 패턴 오류 (JIT 미생성) |
| B6 | 쿠폰이 전부 5%만 발급 | 등급 기준이 단일 hazard 값으로만 판단돼 장바구니 세션이 항상 최하 등급 |
| B7 | "할인 쿠폰 받고 상품 보기" 클릭 시 아무 동작 없음 | 클릭 이벤트에 네비게이션 코드 누락 |
| B8 | 상품 클릭 시 "Product not found" | 정적 목록에만 조회하고 백엔드 카탈로그 API 미호출 |

**핵심 교훈**
- artifact 리더는 키를 직접 인덱싱하지 말고 `.get()`과 `isinstance` 가드로 스키마 변경에 견고하게 만들어야 한다.
- 백엔드 재기동 시 기존 프로세스가 포트를 점유하고 있지 않은지 반드시 확인해야 한다(좀비 프로세스).

## BUG-009 — 대시보드↔시뮬 Churn Rate 헤드라인 불일치

**문제**
같은 유저·같은 세션인데 이탈률 헤드라인 수치가 대시보드(30.6%)와 시뮬레이션 사이트(45.3%)에서 다르게 표시됐다. 3종 세부 지표(7일/하자드/바운스)는 양쪽에서 동일했다.

**원인**
헤드라인 이탈률을 서버와 대시보드 클라이언트 양쪽에서 각각 계산하되, 적용하는 정책이 달랐다.  
- 시뮬: 서버의 `apply_policy()`로 계산한 값 사용
- 대시보드: 세션 상태에 저장된 정책값으로 **로컬에서 재계산**
- 백엔드 재기동 시 인메모리 정책이 기본값(`max`)으로 초기화되지만 대시보드 세션 상태는 유지되어 두 값이 갈라짐

**해결**
1. 서버가 정책 적용값(`churn_rate`)을 한 번만 계산해 결과에 포함
2. 시뮬과 대시보드 모두 서버가 반환한 `churn_rate`를 그대로 표시 (로컬 재계산 제거)
3. 정책 설정을 `data/processed/realtime/churn_policy.json`에 파일로 영속화 → 백엔드 재기동 시에도 정책 유지

## 재발 방지 핵심 원칙 (전 버그 공통 교훈)

1. **API 계약에 임베딩 주체 등 책임 분담을 명확히 명시**한다 — 암묵적 가정이 BUG-001 같은 불일치를 만든다.
2. **환경변수를 URL·`new URL()`에 직접 넣을 때는 반드시 미설정 가드**를 추가한다.
3. **모델 artifact export는 LF 개행으로 저장**한다. `.gitattributes`로 CRLF 재유입을 차단한다.
4. **API 응답 봉투 구조(`{ok, data:{...}}`)의 내부 컨테이너는 항상 명시적으로 언랩**한다.
5. **임베딩·무거운 ML 연산은 백엔드 한 곳으로 일원화**하고, 서버 기동 시 사전 로드(prewarm)로 콜드스타트를 막는다.
6. **artifact 리더는 키를 직접 인덱싱하지 않는다** — `.get()` + `isinstance` 가드로 스키마 변경에 견고하게 작성한다.
7. **동일한 값은 서버에서 한 번만 계산하고 클라이언트는 표시만** 한다. 로컬 재계산은 정책·상태 갈라짐을 만든다.
8. **인메모리 상태(정책 등)는 파일 또는 DB에 영속화**한다 — 재기동 시 초기화로 인한 불일치를 방지한다.
9. **백엔드 재기동 시 구 프로세스 포트 점유 여부를 반드시 확인**한다(좀비 프로세스).
10. **함수 리팩터 시 grep으로 호출부를 전수 확인**한다.
