# DB 서버 선정 추천 리포트

작성일: 2026-06-18

대상 프로젝트: REES46 고객 이탈 예측, Colab 학습, Streamlit 얼굴 로그인 대시보드, Vercel API 연동

---

## 1. 결론

이 프로젝트에는 **Neon Postgres를 1순위로 추천**합니다.

이유는 단순합니다.

- Vercel과 공식 Marketplace 통합이 좋다.
- Postgres라서 REES46 이벤트 로그, feature table, prediction log, face login log를 모두 관계형으로 관리하기 좋다.
- serverless Postgres라 Vercel API와 궁합이 좋다.
- 무료/소규모 시작이 가능하고, 프로젝트 발표/데모 규모에 맞다.
- Colab, Streamlit, Vercel API가 모두 같은 `DATABASE_URL` 기반으로 접근할 수 있다.

추천 순위:

| 순위 | DB 서버 | 추천도 | 한 줄 판단 |
| ---: | --- | --- | --- |
| 1 | Neon Postgres | 매우 높음 | Vercel + Postgres + serverless 조합에서 가장 무난 |
| 2 | Supabase Postgres | 높음 | Auth/Storage/Realtime까지 쓰려면 좋음 |
| 3 | Railway Postgres | 보통~높음 | Streamlit/백엔드까지 같이 띄울 때 편함 |
| 4 | Render Postgres | 보통 | 전통적인 서버/Streamlit 배포와 같이 쓰기 좋음 |
| 5 | PlanetScale | 보통 | 대규모/브랜칭은 좋지만 현재 프로젝트에는 과함 |
| 6 | Aiven PostgreSQL | 보통 | 안정적인 managed Postgres지만 교육용 프로젝트에는 무거움 |

---

## 2. Vercel Postgres 주의

**Vercel Postgres 자체는 신규 프로젝트에서 쓰는 선택지가 아닙니다.**

Vercel 공식 문서 기준으로 Vercel은 외부 Postgres를 Marketplace로 연결하는 방식을 안내하고 있으며, 기존 Vercel Postgres 데이터베이스는 2024년 12월 Neon으로 이동되었습니다. 신규 프로젝트는 Marketplace의 Postgres integration을 설치하는 방식입니다.

따라서 선택지는 `Vercel Postgres`가 아니라 **Neon, Supabase, Railway, PlanetScale 등 Vercel Marketplace DB 통합**입니다.

출처:
- Vercel Postgres 문서: <https://vercel.com/docs/postgres>
- Vercel Marketplace Neon: <https://vercel.com/marketplace/neon>
- Vercel Marketplace Supabase: <https://vercel.com/marketplace/supabase>

## 3. 후보별 평가

### 3.1 Neon Postgres

| 항목 | 평가 |
| --- | --- |
| Vercel 연동 | 매우 좋음 |
| DB 유형 | Serverless Postgres |
| 프로젝트 적합성 | 매우 높음 |
| 장점 | Vercel Marketplace 통합, branching, autoscaling, scale-to-zero, read replica, serverless driver |
| 단점 | 완전한 BI/관리자 기능은 Supabase보다 적음 |
| 추천 용도 | 이번 프로젝트의 기본 DB 서버 |

Neon은 Vercel 통합 설명에서 fully managed Postgres, database branching, autoscaling, scale-to-zero, low-latency serverless driver 등을 강조합니다. 우리 프로젝트는 Vercel API와 Colab/Streamlit이 같은 Postgres를 바라보면 되므로 Neon이 가장 단순합니다.

추천 구성:

```text
Vercel API
  -> Neon Postgres

Colab
  -> Neon Postgres

Streamlit
  -> Vercel API 또는 Neon Postgres
```

출처:
- <https://vercel.com/marketplace/neon>
- <https://neon.com/docs/guides/vercel-overview>

### 3.2 Supabase Postgres

| 항목 | 평가 |
| --- | --- |
| Vercel 연동 | 좋음 |
| DB 유형 | Postgres + Auth + Storage + Realtime |
| 프로젝트 적합성 | 높음 |
| 장점 | Auth, Storage, Realtime, Dashboard, Row Level Security |
| 단점 | 우리는 얼굴 로그인 자체 구현을 쓸 예정이라 Auth 장점이 일부 중복 |
| 추천 용도 | 향후 사용자 계정/권한/파일 저장까지 확장할 때 |

Supabase는 Vercel Marketplace에서 Postgres Database, Auth, Storage, Edge Functions, Realtime을 함께 제공하는 통합으로 소개됩니다. 얼굴 로그인 외에 일반 이메일 로그인, 관리자 권한, 파일 저장까지 확장한다면 Supabase가 더 편합니다.

다만 이번 프로젝트는 `opencv_face_login` 기반 얼굴 인증을 직접 이식할 예정이므로, Supabase Auth의 장점이 전부 필요한 상황은 아닙니다.

출처:
- <https://vercel.com/marketplace/supabase>
- <https://supabase.com/docs/guides/integrations/vercel-marketplace>

### 3.3 Railway Postgres

| 항목 | 평가 |
| --- | --- |
| Vercel 연동 | 가능 |
| DB 유형 | Postgres 등 여러 인프라 |
| 프로젝트 적합성 | 보통~높음 |
| 장점 | DB와 백엔드/Streamlit 같은 장기 실행 서비스를 같이 운영하기 편함 |
| 단점 | Vercel-native DB 경험은 Neon/Supabase보다 약함 |
| 추천 용도 | Streamlit 앱까지 Railway에 같이 배포할 경우 |

Railway Vercel integration은 Railway의 Postgres, Redis, MySQL, Mongo 등을 Vercel production/preview deployment와 연결할 수 있게 해줍니다. Vercel은 API/프론트, Railway는 Streamlit/백엔드/DB를 맡는 하이브리드 구조를 원하면 괜찮습니다.

출처:
- <https://vercel.com/marketplace/railway>

### 3.4 Render Postgres

| 항목 | 평가 |
| --- | --- |
| Vercel 연동 | 직접 환경변수 연결 |
| DB 유형 | Managed Postgres |
| 프로젝트 적합성 | 보통 |
| 장점 | Streamlit/Flask 같은 Python 앱 배포와 함께 쓰기 편함 |
| 단점 | Vercel Marketplace 기준으로는 Neon/Supabase보다 덜 자연스러움 |
| 추천 용도 | Streamlit을 Render에 배포하고 DB도 Render에 둘 때 |

Render Postgres는 PgBouncer를 통한 connection pooling 구성이 가능하다고 안내합니다. Python 서비스와 DB를 한 플랫폼에서 운영하고 싶다면 실용적인 선택입니다.

출처:
- <https://render.com/docs/postgresql-connection-pooling>
- <https://render.com/docs/postgresql-creating-connecting>

### 3.5 PlanetScale

| 항목 | 평가 |
| --- | --- |
| Vercel 연동 | 좋음 |
| DB 유형 | MySQL 호환 serverless DB, Postgres 제품도 제공 |
| 프로젝트 적합성 | 보통 |
| 장점 | Vercel integration, connection string 자동 설정, 확장성 |
| 단점 | 우리 스키마/분석 쿼리에는 일반 Postgres 선택지가 더 단순 |
| 추천 용도 | 대규모 웹서비스형 DB, DB branching 중심 개발 |

PlanetScale은 Vercel Marketplace에서 connection string 자동 설정을 제공합니다. 다만 REES46 이벤트 분석, JSONB, Colab/SQL 분석 편의성까지 고려하면 이번 프로젝트는 Neon/Supabase Postgres가 더 직관적입니다.

출처:
- <https://vercel.com/marketplace/planetscale>
- <https://planetscale.com/docs/postgres/connecting>

### 3.6 Aiven PostgreSQL

| 항목 | 평가 |
| --- | --- |
| Vercel 연동 | 직접 환경변수 연결 |
| DB 유형 | Fully managed PostgreSQL |
| 프로젝트 적합성 | 보통 |
| 장점 | 안정적인 managed DB, 확장/백업/운영 기능 |
| 단점 | 교육용/발표용 프로젝트에는 설정과 비용 관점에서 과할 수 있음 |
| 추천 용도 | 운영 안정성, 백업, 확장성이 중요한 장기 서비스 |

Aiven은 fully managed PostgreSQL을 제공하고, JSONB와 다양한 확장 기능을 쓸 수 있는 일반 Postgres 기반입니다. 다만 Vercel Marketplace 중심의 빠른 데모에는 Neon이 더 가볍습니다.

출처:
- <https://aiven.io/docs/products/postgresql>

## 4. 우리 프로젝트 권장 아키텍처

### 4.1 1차 추천안: Neon 중심

```text
Vercel API
  -> Neon Postgres

Streamlit 얼굴 로그인 대시보드
  -> Vercel API
  -> Neon Postgres

Colab 학습 노트북
  -> Neon Postgres 직접 연결
  -> models/outputs 생성
  -> model_registry 갱신
```

장점:
- 가장 단순하다.
- Vercel과 맞다.
- Postgres라 분석/로그/예측/얼굴 로그인 로그를 한 DB에서 관리할 수 있다.
- 발표 때 구조 설명이 쉽다.

### 4.2 대안: Supabase 중심

```text
Vercel API
  -> Supabase Postgres

Streamlit
  -> Supabase Postgres 또는 Vercel API

추후 일반 로그인/Storage/Realtime
  -> Supabase Auth/Storage/Realtime 사용
```

장점:
- Supabase Dashboard가 편하다.
- 권한/스토리지/실시간 구독까지 확장하기 좋다.

단점:
- 얼굴 로그인 자체 구현과 Supabase Auth가 역할이 겹칠 수 있다.

### 4.3 Streamlit 배포까지 같이 고려하는 대안

Streamlit 자체는 Python 장기 실행 앱입니다. Vercel serverless API와는 성격이 다르기 때문에 Streamlit을 실제 배포하려면 다음 중 하나가 좋습니다.

| 방식 | 설명 |
| --- | --- |
| 로컬 실행 | 수업/발표 데모에 가장 간단 |
| Streamlit Community Cloud | Streamlit 앱만 빠르게 공유 |
| Render | Python 웹 앱 + Postgres를 같이 운영 |
| Railway | Streamlit/백엔드/DB를 같이 운영 |
| Vercel | API/Next.js 프론트에 적합. Streamlit 직접 배포는 비추천 |

## 5. 최종 추천

이번 프로젝트는 **Neon Postgres + Vercel API + Streamlit 데모 앱** 구조를 추천합니다.

구체적으로는:

```text
DB 서버: Neon Postgres
API: Vercel serverless API
학습: Colab에서 Neon 연결
프론트: Streamlit 얼굴 로그인/대시보드
모델: 로컬 models/ + DB model_registry
로그: DB prediction_log, face_login_log, realtime_event_log
```

Supabase는 2순위입니다. 얼굴 로그인 외에 이메일 로그인, 파일 저장, Realtime 구독까지 확장할 계획이 생기면 Supabase로 바꿀 가치가 있습니다.

## 6. 체크리스트

- Neon 프로젝트 생성
- Vercel Marketplace에서 Neon integration 설치
- Vercel 환경변수에 `DATABASE_URL` 확인
- Colab secret 또는 `.env`에 같은 DB URL 등록
- `db/schema.sql` 실행
- REES46 원본 적재
- Streamlit에서 DB 또는 Vercel API 연결
- 얼굴 로그인 로그와 예측 로그가 DB에 쌓이는지 검증
- 발표 전 DB 비밀번호/서비스키가 노출되지 않았는지 확인
