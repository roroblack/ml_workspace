# 17-7-1. 전처리 최적화 · 논문 리서치 · 7모델 최고성능 + 통합 최고성능 구조 계획서

> 목적: **REES46 화장품 이탈예측**에서 `v2_5m` 10피처/주별 시퀀스/라벨 2종과의 **호환을 유지**하면서 (1) 7개 모델 각각 최고 성능, (2) 모든 모델 통틀어 최고 성능 구조를 만드는 **전처리 + 아키텍처 + 베이지안 탐색 계획서**.
> 입력: `search.txt`(첫 `----` 이전), [17-6-2], [17-6-4], [17-6-5], `v2_5m/README.md`.
> 리서치: WebSearch/WebFetch로 인용 논문 실재성·수치 검증.
> 범위: **계획서까지**(장시간 베이지안 실행은 본 작업 밖, 스크립트 스켈레톤 경로/구성만 명시).

## 0. 핵심 결론 (먼저 요약)

1. search.txt의 **전략 방향(시간간격·하이브리드·MTL·DL→GBM 스태킹)은 학술적으로 옳다**. 그러나 **구체 수치/논문명/도메인에 과장·오류**가 섞여 있다(아래 §1 표).
2. **순수 DL이 안 되는 이유**는 학술적으로 확립됨: ① 추천DL의 약한 baseline 문제(Jannach RecSys'19), ② **테이블형 데이터에서 GBDT가 여전히 우위**(Grinsztajn NeurIPS'22), ③ 이탈은 **recency 지배** 신호라 long-sequence DL이 손해.
3. **GBM/Last-cat을 넘는 길은 "교체"가 아니라 "결합"**: 강력한 통계 피처(Wide) + 시퀀스 임베딩(Deep)을 **한 GBM/하이브리드 안에서** 합치는 것. DL→GBM 스태킹은 Kaggle OTTO/H&M에서 실증된 표준(co-visitation 후보 → GBT 재랭커 + W2V/MF 임베딩 피처).
4. **5m 호환은 추가형(additive)으로만**: `v2_5m` 10피처·주별 시퀀스·라벨 2종(`churn`,`churn_no_purchase`)을 **정본으로 고정**하고, 신규 피처(Δt·dwell·last_cat·cat/brand 임베딩·시간간격)와 DL 임베딩을 **컬럼/채널 추가**로 얹는다([17-6-5] 4원칙 준수).
5. 베이지안은 **전처리+HP 공동탐색 + calibration + 임계값**을 한 optuna study로([17-6-4] P1 회수). 평가는 **시간외삽(Feb) PR-AUC/Brier/ECE**.

## 1. search.txt 분석 요약 + 사실검증

### 1.1 search.txt 요지 (첫 `----` 이전)
- 순수 DL(BERT4Rec/GPT/SASRec)이 Last-cat 휴리스틱·GBM을 못 이김 → **정상적 절벽**.
- 돌파구 3종: **(a) 시간간격 주입(TiSASRec)**, **(b) 하이브리드(Wide&Deep/DeepFM/DLRM)**, **(c) MTL/MMoE**.
- 치트키: **SASRec hidden state → 통계 피처와 concat → LightGBM**.
- 근거 논문 6편 + 벤치 수치 표 2개, 코호트 개념, 논문별 churn Y 정의, REES46 타임스탬프 포맷.

### 1.3 추가로 확인한 핵심 근거 (내 리서치)
- **GBDT 우위의 학술 근거**: Grinsztajn et al. "Why do tree-based models still outperform deep learning on typical tabular data?" (NeurIPS'22, arXiv 2207.08815) — 45개 데이터셋, **HP 튜닝 후에도** 트리계열 우위, 원인은 inductive bias(불규칙 함수·비정보 피처 강건성·회전 비불변). → 우리 [17-6-2]의 "부스팅 계열 일관 최강(LightGBM/CatBoost Feb~0.79)" 결과와 정확히 일치.
- **REES46 churn 실증**: 외부 연구들이 LightGBM으로 REES46 churn AUC 0.84~0.95 보고(라벨창/모집단 정의에 따라 상이). → 우리 0.79대는 **recency≤7 코호트 + 7일 무활동 라벨**이라는 **보수적·누수차단** 설정 탓일 수 있음(낮다고 단정 금지, 라벨창 민감도 분석 필요).
- **calibration**: isotonic이 Platt 대비 ECE 평균 ~22%↓(데이터 충분 시). **calibration은 별도 검증셋(누수차단)에서 fit, test에서 평가**가 표준. → [17-6-4] P1의 보정/임계값 항목에 직접 대응.

## 4. 7모델별 최적 전처리 + 베이지안(optuna) 탐색안

> 공통: **전처리 탐색공간 + 모델 HP**를 **하나의 optuna study**로 공동탐색([17-6-4] P1). 내부 3-fold(또는 Nested), 목적함수 = **Feb 시간외삽 PR-AUC**(보조로 AUC). 학습 후 **isotonic calibration(별도 검증셋) + F1/비용기반 임계값**을 study 산출물에 기록. SEED 고정 + DL은 3시드 평균.

### 4.1 모델별 전처리 탐색공간 + HP 공동탐색

| 모델 | 전처리 탐색공간 | 핵심 HP 탐색공간 | 17-6-2 기준 메모 |
| --- | --- | --- | --- |
| **DecisionTree** | scaler{none,robust} × log1p{T,F} × imbalance{none,smote,classweight} | max_depth, min_samples_leaf, ccp_alpha | 기존: robust·log |
| **RandomForest** | scaler{none,minmax} × log1p{T,F} × imbalance{none,classweight} | n_estimators, max_depth, max_features, min_samples_leaf | 기존: minmax·log |
| **LogReg** | scaler{std,minmax,robust} × log1p{T,F} × imbalance{none,smote,classweight} × poly{1,2} | C(1e-3~1e2), penalty{l1,l2,en}, l1_ratio | 기존: minmax·log·**SMOTE** |
| **XGBoost** | scaler=none(고정) × log1p{T,F} × **임베딩피처 on/off** | max_depth, eta, subsample, colsample, min_child_weight, **reg_alpha/lambda**, n_est(2000)+ES40 | 기존: raw·ES best_iter53 |
| **LightGBM** ★ | scaler=none × log1p{T,F} × cat_native{T,F}(`last_cat`을 native cat) × 임베딩 on/off | num_leaves, max_depth, lr(0.05), min_child_samples, feature/bagging_fraction, **lambda_l1/l2**, n_est+ES40 | 기존: raw, Feb 0.7895 |
| **CatBoost** ★ | scaler=none × log1p{T,F} × `last_cat`/`brand`를 **cat_features로** | depth, lr, l2_leaf_reg, bagging_temperature, border_count, n_est+ES | 기존: raw, **Feb 0.7902(최고)** |
| **Transformer** | norm{log,zscore} × seq_len{4,8,12,17} × 채널{3,5} × mask{T} | d_model, n_heads, n_layers, dropout, lr, batch, focal{T,F}, patience5+best복원 | 기존: log, val 0.7878 |

- **부스팅 3종**: scale·log 거의 불필요([17-6-2] 확인) → 탐색은 **HP + reg + 임베딩피처 on/off**에 집중. CatBoost/LightGBM은 `last_cat`·`brand`를 **네이티브 범주형**으로 주는 옵션이 임베딩보다 셀 수 있음(필수 탐색).
- **선형(LogReg)**: scale+log+SMOTE 민감 → 전처리 탐색 가치 큼.
- **Transformer**: seq_len·채널·focal이 핵심. **3~5시드 평균**([17-6-4] P2).

### 4.2 optuna study 설계(공통 스켈레톤)
```
study = optuna.create_study(direction="maximize")  # 목적 = Feb PR-AUC
def objective(trial):
    prep = sample_prep(trial, model_name)      # scaler/log/imbalance/embed on-off
    hp   = sample_hp(trial, model_name)        # 모델별 HP
    Xtr  = prep.fit_transform(train_v2)        # train만 fit
    cv   = time_series_cv(Xtr, y, n=3)         # 시간 인지 분할
    model.fit(..., early_stopping=ES40/patience5)
    cal  = CalibratedClassifierCV(isotonic, cv=val_fold)  # 별도 검증셋
    thr  = optimize_threshold(cal, metric="f1"|"cost")
    return pr_auc(cal.predict_proba(Feb))
# 산출: best prep + best hp + calibrator + threshold → prep_{Model}.joblib + manifest
```
- **산출물**: `prep_{Model}.joblib`(전처리+모델+calibrator+threshold), `models7_manifest.json`(model→prep_config→artifact→{PR-AUC,AUC,Brier,ECE,thr}). [17-6-5] 원칙② 충족(서빙 재현).

## 5. 모든 모델 통합 최고 성능 구조 (스태킹 + 하이브리드 + MTL)

### 5.1 권고 아키텍처 (3계층)
```
 ┌── L0 임베딩 추출기 (DL, train에서만 fit) ──────────────────┐
 │  SASRec / TiSASRec  (이벤트 시퀀스 + 시간간격 relation)     │
 │     → user hidden state  seq_emb[d]   (예 d=64)            │
 │  category_id / brand  → cat_emb[k], brand_emb[k]          │
 │  (선택) DLLM2Rec식 텍스트(성분/상품명) distill → 의미피처   │
 └────────────────────────────────────────────────────────────┘
                 │  concat 컬럼으로 주입
                 ▼
 ┌── L1 메타 GBM (LightGBM/CatBoost) ── 최종 churn 분류 ───────┐
 │  X = 정본10 + 추가스칼라(Δt/dwell/last_cat/loyalty…)        │
 │      + seq_emb + cat_emb + brand_emb                       │
 │  → isotonic calibration → threshold                        │
 └────────────────────────────────────────────────────────────┘
   (대안 L1') Wide&Deep/DeepFM 하이브리드: Wide=정본+통계,
              Deep=seq_emb concat → 단일 joint 분류 (스태킹과 비교)

 ┌── (선택) MTL 백본: 공유 Transformer + 3 헤드 ─────────────┐
 │  H1 churn(주) · H2 churn_no_purchase(보조) · H3 next_cat   │
 │  loss = w1·BCE + w2·BCE + w3·CE  (dwell 가중 옵션)         │
 └────────────────────────────────────────────────────────────┘
```

### 5.2 왜 이 구조인가
- **L1 GBM 스태킹**이 1순위: Kaggle OTTO/H&M 실증 + GBDT 테이블 우위(NeurIPS'22) + 우리 [17-6-2] 결과(부스팅 최강)와 정합. **하한선=현재 CatBoost 0.7902를 깔고**, seq_emb가 +α.
- **하이브리드(L1')는 비교군**: Wide&Deep/DeepFM은 단일 joint라 운영 단순하나, 화장품 recency 지배에선 스태킹이 더 안전(둘 다 돌려 manifest로 비교).
- **MTL은 부가**: 화장품 주기성 → `churn_no_purchase`(이미 보유)·`next_cat`이 자연스러운 보조태스크. seq_emb 품질을 끌어올려 L1에 환류.

### 5.3 단계별 실행 계획
| 단계 | 작업 | 산출 | 성공기준 |
| --- | --- | --- | --- |
| T1 | 이벤트 시퀀스 + Δt relation 추출 | `processed_eventseq/` | 누수 없는 시간 분할 확인 |
| T2 | SASRec→TiSASRec 학습, hidden state 추출 | `seq_emb_train/test.npy` | next-item NDCG로 임베딩 sanity |
| T3 | cat/brand 임베딩 학습(또는 entity-emb) | `cat_emb.joblib`,`brand_emb.joblib` | OOV(UNK) 처리 검증 |
| T4 | `*_tabular_v2.parquet` 생성(정본+추가+임베딩) | v2 정본 | 컬럼 스키마 v2 통과 |
| T5 | **L1 LightGBM/CatBoost 스태킹** + 4.2 베이지안 | manifest, prep_joblib | **Feb PR-AUC ≥ 현행, 가능하면 AUC>0.7902** |
| T6 | (비교) Wide&Deep/DeepFM 하이브리드 | 별도 manifest 행 | 스태킹과 정량 비교 |
| T7 | (부가) MTL 백본 → seq_emb 갱신 → T5 재실행 | v2 manifest++ | 환류 향상 여부 |

## 7. 위험 · 한계

| 위험 | 내용 | 완화 |
| --- | --- | --- |
| **연산비용** | SASRec/TiSASRec/MTL 학습 + optuna 공동탐색은 장시간 | 본 작업은 **계획서까지**. 실행은 단계(T1→T7) 분리, 부스팅 우선·DL 임베딩은 캐시 |
| **화장품 주기성** | 스킨케어=재구매(이탈↓) vs 색조=단발(이탈↑) → 단일 7일창이 도메인 왜곡 | `churn_no_purchase` 병행 + **45일 소모주기 라벨** 민감도 분석(라벨창 sweep) |
| **임베딩 누수** | seq_emb/cat_emb를 전체에서 fit하면 누수 | **train에서만 fit→저장**, test/serve는 transform만 |
| **스태킹 과적합** | L0 임베딩→L1 GBM이 동일 train이면 낙관 편향 | OOF(out-of-fold) 임베딩 생성으로 메타피처 만들기 |
| **수치 인용 오류** | search.txt #6·#8 표를 발표에 쓰면 사실관계 오류 | §1.2 정정표만 사용, 원수치 폐기 |
| **기대 향상 불확실** | DL 임베딩이 recency 지배에서 +α가 작을 수 있음 | 성공기준을 "현행 유지+α"로, 안 되면 **네이티브 cat(last_cat/brand) GBM**만으로도 가치 |
| **GBDT 우위 불변 가능성** | NeurIPS'22대로 끝까지 GBM이 최강일 수 있음 | 그 경우 결론="DL은 **피처 생성기**, 최종 분류기는 GBM" — 이미 1순위 설계와 일치 |
