## 1. 결론 — 로그인은 연결되어 동작함 ✅
프론트↔백엔드 로그인 경로가 계약대로 배선돼 있고, BUG-001에서 register→login 매칭(similarity 1.0)까지 검증됨.

| 질문 | 점검 결과 |
| --- | --- |
| 얼굴 정보가 서버로 들어가 로그인 신호를 프론트가 처리하나? | ✅ `login_face`가 이미지를 **multipart로 `/auth/face/login` 전송** → 백엔드 임베딩·매칭 → `{user_id, display_name, role, similarity}` 반환 → `_apply_login_session`이 `session_state.is_logged_in/user_id/display_name/role` 세팅 → `02_dashboard.py`로 이동 |
| 로그인 시 회원정보 잘 요청·수신하나? | ✅ 로그인 응답의 `display_name/role`을 session_state에 저장. (`02_dashboard`가 이름/역할 표시) |
| 아이디 검색(중복확인) 서버 요청? | ✅ `check_user_id_available` → **`GET /auth/face/check-id?user_id=`** → `{exists, available}` 파싱 |
| 등록 흐름? | ✅ `register_face` → **multipart `/auth/face/register`** (user_id·display_name·role·image·face_bbox) |
| API 인증 헤더? | ✅ `api_client`가 `X-API-Key` 자동 첨부(백엔드 `require_api_key` 충족) |
| 환경설정? | ✅ `.env` = `8090 / anchor-dev-key / USE_MOCK=false` 확인 → 런타임 실연동 |

## 2. 발견된 문제 (4건)

### 🟠 (M1) face_utils가 **클라이언트에서 insightface(buffalo_l)를 또 로드** — 중복·19-7-1 §1 위반
- `services/face_utils.py`: `from insightface.app import FaceAnalysis` + `app = FaceAnalysis(name='buffalo_l', root='.')` + `np.dot(current_user_embeddings, main_face.embedding.T)` → **검출+임베딩+코사인 점수를 클라에서 수행**.
- 그러나 BUG-001로 **임베딩·매칭은 백엔드**가 한다(19-7-1 §1 "대시보드는 얼굴 임베딩 직접 계산 안 함"). → **임베딩이 클라+백엔드 이중**, Streamlit 프로세스에 ~300MB 모델 로드(무겁고 느림).
- **권장**: 클라는 **OpenCV(Haar/DNN) 검출만**(bbox) 하고 임베딩은 백엔드로 일원화. `face_utils`를 경량 검출 전용으로 교체.

### 🟡 (M2) api_client 기본값이 위험 (`.env` 누락 시 landmine)
- `api_client.py`: `DASHBOARD_API_BASE_URL` 기본 **`http://localhost:8080`**, `DASHBOARD_API_KEY` 기본 **`dev-key`**, `DASHBOARD_USE_MOCK` 기본 **`true`**.
- `.env`가 덮어써서 지금은 정상이지만, **.env 미로딩/누락 시**: (a) 8080·dev-key로 **401**, 또는 (b) `USE_MOCK=true` → `login_face`가 **백엔드 안 거치고 가짜 `demo_customer` 반환**(로그인 위장).
- **권장**: 기본값을 `8090 / anchor-dev-key / USE_MOCK=false`로 정정(또는 최소 `USE_MOCK` 기본 false). 19-4/19-7-1 키 표기도 `anchor-dev-key`로 통일.

### 🟡 (L1) 로그인 점수 하드코딩 폴백 `or 0.954`
- `01_face_login.py:116` `score = data.get("score") or data.get("similarity") or 0.954` → 백엔드 `similarity`가 없거나 0이면 **가짜 95.4%** 표시.
- **권장**: 실제 `similarity`만 사용하고 없으면 "N/A". 데모 인상조작 오해 방지.

### 🟢 (L2) `current_user_embeddings`가 한 번도 설정 안 됨 → 클라 코사인 매칭 죽은 코드
- `01_face_login.py`가 `st.session_state["current_user_embeddings"]`를 **세팅하지 않음** → `face_utils` login 모드의 `np.dot(...)` 점수 분기(항상 None)는 **사실상 죽은 코드**. (실매칭은 백엔드라 기능 무해, 정리 대상.)

## 3. 영향
- 로그인 자체는 정상 동작(치명 X). 단 **M1로 대시보드 기동/촬영이 무겁고 느림**, **M2로 환경 어긋나면 401 또는 가짜 로그인**, **L1로 표시 점수 신뢰성↓**.

## 4. 권장 조치 (우선순위)
1. **M1**: `face_utils`를 OpenCV 검출 전용으로 교체(클라 insightface 제거) — 19-7-1 §1·BUG-001 일원화.
2. **M2**: `api_client` 기본값 정정(8090/anchor-dev-key/USE_MOCK=false).
3. **L1**: 로그인 점수 폴백 `0.954` 제거 → similarity만/“N/A”.
4. **L2**: 죽은 `current_user_embeddings` 분기 정리.

## 5. 검증 근거
- `.env` 실값 확인(8090·anchor-dev-key·false). `auth_service`/`api_client`/`01_face_login` 코드 경로 추적. 백엔드 `auth_router`(check-id·register·login·me) 존재·BUG-001 매칭 검증(similarity 1.0).
