## 4. 해석 — 풀데이터로도 "DL 최상위, 그러나 천장"

1. **DL(GRU/Transformer)이 일관되게 최상위** — 463k 윈도우의 대규모 test에서도 GBM·MLP·Ridge를 모두 앞섬. **17-3-3의 방향이 풀데이터로 견고히 재확인**(우연 아님).
2. **그러나 마진은 여전히 얇다** — GRU 0.2959 vs GBM 0.2986 ≈ **RMSE −0.9%**, AUC +0.4p. 데이터 47배·세션 38배로 늘려도 격차가 안 벌어짐.
3. **Ridge만 확연히 뒤짐(0.317)** — 포화 비선형을 선형이 못 따라감(B-2와 동일 패턴, 실데이터서도 성립).
4. **왜 천장인가**: 미래 level은 *미래 클릭*(예측불가)에 좌우 → 증분에서 짜낼 수 있는 정보가 ~0.296 RMSE에서 포화. 모델 정교화로 더 못 내려감.

## 5. 개선안 진행 결과 (정직하게)

| 개선 시도 | 결과 | 판정 |
| --- | --- | --- |
| ① **category 임베딩**(Transformer+Emb) | 0.2969 (plain 0.2965보다 **나쁨**) | ❌ 실패 |
| ② **GBM+GRU 앙상블** | 0.2957 (GRU 0.2959와 동률, 최적가중 0.7=거의 GRU) | △ 무의미 |

- **임베딩 실패 이유**: 장바구니 *가치(level)* 는 *어떤 카테고리냐* 가 아니라 *얼마짜리를 담고/빼냐(price·행동)* 가 결정. category는 신호가 아님. ([리포트16](16_전처리_기법정리_베이지안최적화_파일포맷.md)의 "정형 임베딩 무용"과 일관 — 임베딩은 *순서/추천* 타깃에서만 유효.)
- **앙상블 무의미 이유**: GBM이 GRU에 더해줄 직교 정보가 거의 없음(둘 다 같은 증분에서 적분) → 최적가중이 0.7 GRU로 쏠림.
- **→ 진짜 레버는 모델이 아니라 "문제 재정의"**: ρ↑(긴 메모리)·H↑(긴 호라이즌)으로 *적분 길이*를 늘리면 [B-2](17-3-2_다노드_부하예측.md)처럼 DL 격차가 커질 것(이번엔 ρ0.85·H5라 단기 적분 → 트리가 따라옴).

## 6. 우리 프로젝트 활용처 (스트림 누적 = DL의 정당 영역)

이 실험이 검증하는 건 **"클릭(view/cart/remove/purchase)이 하나씩 들어오며 구매의도/장바구니가치가 쌓이는 걸 실시간 누적 처리"** — 즉 [05-x 아키텍처](05-5_프로그램_구조도_및_함수_변수_비전_명세서.md)의 **빠른 루프**:

| 컨텐츠/기능 | 모델 | 근거 |
| --- | --- | --- |
| **① Vercel 시뮬 → Streamlit 실시간 세션 구매의도/이탈 예측** | **GRU(경량 시퀀스 DL)** | 스트림 누적 → DL 최상위(이 실험). Transformer는 12배 느려 부적합 |
| **② 이탈방지 프로토콜**([17-2 §5](17-2_초단위_실시간_세션이탈_프로토콜.md)) | 위 스코어러 | high-intent(level>0.85) 탐지 AUC 0.866 → 쿠폰/개입 |
| **③ 아이템 추천** | `recommend_user_interest.parquet` + 임베딩 | 누적 관심(category/brand 가중) — 룰 §4 |
| 일/주 단위 장기 churn([17-1](17-1_실시간_모델비교.md)) | **경량 GBM** | recency 집계로 충분, DL 불필요 |

→ **실시간 예측 서비스([predictor.py](../sample_project/frontend_streamlit/services/predictor.py))엔 GRU**(정확도 최상 + 지연 GBM과 동급), **장기 churn 배치엔 GBM**. "빠른 루프=DL, 느린 루프=GBM"이 이 실험들로 수치 확정.

## 7. 17-x 전체 결론 (요약)

- DL이 트리를 이기는 건 **"증분 관측 → 비선형 누적 적분"** 일 때뿐. 합성서 강하면 +18%([B-2](17-3-2_다노드_부하예측.md)), 실 REES46선 +0.9~1.4%([17-3-3/4](17-3-4_풀REES46_세션누적_전모델비교.md)), recency 집계로 환원되면 트리 승([17-1/2](17-1_실시간_모델비교.md)).
- 실데이터의 DL 우위는 **실재하지만 작다** → 운영은 **GRU(빠른 루프)/GBM(느린 루프)** 분리.
- 모델 정교화(임베딩·앙상블)보다 **문제 재정의(적분 길이·증분 풍부화)** 가 다음 레버.
