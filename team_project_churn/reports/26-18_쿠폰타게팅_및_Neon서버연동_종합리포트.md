## 1. 쿠폰 타게팅 기능 (스펙 + 반영)

### 1.1 목표
장바구니 **2개 이상** 담은 고객 중 **이탈 가능성 높은 고객**을 미리 찾아 **할인 쿠폰** 제공 → 이탈률 감소.

### 1.2 모델 구성 (쿠폰 모델)
| 항목 | 값 |
| --- | --- |
| 알고리즘 | **LightGBM**(이진 분류) |
| 학습 데이터 | 고객 행동 약 **126만 명** |
| 피처 | 장바구니 횟수·구매 금액·세션 수·비율 피처 등 **33개** |
| 불균형 처리 | 이탈/비이탈 **언더샘플링** |

### 1.3 성능 (테스트 29만 명)
| 지표 | 값 |
| --- | --- |
| 정확도 | **89.7%** |
| 이탈 탐지율(Recall) | **96%** |
| F1 | **94.4%** |

### 1.4 쿠폰 대상자 (장바구니 2+ 고객 54,783명 → 41,093명 선정)
| 등급 | 기준(이탈확률) | 인원 |
| --- | --- | ---: |
| **20% 할인(긴급)** | ≥ 80% | 20,747 |
| **10% 할인(주의)** | 60–80% | 15,335 |
| **5% 할인(관심)** | 50–60% | 5,011 |

산출물: `coupon_targets.csv`(user_id·n_cart·이탈확률·쿠폰등급), 이탈확률 분포·등급별 인원 시각화.

### 1.5 우리 시스템에 반영 ✅
실시간 이탈방지 액션(`sim_usecase.decide_action`)이 위 **쿠폰 등급 체계와 정합**되도록 보강:
- 신규 `coupon_grade(p)`: `p≥0.8→20%(긴급)`, `0.6–0.8→10%(주의)`, `0.5–0.6→5%(관심)`, else 5%(기본). (검증: 0.85→20/긴급, 0.65→10/주의, 0.55→5/관심)
- 장바구니 담고 미구매(`cart_no_purchase`) 액션이 **이탈확률 등급별 할인** + `coupon_grade`·`coupon_target`(n_cart≥2) 필드 반환 → 배치 쿠폰모델과 동일 등급으로 실시간에서도 작동.
- 즉 **배치(coupon_targets.csv) = 사전 일괄 쿠폰 발송**, **실시간 액션 = 세션 중 같은 등급으로 즉시 개입** — 두 경로가 한 등급 체계로 통일.

> ⚠ 참고: 쿠폰 모델은 **33피처 LightGBM**(배치), 우리 실시간 세션 추론은 v2 22피처/하자드라 둘은 입력이 다름. 등급 체계(임계 80/60/50%)만 공유. 실시간 세션 확률은 낮게 나올 수 있어, 고등급(20%)은 주로 **배치 쿠폰 발송**에서 발생.

### 1.6 배치 산출물 + 백엔드 서빙 ✅ (구현)
**`backend/scripts/make_coupon_targets.py`**: `train_tabular_v2`(2+장바구니) → `prep_LightGBM_v2.joblib`(isotonic 보정) 채점 → 등급 → 산출:
- `data/processed/coupons/coupon_targets.csv`(user_id·n_cart·churn_prob·coupon_grade·discount_pct)
- `coupon_summary.json`, `coupon_dist.png`(이탈확률 분포 + 등급별 인원)

**우리 모델 실측(코드 동작 검증):** 2+장바구니 **265,881명 → 쿠폰대상 24,434명** (주의 1,045 · 관심 23,389 · 긴급 0).
> ⚠ 스펙(54,783→41,093, 긴급 20,747)과 **수치 다름**: 모델팀은 **언더샘플링**(확률 부풀림·미보정)이라 고등급 多, 우리 v2는 **isotonic 보정**이라 보수적(2+장바구니=인게이지먼트↑ → 대부분 저확률). 파이프라인·등급체계는 동일, 절대수만 모델 차이.

**백엔드 서빙(artifact-first):** `infrastructure/files/coupons.py` + `dashboard_router`:
- `GET /coupons/summary` → 등급별 인원(265,881→24,434 확인) ✅
- `GET /coupons/targets?grade=&limit=` → 이탈확률 내림차순 대상자(top 0.71) ✅
- CSV 없으면 빈 결과(폴백). 모델팀이 33피처 `coupon_targets.csv`를 같은 경로에 두면 그대로 서빙.

## 2. Neon↔서버 연동 (Cloudflare 터널)

### 2.1 왜 터널인가
- Vercel 시뮬(`gajimasimul.vercel.app`)은 **인터넷**, 우리 백엔드는 **로컬(8090, NAT 뒤)** → 브라우저가 `localhost`로 직접 못 닿음 + 혼합콘텐츠 차단.
- 우리 백엔드는 **무거워(torch·insightface·catboost ~1GB+ · 로컬 모델 · MySQL)** 무료 클라우드에 "그대로" 배포 곤란.
- → **Cloudflare quick tunnel**: 배포 없이 로컬 서버를 공개 HTTPS로 노출. **포트포워딩·공인IP·공유기설정 불필요**(outbound 연결이라 NAT 통과).

### 2.2 적용
```bash
cloudflared tunnel --url http://localhost:8090
#  → https://springfield-hampshire-roman-example.trycloudflare.com (발급)
```
- 검증: 터널 경유 `/health`=`{ok:true}`, `/api/churn/predict`=churn+action(discount_related) ✅
- Vercel 설정: **Settings → Environment Variables**(환경 아님) → `VITE_FASTAPI_URL = <터널 URL>`(Key/Value 별도 칸) → Production 체크 → **Redeploy**.
- ⚠ quick tunnel URL은 cloudflared 재시작 시 바뀜(고정은 Cloudflare 계정+named tunnel). 로컬 PC+터널 켜둬야 동작.

### 2.3 Neon 카탈로그 적재
- `simulation_site/neon/upload_neon.py`(psql 불필요, psycopg2) / `upload_neon.sh`(psql) → `schema_neon.sql` + seed CSV 4종(categories/brands/products/similarity) 적재.
- 실행: `python upload_neon.py "postgresql://...neon.tech/db?sslmode=require"`(접속정보 필요).
- ⚠ **올려도 화면 상품은 안 바뀜** — 시뮬이 정적 `productData.ts`(25개)를 보고, Neon 카탈로그를 안 읽음. 54k 표시하려면 시뮬↔Neon/백엔드 카탈로그 연동 별도 필요.

### 2.4 액션 루프(26-17 요약)
`decide_action` → `/api/churn/predict` 응답 `recommended_action` → 시뮬 `ChurnActionPanel.tsx`가 렌더:
sns_view(첫진입·SNS 클릭=view) / discount_related(담고 미구매·등급 할인) / discount(조회만) / none.

## 3. 현재 가동 상태 + 왜 이렇게 구성했나 (사용자 요청)

| 구성 | 상태 | 역할 / 왜 |
| --- | --- | --- |
| **백엔드 8090** | UP | churn 추론·액션·추천·카탈로그 서빙. 모델/MySQL 로컬에 있어 여기서만 동작 |
| **cloudflared 터널** | UP | **Vercel(인터넷)→우리 백엔드** 경로. 로컬 백엔드는 외부에서 직접 못 닿아 터널로 공개(포트포워딩 회피) |
| **로컬 시뮬 3000** | UP | **로컬 검증/fallback**. `VITE_FASTAPI_URL=localhost:8090`로 백엔드에 직접 → 터널/Vercel 없이도 바로 확인 |

### 왜 이렇게(이중 경로)?
1. **Vercel 경로**: 배포본 시연용. 단 로컬 백엔드 공개(터널) + Vercel env + 재배포 필요, URL 휘발성.
2. **로컬 경로**: 터널/배포가 막혀도 **`localhost:3000`만 열면** churn·액션 즉시 검증. 의존성(인터넷·터널) 0.
→ 둘을 동시에 띄워, **어느 쪽이 막혀도 데모/검증이 끊기지 않게** 이중화. (사용자 지시: "터널 안 되면 로컬에서 바로 동작 확인")
