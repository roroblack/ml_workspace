# 14. DB 서버 추천 리스트 (Vercel + API + Postgres 전제)

전제: **Vercel 서버리스 API + Colab(학습) + Streamlit(프론트)** 가 모두 한 DB를 바라보는 구조([05-3](05-3_아키텍처_정합성_API_계층_인프라.md)). 우리 스키마([05-1] DDL)가 **PostgreSQL**(BIGSERIAL·JSONB·TIMESTAMPTZ·BYTEA)을 쓰므로 **Postgres 호환**이 필수.

> ⚠️ 무료 한도/정책은 자주 바뀝니다. 최종 선택 전 각 공식 가격 페이지 확인 권장(아래는 2026년 중반 일반 기준).

## 0. 선정 기준
1. **PostgreSQL 호환**(우리 DDL 그대로 사용)
2. **서버리스 친화 + 연결 풀링**(Vercel 서버리스는 함수마다 커넥션 → PgBouncer류 풀링 필수)
3. **Vercel 연동 쉬움**(`DATABASE_URL` 환경변수)
4. **무료/저비용 티어**(학생 프로젝트)
5. 운영 편의(대시보드·백업·브랜치)

## 1. 추천 순위

### 🥇 1순위 — Neon (서버리스 Postgres) ★기본 추천
- 순수 **서버리스 Postgres**, **scale-to-zero**(미사용 시 과금↓), **커넥션 풀링 내장**(서버리스에 최적).
- **Vercel 공식 연동**(Vercel Marketplace에서 바로 연결, `DATABASE_URL` 자동 주입).
- **브랜칭**(dev/test용 DB 분기) — 팀 협업·실험에 유용.
- 무료 티어 충분(소규모 프로젝트). → **우리 구조에 가장 잘 맞음.**
- 단점: 순수 DB만(인증/스토리지 없음 — 우리는 얼굴로그인 자체 구현이라 무방).

### 🥈 2순위 — Supabase (Postgres + 부가기능) ★올인원 원할 때
- **Postgres** + **Auth·Storage·Realtime·자동 REST/GraphQL·관리 UI** 포함.
- 장점: 대시보드/실시간 구독, 스토리지(샘플 이미지), 관리 콘솔이 강력 → **프론트 기능 많을 때 생산성↑**.
- 우리 프로젝트와 궁합: **실시간 이탈률 갱신·관리자 대시보드**에 Realtime 활용 가능. 단 얼굴로그인은 우리가 직접 하므로 Auth는 선택.
- 단점: 무료 프로젝트는 **일정 기간 미사용 시 일시정지(pause)**, 기능이 많아 학습 곡선 있음.

### 🥉 3순위 — Vercel Postgres (Neon 기반) ★설정 최소
- Vercel 마켓플레이스 통합(내부적으로 Neon 등). **Vercel만 쓰면 설정이 가장 단순**.
- 장점: 배포·환경변수·DB가 한 콘솔. 
- 단점: Vercel 생태계 종속, 한도/가격이 직접 Neon 쓰는 것보다 빡빡할 수 있음.

### 후보(차순위)
| 서비스 | 메모 |

## 2. 최종 권고
- **기본: Neon** — 서버리스 Postgres + Vercel 공식 연동 + 풀링 + 브랜칭. 우리 구조(서버리스 API)에 가장 정합.
- **부가기능(실시간·관리UI·스토리지)을 적극 쓰고 싶다면: Supabase**.
- **설정을 최소화하고 Vercel에 올인하면: Vercel Postgres(Neon 기반)**.

→ **결정 트리**: "순수 DB·서버리스 최적화" → Neon / "Auth·Realtime·Storage 한 번에" → Supabase / "Vercel 콘솔 하나로 끝" → Vercel Postgres.

## 3. 공통 적용 주의 (어느 걸 골라도)
- **연결 풀링 URL 사용**(Neon/Supabase는 풀러 엔드포인트 별도 제공) — 서버리스 함수 커넥션 폭주 방지.
- `DATABASE_URL`은 **Vercel/서버 환경변수**에만. Streamlit·브라우저 노출 금지([05-3] 규칙).
- **SSL 필수**(`sslmode=require`).
- 무료 티어 **용량·일시정지** 정책 확인(데모 직전 깨우기).
- 민감정보(얼굴 임베딩)는 **암호화 컬럼(BYTEA)** + 접근 권한 분리([05-1] `face_user`).

## 4. 빠른 시작(예: Neon)
1. Neon 프로젝트 생성 → 풀링 연결문자열 복사
2. Vercel 프로젝트 환경변수 `DATABASE_URL` 등록(+ `DB_SSL=require`)
3. `db/schema.sql` 실행([05-1] DDL)
4. `db/db_client.py`에서 `psycopg`/`asyncpg`로 접속 → insert/select 공통 함수
5. Colab은 동일 `DATABASE_URL`로 접속(읽기/쓰기 권한 분리 권장)
