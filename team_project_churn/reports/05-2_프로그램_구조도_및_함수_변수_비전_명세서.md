## 3. DB 서버 설계

### 3.1 DB 중심 원칙

| 원칙 | 설명 |
| --- | --- |
| 모든 원천 이벤트는 DB에 저장 | REES46 원본과 Streamlit 실시간 입력을 모두 DB에 남김 |
| ML/Colab도 DB에서 읽고 DB에 씀 | Colab은 CSV가 아니라 DB 테이블을 기준 데이터로 사용 |
| 프론트엔드도 DB/API에서 읽고 씀 | Streamlit은 직접 DB 연결 또는 Vercel API를 통해 데이터 조회 |
| 모델 파일만 파일 시스템에 저장 | `.pth`, `.joblib`, scaler는 `models/`에 저장하고 메타정보는 DB 등록 |
| 민감정보는 분리/암호화 | 얼굴 임베딩, 로그인 로그는 별도 테이블과 권한으로 관리 |

### 3.2 핵심 테이블 초안

```sql
CREATE TABLE raw_rees46_events (
    id BIGSERIAL PRIMARY KEY,
    event_time TIMESTAMPTZ NOT NULL,
    event_type VARCHAR(32) NOT NULL,
    product_id VARCHAR(64),
    category_id VARCHAR(64),
    category_code TEXT,
    brand TEXT,
    price NUMERIC(12, 2),
    user_id VARCHAR(64) NOT NULL,
    user_session VARCHAR(128),
    source_file TEXT,
    ingested_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE realtime_event_log (
    event_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    session_id VARCHAR(128),
    event_type VARCHAR(32) NOT NULL,
    product_id VARCHAR(64),
    category_code TEXT,
    price NUMERIC(12, 2),
    event_time TIMESTAMPTZ NOT NULL,
    source VARCHAR(32) DEFAULT 'streamlit',
    value_json JSONB,
    received_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE feature_user_snapshot (
    snapshot_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    snapshot_time TIMESTAMPTZ NOT NULL,
    recency_hours DOUBLE PRECISION,
    view_count INTEGER,
    cart_count INTEGER,
    purchase_count INTEGER,
    session_count INTEGER,
    sequence_len INTEGER,
    label INTEGER,
    feature_json JSONB,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE sequence_snapshot (
    snapshot_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    snapshot_time TIMESTAMPTZ NOT NULL,
    seq_len INTEGER NOT NULL,
    sequence_json JSONB NOT NULL,
    label INTEGER,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE model_registry (
    model_id BIGSERIAL PRIMARY KEY,
    model_name VARCHAR(128) NOT NULL,
    model_type VARCHAR(64) NOT NULL,
    artifact_path TEXT NOT NULL,
    feature_schema_version VARCHAR(32),
    metrics_json JSONB,
    is_active BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE prediction_log (
    prediction_id BIGSERIAL PRIMARY KEY,
    model_id BIGINT REFERENCES model_registry(model_id),
    user_id VARCHAR(64) NOT NULL,
    session_id VARCHAR(128),
    churn_probability DOUBLE PRECISION NOT NULL,
    risk_level VARCHAR(16) NOT NULL,
    top_factors_json JSONB,
    recommended_action TEXT,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE face_user (
    user_id VARCHAR(64) PRIMARY KEY,
    display_name VARCHAR(100),
    role VARCHAR(32) DEFAULT 'customer',
    face_embedding_encrypted BYTEA,
    face_threshold DOUBLE PRECISION DEFAULT 0.45,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE face_login_log (
    login_id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64),
    success BOOLEAN NOT NULL,
    similarity DOUBLE PRECISION,
    failure_reason TEXT,
    login_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE retention_action_log (
    action_id BIGSERIAL PRIMARY KEY,
    prediction_id BIGINT REFERENCES prediction_log(prediction_id),
    user_id VARCHAR(64) NOT NULL,
    action_type VARCHAR(64),
    action_message TEXT,
    status VARCHAR(32) DEFAULT 'suggested',
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

## 5. 모델별 추가 전처리

DB에 저장된 데이터가 기준이더라도, 모델별 입력 형태가 달라서 추가 전처리는 필요합니다.

| 모델/화면 | 추가 전처리 | 이유 |
| --- | --- | --- |
| LogReg/GBM/LightGBM | 결측 처리, 컬럼 순서 고정, train 기준 scaler/encoder | 2D 정형 테이블 필요 |
| XGBoost | class weight 또는 scale_pos_weight 설정 | 이탈 클래스 불균형 대응 |
| MLP | float32 변환, tensor dataset 생성 | PyTorch 입력 형식 필요 |
| LSTM | 시간순 정렬, 최근 `SEQ_MAX_LEN` 자르기, padding, mask | 시퀀스 길이 통일 |
| Transformer | LSTM 전처리 + position/time-gap feature + attention mask | padding 위치 attention 제외 |
| 실시간 예측 | DB에서 최근 이벤트 조회 후 학습 때와 동일한 변환 적용 | 학습/추론 feature drift 방지 |
| 대시보드 그래프 | 시간 단위 집계, 위험등급 bucket, 최근 예측 join | 사용자에게 보이는 요약 생성 |

중요한 규칙은 하나입니다. **스케일러/인코더/이벤트 ID 매핑은 학습 train 구간에서만 fit하고, Colab/Streamlit/Vercel API에서는 동일 artifact를 transform만 합니다.**

## 6. Streamlit 얼굴 로그인 & 대시보드 구성

`C:\Users\playdata2\Documents\ml_workspace\opencv_face_login`의 구조를 참고합니다. 핵심 기능은 `InsightFace FaceAnalysis(name="buffalo_l")`, 512차원 ArcFace 계열 임베딩, 코사인 유사도, 기본 임계값 `0.45`입니다.

### 6.1 얼굴 로그인 흐름

```
[얼굴 등록]
  -> 사용자 ID 입력
  -> 중복 ID DB 조회
  -> 카메라/이미지에서 얼굴 검출
  -> 가장 큰 얼굴 선택
  -> 512차원 embedding 추출
  -> L2 normalize
  -> embedding 암호화 후 face_user 저장

[얼굴 로그인]
  -> 카메라/이미지에서 얼굴 검출
  -> embedding 추출/정규화
  -> face_user 후보 embedding과 cosine similarity 계산
  -> similarity >= threshold 이면 성공
  -> face_login_log 저장
  -> role에 따라 고객/관리자 대시보드 분기
```

### 6.2 고객 대시보드

| 영역 | 내용 | DB/API |
| --- | --- | --- |
| 내 이탈 위험 | 현재 이탈 확률, 위험 등급 | `prediction_log` |

## 7. Vercel API 구조

Streamlit 자체는 Python 장기 실행 앱이라 Vercel 서버리스 배포와 궁합이 좋지 않습니다. 따라서 권장 구조는 다음 둘 중 하나입니다.

| 선택지 | 설명 | 추천 |
| --- | --- | --- |
| A. Streamlit은 로컬/Streamlit Cloud/Render, Vercel은 API만 담당 | 가장 현실적. Streamlit은 데모 UI, Vercel API는 DB 연동 | 추천 |
| B. Vercel에 Next.js 프론트까지 구현 | Streamlit 대신 Next.js 대시보드로 전환 | 추후 확장 |

이번 명세서는 A안을 기준으로 합니다.

### 7.1 API 엔드포인트 초안

| Endpoint | Method | 입력 | 출력 | 책임 |
| --- | --- | --- | --- | --- |
| `/api/events` | `POST` | 이벤트 payload | `event_id` | `realtime_event_log` 저장 |
| `/api/events/recent` | `GET` | `user_id`, `limit` | 최근 이벤트 | 대시보드/예측용 조회 |
| `/api/predictions` | `POST` | 예측 결과 payload | `prediction_id` | `prediction_log` 저장 |
| `/api/predictions/latest` | `GET` | `user_id` | 최신 예측 | 고객 대시보드 |
| `/api/dashboard/summary` | `GET` | 기간/권한 | 집계 통계 | 관리자 대시보드 |
| `/api/auth/login-log` | `POST` | 로그인 결과 | `login_id` | 얼굴 로그인 로그 저장 |

### 7.2 Vercel 환경변수

| 환경변수 | 의미 |
| --- | --- |
| `DATABASE_URL` | Neon/Supabase 등 Postgres 접속 문자열 |
| `DB_SSL` | 외부 DB 연결 시 SSL 사용 여부 |
| `ACTIVE_MODEL_ID` | 현재 활성 모델 ID |
| `PRED_THRESHOLD_LOW` | 낮은 위험 기준 |
| `PRED_THRESHOLD_HIGH` | 높은 위험 기준 |
| `API_SECRET` | Streamlit → Vercel API 호출 보호용 토큰 |

## 11. 주의사항

- REES46가 최종 소스이므로 모바일 게임 데이터는 이 명세서에서 제외합니다.
- Streamlit 화면, Colab 학습, Vercel API가 모두 DB를 바라보므로 스키마 변경은 반드시 문서와 함께 진행합니다.
- 얼굴 embedding은 생체정보이므로 원본 이미지 저장을 최소화하고, embedding도 암호화 저장을 원칙으로 합니다.
- Vercel API는 DB 비밀번호를 서버 환경변수에만 보관합니다. 브라우저/Streamlit 화면에 직접 노출하지 않습니다.
- 대용량 시퀀스는 DB JSON 저장보다 parquet/npz + 경로 저장이 빠를 수 있습니다. 단, MVP에서는 DB 중심 원칙을 우선합니다.
