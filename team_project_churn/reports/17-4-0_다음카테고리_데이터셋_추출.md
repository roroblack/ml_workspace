# 17-4-0. 다음-카테고리 예측 데이터셋 추출 (순서민감 과제용 데이터 기반)

코드: `nextcat_1735.py`(build_dataset) / 데이터: REES46 **2019-Nov 전체**(`src/2019-Nov.csv.zip`, 463만행)에서 추출.
용도: [17-3-5 모델비교](17-3-5_다음카테고리_모델선정.md) 및 17-4 시리즈(SASRec/BERT4Rec 등)의 **공통 데이터 기반**.

---

## 1. 과제 정의 — 왜 "다음 카테고리"인가

SASRec/BERT4Rec(시퀀스 추천 트랜스포머)가 빛나는 건 **순서민감·고차원 분류**(다음에 무엇을). 그래서 회귀(장바구니 level, [17-3-4])가 아니라:

> **세션 내 직전 L=10 이벤트 → 다음 이벤트의 `category_id`(462종) 예측.** 순서가 곧 신호. 추천(다음 관심 카테고리)과 직결.

---

## 2. 전처리 파이프라인

| 단계 | 처리 |
| --- | --- |
| 소스 | 2019-Nov 전체 463만행 로드(dtype 명시로 메모리 절감) |
| 세션화 | `user_session` 정렬, **길이 ≥ L+1(=11)** 필터 |
| 표본 | 세션 **40,000개** 추출(SESS_CAP, CPU 속도) |
| 입력피처(스텝별) | `is_view/is_cart/is_remove/is_purchase`, `gap_log`, `price_log` (수치 6) + **category_id 시퀀스**(임베딩용 인덱스) |
| 타깃 | 다음 이벤트의 category 인덱스(462 + unknown 0) |
| 윈도우 | 각 위치 t: 입력 `[t-L:t]` → 타깃 `cat[t]`, **세션당 ≤4개**(MAXWIN, 중복·속도) |
| 분할 | **user_id 단위** 75:25(누수 차단), vocab은 **train 카테고리로만** |

**누수 차단**: 입력=과거 L 이벤트만, 타깃=다음 1개. 분할 유저단위. 카테고리 vocab은 train에서만 구축.

## 3. 산출물 — 위치 · 포맷 · 용량

`team_project_churn/sample_project/data/processed_nextcat/`:

| 파일 | 용량 | 윈도우 | 내용 |
| --- | --- | --- | --- |
| **nextcat_dataset.npz** (추린·학습용) | **5.1 MB** | **143,915** (세션당 ≤4) | `X_num(·,10,6)` · `X_cat(·,10)` · `y` · `user_id` · `is_train` |
| **nextcat_dataset_fullwin.npz** (전량·보존용) | **10.7 MB** | **883,959** (MAXWIN 미적용) | 같은 40k 세션의 *모든* 윈도우 |
| nextcat_meta.json / nextcat_fullwin_meta.json | <1 KB | — | 메타 |

**두 버전을 모두 보존**(버린 것 + 남은 것):
- 추린본(143,915)은 전량본의 **세션당 균등 ≤4 무작위 부분집합**.
- 전량본은 MAXWIN으로 버려졌던 **740,044개를 복원**한 것(143,915 + 740,044 = 883,959).
- ⚠ **전량이 학습에 무조건 낫진 않음**: 긴 세션이 윈도우 수로 데이터셋을 지배 + 겹치는 윈도우는 강상관(중복) → 일반화엔 추린본이 유리할 수 있음. 그래서 *완전성=전량 / 학습=추린* 둘 다 보유가 정답.
- 원본 545.8MB → 학습셋 5.1MB(추린)/10.7MB(전량). (컬럼 추림+숫자화+압축 — *무손실 아님*, 파생 학습셋)

## 4. 설계 한계 (정직하게) ⚠

1. **카테고리(462) = 저차원·끈끈한 타깃**. 화장품 세션은 같은 카테고리를 계속 봄 → "다음 카테고리"가 너무 쉬워, [17-3-5]에서 *trivial 휴리스틱이 DL과 동률*이 나옴. **SASRec/DL의 진짜 잠재력은 `product_id`(6만+ 고차원) 레벨에서 더 드러날 것** → 후속 추출 권장.
2. **세션 4만·윈도우 ≤4 표본** = CPU 속도용 추림. 모델 *비교*엔 충분하나, **SASRec는 데이터 욕심이 커 풀데이터에서 더 유리**할 수 있음(과소평가 위험).
3. brand 42% 결측은 이 과제에선 미사용(카테고리만).

→ **다음 데이터 추출 후보**: ① `product_id` 레벨(고차원), ② 풀 세션(40k→전량), ③ 멀티타깃(다음 카테고리+행동+구매여부).
