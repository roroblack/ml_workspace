# 15. 샘플 프로젝트 계획서 (sample_project)

목적: [05-5 비전 명세서](05-5_프로그램_구조도_및_함수_변수_비전_명세서.md)의 아키텍처를 **로컬에서 즉시 실행 가능한 최소 샘플**로 구현한다. Neon·Vercel·카메라 같은 외부 의존 없이도 `python run_pipeline.py` → `streamlit run` 으로 **데이터 생성 → 학습 → DB → 실시간 예측 → 대시보드** 전체 루프가 돌게 만든다.

위치: `team_project_churn/sample_project/`

---

## 1. 범위 — 실제 구현 vs 스텁(강등)

| v5 구성요소 | 샘플에서 | 비고 |
| --- | --- | --- |
| REES46 원본 | **합성 이벤트 생성기**(`generate_sample_data.py`) | 자기완결·수초 실행. 실제는 REES46로 교체 |
| 피처/시퀀스 생성 | ✅ 실제 구현(`build_features.py`) | 파일(csv/npz) + DB 요약 |
| ML(LogReg/GBM) | ✅ 실제 | |
| DL(LSTM) | ✅ 실제 | Transformer는 확장 포인트 |
| DB(Neon Postgres) | **SQLite**(`data/churn.db`) 기본, `DATABASE_URL` 주면 Postgres | v5 스키마를 SQLite로 강등 + Postgres DDL 동봉 |
| 실시간 예측(로컬 torch) | ✅ 실제(`predictor.py`) | DB 최근 이벤트 → 시퀀스 → 예측 |
| Vercel 시뮬 사이트 | **로컬 시뮬레이터**(`simulate_events.py`) | 라이브 이벤트를 DB에 적재(사이트 대역) |
| 얼굴 로그인 | **간단 로그인 스텁** | `face_auth.py` 인터페이스만 두고 실제 InsightFace는 확장 포인트(카메라/의존성 회피) |
| 대시보드 | ✅ 실제(Streamlit) | 이탈 리스트·확률·행동그래프·개선안 |

→ "핵심 데이터·모델·예측·DB·대시보드 루프"는 **진짜로 동작**, 외부 인프라/생체인증만 스텁.

## 2. 폴더 구조

```
sample_project/
├── README.md
├── requirements.txt
├── config.py                  경로·파라미터·DB 설정
├── data/{raw, processed}      원본(합성)·피처·시퀀스
├── db/
│   ├── schema_sqlite.sql       샘플용 SQLite 스키마
│   ├── schema_postgres.sql     실제 Neon용 DDL(v5)
│   └── db_client.py            연결·초기화·insert/select (sqlite 기본)
├── src/
│   ├── generate_sample_data.py 합성 이커머스 이벤트
│   ├── build_features.py       이벤트→피처표+시퀀스(파일)+DB 요약
│   ├── train_ml.py             LogReg/GBM
│   ├── train_dl.py             LSTM
│   ├── predictor.py            모델 로드·최근이벤트→예측
│   ├── simulate_events.py      라이브 이벤트 DB 적재(Vercel 대역)
│   └── run_pipeline.py         전체 오케스트레이션
├── app/streamlit_app.py        로그인(스텁)+대시보드
└── models/                     학습 모델·전처리기
```

## 3. 데이터·라벨 설계 (샘플)
- 합성 사용자 ~2,000명, 21일 이벤트(view/cart/purchase).
- 관찰 14일 / 결과 7일 → **결과기간 무활동 = 이탈(1)** (recency형, 누수 차단).
- 정형 피처: recency·n_view/cart/purchase·n_events·active_days·avg_price.
- 시퀀스: 일별 [view,cart,purchase] 14스텝.

## 4. DB 경계 (v5 원칙 반영)
- **파일**: 원본 이벤트 csv, 시퀀스 npz, 모델 파일.
- **DB(SQLite)**: `realtime_event_log`(시뮬 라이브), `feature_user_snapshot`(요약), `sequence_snapshot`(경로), `model_registry`(경로·지표), `prediction_log`, `retention_action_log`, `face_user`, `face_login_log`.
- 모델 바이너리는 DB에 넣지 않고 경로만(`model_registry.artifact_path`).
- 스케일러는 train에만 fit → predictor는 transform만.

## 5. 실행 순서
```
python src/run_pipeline.py     # 생성→피처→학습→DB초기화·모델등록·이벤트시드·배치예측
streamlit run app/streamlit_app.py   # 대시보드(로그인 스텁→이탈 현황·실시간 예측·개선안)
python src/simulate_events.py  # (선택) 라이브 이벤트 추가 적재 후 대시보드 갱신
```

## 6. 검증 기준
- `run_pipeline.py`가 오류 없이 끝나고 모델/지표/DB 행이 생성됨.
- `predictor.predict_user(uid)`가 확률 반환.
- DB에 `prediction_log` 행 존재.
- Streamlit 앱 import/구문 OK(서버 실행은 사용자 환경).

## 7. 한계 / 확장 포인트
- 합성 데이터 → 실제는 REES46 교체(`build_features` 입력만 변경).
- 얼굴 로그인 스텁 → `face_auth.py`에 InsightFace 구현 주입(인터페이스 동일).
- SQLite → `DATABASE_URL`(Neon) 설정 시 Postgres 경로.
- 로컬 시뮬레이터 → Vercel 사이트 `/api/events`로 교체.
