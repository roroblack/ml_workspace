# 17-6-1. 백엔드 남은 작업 · DB 변경사항 (신규 전처리 데이터셋 반영)

기준: 5개월 전처리([17-5](17-5-1_5개월_전처리기술_베이지안최적화_결과.md)) + 7모델/추천 데이터셋 도입.

---

## 1. DB 변경사항

### 1.1 원칙 (변경 없음)
- **DB = 운영 데이터 / 파일 = 대용량**(05-x). 1.27M 유저 피처·시퀀스는 **DB 미적재 → parquet/npz 파일 + 경로**. Neon free(~0.5GB) 보호.

### 1.2 기존 테이블 수정
| 테이블 | 변경 | 이유 |
| --- | --- | --- |
| `model_registry` | **+컬럼**: `preprocessing_config(JSON)`, `dataset_path`, `train_period`, `metric_cv`, `metric_oot`, `model_type` | 모델별 전처리·데이터셋·성능 추적(7모델·전처리 다름) |
| `feature_user_snapshot` | **+컬럼**: `cohort_flag`, `churn`, `churn_no_purchase`, `obs_period`, `outcome_period` | 라벨 정의 변경(코호트 recency≤7, 7일 무활동) |
| `sequence_snapshot` | `artifact_path`를 5개월 npz로, **+`dataset_tag`** | 다중 시퀀스 데이터셋 구분 |

### 1.3 신규 테이블 (추천 기능)
```sql
user_interest(user_id PK, top_category_id, top_brand, interest_json, updated_at)
recommendation(rec_id PK, user_id, model_id, rec_items_json, rec_categories_json, created_at)
```
- `user_interest` ← `recommend_user_interest.parquet`에서 적재(운영 대상 유저만).
- `recommendation` ← 추천 서비스 출력 로그.

## 2. 백엔드 남은 작업

| 작업 | 내용 | 의존 |
| --- | --- | --- |
| **모델 로딩 일원화** | `model_registry` 기반 active 모델 + `preprocessing_config`·scaler(joblib) 로드 | DB 1.2 |
| **이탈 예측 서비스** | 5개월 최적 모델(GBM)+ML_opt_scaler로 스코어 | 17-5 산출 |
| **배치 스코어링** | 일/주 단위 코호트(recency≤7) 일괄 예측 → `prediction_log` | — |
| **추천 서비스 (신규)** | `user_interest`+모델 → 상품/카테고리 추천(룰 §4 가중 view1/cart3/purchase5) | 추천 데이터셋([17-6-3]) |
| **API 엔드포인트** | `/predict`, `/recommend`, `/retention-action` | 위 서비스 |
| **실시간 수집** | Vercel 시뮬 이벤트 → `realtime_event_log`(REES46 스키마) | — |
| **대시보드** | Streamlit: 이탈확률 + **추천 패널** + 리텐션 액션 | API |
| **얼굴 로그인** | 인증/권한만(학습 미사용) | — |

### 2.1 전처리 데이터셋 도입으로 *추가로* 생긴 일
- **전처리 일관성**: 학습 때 쓴 전처리(log1p+scaler 또는 raw)를 **서빙에서 transform만** 재현 → `ML_opt_scaler.joblib` 배포 필수(모델별 다름).
- **모델별 분기**: 트리(scale 불필요)/선형(scale 필요)/시퀀스(raw) → 서빙 코드가 `model_registry.preprocessing_config` 보고 분기.
- **추천/이탈 데이터 분리**: churn(유저집계) ≠ 추천(아이템단위) → 두 파이프라인 별도 운영.

## 3. 우선순위
1. `model_registry`·`feature_user_snapshot` 스키마 갱신 + `user_interest`/`recommendation` 신설
2. 모델 로딩 일원화(전처리 config 기반) → 이탈 예측 서비스
3. 추천 서비스 + API
4. 대시보드/시뮬 통합
