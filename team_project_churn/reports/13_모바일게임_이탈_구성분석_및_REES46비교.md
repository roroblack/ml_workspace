## 0. 논문 및 원본 데이터 검토

대상 논문은 Emre & Cotul의 **"Prediction of Player Churn in Mobile Games Using Classification Algorithms"**이다. PDF 본문 표기는 `JODA 2025, (4):20-29`이고 citation도 2025로 되어 있으나, DergiPark 공식 페이지의 publication date는 **2026-01-09**, published issue는 **Year 2025 Number 4**로 표시된다. 발표나 보고서에서는 `Emre & Cotul, Journal of Data Applications, no.4, pp.20-29, DOI: 10.26650/JODA.1742874`처럼 DOI와 함께 적는 편이 가장 안전하다.

출처:
- 논문 페이지: <https://dergipark.org.tr/en/pub/jda/article/1742874>
- PDF: <https://dergipark.org.tr/en/download/article-file/5056905>
- Kaggle 데이터: <https://www.kaggle.com/datasets/manchvictor/prediction-of-user-loss-in-mobile-games>

### 0.1 논문의 핵심 내용

논문은 Kaggle의 **Prediction of user loss in mobile games** 데이터를 사용해 모바일 게임 유저 이탈을 분류한다. 원본 로그를 그대로 딥러닝에 넣은 연구는 아니고, `level_seq.csv`의 레벨 플레이 로그를 유저 단위로 집계한 뒤 5개 피처로 모델을 학습했다.

| 구분 | 내용 |
| --- | --- |
| 데이터 | 2020-02-01~2020-02-04 가입/활동 유저의 레벨 플레이 로그 |
| 예측 대상 | 2020-02-07~2020-02-13 재접속 여부 기반 이탈 |
| 표본 | train 8,158명. 논문 기준 5,428명(66.54%) vs 2,730명(33.46%) |
| 입력 피처 | `success_rate`, `avg_duration`, `help_ratio`, `level_count`, `avg_reststep` |
| 모델 | Random Forest, XGBoost, Logistic Regression |
| 불균형 처리 | RF/LR은 `class_weight="balanced"`, XGBoost는 `scale_pos_weight` |
| 평가 지표 | accuracy, precision, recall |

논문 결과는 다음과 같다.

| 모델 | Accuracy | Churn Precision | Churn Recall | 해석 |
| --- | ---: | ---: | ---: | --- |
| Random Forest | 0.7003 | 0.74 | 0.84 | 전체 정확도와 이탈 탐지 균형이 가장 좋음 |
| XGBoost | 0.6954 | 0.71 | 0.90 | 이탈 recall은 가장 높지만 active 유저를 이탈로 과다 분류 |
| Logistic Regression | 0.6893 | 0.83 | 0.66 | 성능은 약간 낮지만 해석 가능성과 균형이 좋음 |

중요 피처는 모델별로 거의 일관된다.

| 모델 | 상위 피처 |
| --- | --- |
| RF | `avg_reststep`, `level_count`, `avg_duration`, `success_rate`, `help_ratio` |
| XGBoost | `level_count`, `avg_reststep`, `success_rate`, `avg_duration`, `help_ratio` |
| LR | `avg_reststep` 계수 약 +2.98, `help_ratio` 계수 약 +0.82 |

논문의 메시지는 명확하다. 레벨을 얼마나 많이 진행했는지, 얼마나 오래 플레이했는지, 실패/남은 스텝/도움 사용이 어떤지 같은 **행동 집계 피처만으로도 이탈 위험을 어느 정도 예측할 수 있다**는 것이다. 다만 논문은 DL 비교, AUC/PR-AUC, 시간 기준 split, 시퀀스 모델링은 하지 않았다.

### 0.2 원본 Kaggle 데이터 실측 구조

Kaggle API와 실제 다운로드 파일을 확인했다. 다운로드 ZIP은 약 21.5MB이고, 압축 해제 후 핵심 로그 `level_seq.csv`는 약 105.7MB다.

| 파일 | 행 수 | 컬럼 |
| --- | ---: | --- |
| `train.csv` | 8,158 | `user_id`, `label` |
| `dev.csv` | 2,658 | `user_id`, `label` |
| `test.csv` | 2,773 | `user_id` |
| `level_meta.csv` | 1,509 | `f_avg_duration`, `f_avg_passrate`, `f_avg_win_duration`, `f_avg_retrytimes`, `level_id` |
| `level_seq.csv` | 2,194,351 | `user_id`, `level_id`, `f_success`, `f_duration`, `f_reststep`, `f_help`, `time` |

실측 요약:
- 전체 유저: 13,589명.
- train/dev/test 전원 `level_seq.csv`에 로그 존재.
- 시간 범위: **2020-02-01 00:00:20 ~ 2020-02-04 23:59:59**.
- 사용자별 플레이 attempt 수: 최소 2, 중앙값 108, p75 213, p90 373, p95 493, p99 798, 최대 4,122.
- 레벨 수: 1,509.
- 전체 attempt 승률: 약 52.8%.
- 도움 사용 비율: 약 4.4%.
- 평균 attempt duration: 약 108.1초.

이 구조는 단순 정형 데이터가 아니라 **timestamp가 있는 레벨 단위 이벤트 로그**다. 따라서 유저별 또는 세션별로 정렬하면 LSTM/Transformer 입력 시퀀스를 만들 수 있다. 이 점은 Bank Churn, Telco Churn 같은 정적 이탈 데이터보다 훨씬 좋다.

### 0.3 가장 중요한 주의점: 라벨 0/1 정의 충돌

Kaggle 원문 설명은 `label`을 **1 = lost, 0 = retained**라고 설명한다. 반면 Emre & Cotul 논문 Table 3은 **0 = passive/churned, 1 = active/retained**라고 적는다. 두 출처의 라벨 방향이 반대다.

원본 행동 평균을 보면 Kaggle 설명 쪽이 더 자연스럽다.

| label | 유저 수(train+dev) | 평균 attempt 수 | 평균 max level | 평균 success rate |
| --- | ---: | ---: | ---: | ---: |
| 0 | 7,185 | 199.98 | 153.36 | 0.629 |
| 1 | 3,631 | 87.80 | 84.57 | 0.758 |

`label 0` 유저가 훨씬 많이 플레이하고 더 높은 레벨까지 도달한다. 이탈을 `label 1`로 보는 Kaggle 설명과 우리 실험 설정이 더 설득력 있다. 따라서 이 데이터를 프로젝트에 사용할 때는 **positive class = 1 = lost/churn**으로 고정하고, 논문 수치를 인용할 때는 "논문은 라벨 설명에 혼선이 있음"을 명시하는 것이 좋다.

### 0.4 실제 프로젝트 사용 가능성 판정

결론부터 말하면 **사용 가능하다. 다만 메인 데이터셋 교체용보다는 REES46의 결론을 보강하는 보조 실험 데이터로 쓰는 것이 가장 좋다.**

사용하기 좋은 이유:
- 실제 이탈 라벨이 있다. REES46처럼 우리가 라벨을 설계해야 하는 부담이 적다.
- timestamp가 있는 이벤트 로그라서 시퀀스 DL 실험이 가능하다.
- 유저당 시퀀스 길이 중앙값이 108로 충분하다.
- train/dev/test 사용자가 모두 로그를 갖고 있어 결측 구조가 단순하다.
- 게임 도메인은 "난이도 상승, 연속 실패, 도움 사용, 짧은 플레이 후 이탈"처럼 순서 신호가 자연스럽다.

주의해야 할 이유:
- 관찰 기간이 4일뿐이라 장기 고객 이탈이라고 보기 어렵다.
- test 라벨은 공개되지 않으므로 프로젝트 평가는 train+dev 재분할로 해야 한다.
- Kaggle 라이선스가 `Unknown`으로 표시된다. 공개 제출물/배포물에 원본 데이터를 포함하면 안 되고, 출처 링크만 제공하는 편이 안전하다.
- 논문은 시퀀스 DL 비교가 아니라 유저 단위 집계 ML 비교다.
- 라벨 0/1 설명 충돌이 있어 전처리 코드와 리포트에서 반드시 방향을 고정해야 한다.

우리 프로젝트에서의 권장 포지션:
- **메인 스토리**: REES46로 "실제 커머스 로그 기반 라벨 설계와 ML/DL 비교"를 유지.
- **보조 스토리**: Mobile Game User Loss로 "실제 이탈 라벨이 있는 순서형 로그에서도 라벨 성격에 따라 ML/DL 승자가 달라진다"를 검증.
- **발표 활용**: "논문은 집계 피처 ML까지만 했지만, 우리는 같은 데이터에서 세션/시퀀스 라벨을 설계해 DL 비교까지 확장했다"라고 말하면 차별점이 선명하다.

최종 판정:

| 항목 | 판정 |
| --- | --- |
| 논문 참고 가치 | 높음. 모바일 게임 이탈 문제 정의와 기본 피처 엔지니어링 참고에 좋음 |
| 데이터 사용 가치 | 높음. 실제 timestamp 로그와 공식 라벨이 있어 실험 가능 |
| 메인 데이터셋 적합성 | 보통. 도메인이 게임이고 기간이 짧아 커머스 프로젝트의 주 데이터로는 약함 |
| 보조 검증 데이터 적합성 | 매우 높음. REES46 결론을 다른 도메인에서 재검증하기 좋음 |
| DL 비교 가치 | 높음. 원본 로그를 시퀀스로 쓰면 논문보다 확장성이 큼 |

## 2. ML / DL 적합성 평가

## 3. 동일 환경 결과 (게임)

라벨 정의: **base**=공식 이탈(고객) · **A**=세션(30분gap) 단위 "마지막 세션=즉시이탈"(순서형) · **B**=관찰(2/1~3)→결과(2/4) 미활동(recency형) · **C**=다음 플레이까지 시간 회귀.

### 분류 (AUC / PR-AUC)

| LogReg (tab) | 0.791 | 0.593 | 0.750 |
| **GBM (tab)** | 0.791 | 0.638 | **0.811** |
| MLP (tab DL) | **0.792** | 0.638 | 0.802 |
| LSTM (seq DL) | 0.771 | 0.722 | 0.729 |

## 4. REES46 ↔ 게임 교차 비교 (핵심)

| 라벨 | REES46 정형 / 시퀀스 | 게임 정형 / 시퀀스 | 시퀀스 DL 우위? |
| --- | --- | --- | --- |
| base | 0.803 / 0.795 | 0.792 / 0.780 | 둘 다 정형 |
| **A** | 0.929 / **0.930** (근소) | 0.638 / **0.725** (압승) | **둘 다 시퀀스, 게임은 결정적** ⭐ |
| B | **0.796** / 0.787 | **0.811** / 0.770 | 둘 다 정형 |
| C(MAE) | GBM 0.668 / **LSTM 0.585** | **GBM 5.82** / LSTM 7.34 | REES46=시퀀스, 게임=정형 |

### 결론
1. **"라벨의 성격이 승부를 가른다"가 두 데이터에서 일관**: 계정 이탈(base)·recency(B)는 정형, 순서형(A)은 시퀀스.
2. **게임 Label A가 시퀀스 DL의 결정적 승리 사례**: 정형 0.638 → 시퀀스 **0.725**(+0.087), PR-AUC 약 **2배**. e커머스 A(REES46)는 cart 같은 집계가 이미 강해 근소차였지만, **게임 세션은 "난이도 급상승 → 연속 실패 → 이탈"의 순서 신호가 집계로 안 잡혀** 시퀀스 DL이 크게 앞섰다. (GBM은 A에서 Recall 0.000으로 사실상 무력)
3. **C는 데이터 의존**: REES46은 시퀀스가 MAE 우위였으나, 게임 C는 다음 플레이 시점이 집계(recency)에 강하게 좌우돼 정형이 우위.

## 5. 발표 메시지
- **"실제 이탈 라벨을 가진 게임 데이터에서도, 계정 이탈은 정형 ML이 최선이고, '세션 흐름(마지막 세션=즉시 이탈)'으로 정의하면 시퀀스 DL(Transformer)이 정형을 +0.09 AUC·PR-AUC 2배로 압도한다."**
- → 시퀀스 DL이 가치를 내는 조건이 **"순서가 결과를 만드는 게임 세션"** 에서 가장 선명하게 드러남.
