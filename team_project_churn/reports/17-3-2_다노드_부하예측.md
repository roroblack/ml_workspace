# 17-3-2. 다노드 부하 예측 — RNN계열이 트리를 이기는 *정확한 경계* (레짐 B)

코드: `forecast_node_load.py`(B: 관측가능 부하), `forecast_accum.py`(B-2: 적분 필요 잠재상태).
산출: `sample_project/outputs/realtime/forecast_node.json·png`, `forecast_accum.json·png`.
선행: [17-3-1 유저 부하 궤적](17-3-1_유저활동부하_궤적예측.md). "노드 하나의 부하가 커지는 시계열이라야 RNN이 이긴다"는 가설의 정밀 검증.

---

## 0. 한 줄 결론

> **시계열·부하 예측이라고 RNN이 이기는 게 아니다.** lag로 관측 가능한 상태면 **GBM**이 이기고(B),
> **상태가 직접 안 보여서 관측(증분)을 적분해야 하고 + 포화 비선형**이 끼면 **GRU/Transformer**가 GBM을 이긴다(B-2).
> → RNN 승리의 진짜 조건은 "부하가 커진다"가 아니라 **"예측에 필요한 상태가 lag에 노출되지 않고, 순환으로 적분해야 얻어진다"**.

---

## 1. B — 관측 가능한 부하 (모멘텀+포화+계절+충격)

동역학을 의도적으로 RNN에 유리하게 구성: 잠재수요 `d_t = a·d_{t-1} + 계절 + 추세 + 충격`(모멘텀), 부하 `load_t = sigmoid(k(d_t−d0))`(포화).
**입력에 부하 자체(load)를 24스텝 lag로 제공**. 400노드·14,000윈도우. 입력24→출력12스텝, 노드단위 75:25.

| 모델 | RMSE↓ | overload AUC↑ |
| --- | --- | --- |
| Ridge | 0.1335 | 0.9712 |
| **GBM** | **0.1295** | **0.9738** |
| MLP | 0.1339 | 0.9712 |
| LSTM | 0.1386 | 0.9677 |
| GRU | 0.1412 | 0.9677 |
| Transformer | 0.1402 | 0.9695 |
| naive(지속) | 0.5133 | 0.7106 |

![B observable](../sample_project/outputs/realtime/forecast_node.png)

**해석**: 6모델 거의 동률(0.13대), **GBM 근소 최고**. naive만 크게 뒤짐. 모멘텀·포화·계절이 있어도 **부하를 직접 lag로 주면 그 lag가 충분통계량** → 순환 불필요. (M5 대회에서 LightGBM이 DL을 이긴 것과 같은 현상.)

---

## 2. B-2 — 적분이 필요한 잠재상태 (관측=증분만) ★역전 발생

핵심 변경: **상태(수준 level)를 직접 주지 않는다.** 관측 입력은 **증분(inflow, 노이즈 포함)만**, 실제 수준은 그 (감쇠)누적:
`level_t = clip(ρ·level_{t-1} + g·inflow_t, 0, 1)` (적분 + 포화). 타깃 = 향후 수준/과부하.
→ 트리는 **'합(적분)'을 분기로 흉내내기 어렵고**, 순환(RNN)·어텐션은 자연히 누적. 동일 입력·동일 분할.

| 모델 | RMSE↓ | overload AUC↑ |
| --- | --- | --- |
| Ridge | 0.2532 | 0.9833 |
| GBM | 0.0864 | 0.9966 |
| MLP | 0.0787 | 0.9975 |
| LSTM | 0.1079 | 0.9965 |
| **GRU** | **0.0710** | **0.9979** |
| Transformer | 0.0720 | 0.9974 |
| naive | 0.2910 | 0.8996 |

![B-2 integrate](../sample_project/outputs/realtime/forecast_accum.png)

**해석 (역전)**
- **GRU(0.0710)·Transformer(0.0720)가 GBM(0.0864)을 명확히 이김** — RMSE 약 **18% 낮음**. 드디어 DL 승.
- **호라이즌이 길수록 격차 확대**(그림 좌측): 적분 오차가 누적되는 장기예측에서 순환의 상태 추적이 빛남.
- **Ridge는 최악(0.253)** — 적분은 선형이라 되지만 **clip 포화 비선형**을 못 따라감. (적분만으론 부족, 비선형까지 필요)
- **GBM이 중간(0.086)** — lag 증분으로 합을 근사하지만 트리 분기로는 한계. **LSTM(0.108)은 GRU보다 뒤짐**(이 규모·과제에선 GRU가 더 안정).
- MLP(0.0787)도 GBM보다 좋음 — 충분한 비선형 용량이 있으면 합성을 학습. 그래도 **시퀀스 구조를 쓰는 GRU/Transformer가 최고**.

---

## 3. 종합 — 경계의 지도

| 조건 | B (관측가능) | B-2 (적분필요) | 17-3-1 (실유저) |
| --- | --- | --- | --- |
| 상태가 lag에 노출? | ✅ | ❌(증분만) | ✅(recency) |
| 적분/누적 필요? | 약함 | **강함** | 약함 |
| 포화 비선형? | 있음 | **있음** | 없음 |
| **승자** | **GBM** | **GRU/Transformer** | **GBM** |

→ **RNN이 이기려면 세 가지가 동시에**: ① 예측에 필요한 **상태가 입력 lag에 직접 안 보임**(증분/부분관측), ② **적분(누적)** 으로만 상태 복원, ③ **비선형**(포화/리셋)까지. 하나라도 빠지면(B, 17-3-1) 트리가 이긴다.

---

## 4. 우리 프로젝트에의 함의

1. **핵심 churn(이탈 예측)에는 경량 ML(GBM)을 쓴다** — 실유저 데이터(17-3-1)·관측가능 신호(B)는 전부 트리 우위. [17-2](17-2_초단위_실시간_세션이탈_프로토콜.md)의 결정(경량 ML 실시간 스코어러)을 3개 실험이 재확인.
2. **RNN/시퀀스는 "적분형 잠재상태" 문제에 배치** — 예:
   - **운영 부하 예측**: 우리 실시간 예측서버/DB의 큐·동시접속을 *처리량(throughput) 로그(증분)* 만으로 향후 과부하 예측 → 오토스케일. (B-2가 바로 이 형태) → **GRU 권장**.
   - **누적형 churn 신호**: "불만 누적", "미해결 문의 적체" 같이 *증분 이벤트는 보이지만 누적 상태는 미관측* 인 라벨 → 시퀀스 모델 후보.
3. **발표 메시지**: "DL을 안 쓴 게 아니라, **언제 DL이 이기는지 경계를 실측으로 그었다**" — B-2에서 GRU가 GBM을 18% 앞서는 명확한 반례까지 제시.
