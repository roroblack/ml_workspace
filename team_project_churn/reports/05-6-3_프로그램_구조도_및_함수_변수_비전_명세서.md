# 05-6-3. 프로그램 구조도 · 함수/변수 비전 명세서 (통합 단일 프로젝트 — 백엔드 통합판)

정정: 이전 05-6/05-6-2에서 백엔드를 별도 `backend/` 폴더로 분리한 것은 **잘못**이었다. 사용자가 처음 제시한 **단일 통합 구조**(`db/` + `vercel_site/api/` + `configs/` …) 안으로 **백엔드를 통합**한다. `preprocessing_project/`·`sample_project/`는 **전처리·실험(테스트) 용도**이며, **실제 산출은 아래 단일 구조 하나**에서 이뤄진다고 가정한다.

> 실행 정정 완료: 분리됐던 `backend/`를 해체해 `sample_project/db/`(SQL·계약)와 `sample_project/vercel_site/api/`(Node API)로 이동, `backend/` 폴더 **삭제**. (sample_project = 이 통합 구조의 레퍼런스 구현체)

---

## 2. 백엔드 통합 매핑 (구 backend/ → 통합 구조 어디로)
| 구 `backend/` 파일 | 통합 위치 | 비고 |
| --- | --- | --- |
| `schema_mysql.sql` | `db/schema_mysql.sql` | 운영 MySQL DDL |
| `seed.sql` | `db/seed_mysql.sql` | 운영 시드 |
| `CONTRACT.md` | `db/CONTRACT.md` | 모델→서버 계약 |
| `server.js` | `vercel_site/api/server.js` | 전 엔드포인트(추론 X) |
| `db.js` | `vercel_site/api/db.js` | MySQL/Neon 연결 |
| `check.js`/`package.json`/`.env.example`/`README.md` | `vercel_site/api/` | API 부속 |
| (폴더 `backend/`) | **삭제** | 별도 분리 폐기 |

→ **"백엔드"는 폴더가 아니라 계층**이다: `db/`(DDL·연결) + `vercel_site/api/`(Thin 엔드포인트) + `frontend_streamlit/services/`(호출). 별도 서버 폴더 없음.

## 3. 구조조정 — 원래 구조에서 "무엇을 어떻게" 수정해야 하나
| 폴더 | 원래(05-5) | 수정/추가(현재 작업 반영) |
| --- | --- | --- |
| `db/` | Neon(Postgres) 중심 | **운영=MySQL**(`schema_mysql.sql`: model_registry 확장·prediction_log·feature_user_snapshot(라벨2종·cohort_flag)·sequence_snapshot(**+seq_type**)·user_interest·recommendation·ensemble·retention), **Neon=시뮬 로그 전용**. `CONTRACT.md` 추가 |
| `configs/feature_schema.yaml` | 7피처(일별) | **v2 27피처**(category/brand/세션/remove/price 살림) + 시퀀스 채널. `cohort_recency7` 플래그 |
| `src/build_features.py` | RFM 7~10피처 | **pp_features 로직 채택**: raw→27피처(전체 모집단+코호트 플래그). `build_catalog.py`(추천) 추가 |
| `src/` (신규) | 없음 | **`eval_package.py`**: 학습 후 `eval_predictions.parquet`+curves+`manifest.json` 저장(발표 그래프 8·9·10·11·12·14 토대) |

| `vercel_site/api/` | events·predictions·dashboard·login-log(Thin) | **+ models/submit·predict·recommend·retention·ensemble**, **manifest ingest**(요약+경로 DB 저장)·chart API |
| `models/` | tabular/sequence | **+ preprocessors/**(prep_*.joblib, 전처리+보정+임계값 영속) |
| 모델 학습 | auc/f1 일부만 저장 | **검증 산출물 패키지 의무화**(eval_package 호출) → 발표 시각화 전부 가능 |

## 4. 검증 산출물 패키지 (발표 그래프 활성화 — db/CONTRACT.md 확장)
학습 파이프라인이 모델 외에 다음을 **반드시** `outputs/eval/<model>/` 에 저장:
- `eval_predictions.parquet`(user_id·model·split·y_true·y_score·y_pred·cohort_flag·revenue·top_category·top_brand) ← **핵심**(8·9·10·11·12·14 계산 가능)
- `training_history.json`(DL/부스팅만), `*_curve.json`(파생/캐시), `shap_summary.json`(트리=TreeSHAP), `business_value.json`(가정 명시 필수), `manifest.json`(위 경로·메타·스키마버전·seed)
→ `vercel_site/api`가 `manifest.json`을 ingest, **DB엔 요약+경로**, 프론트(Streamlit)엔 chart API로 제공.

## 5. 프로젝트 폴더 관계 (정리)
- **단일 통합 구조(위 §1)** = 실제 산출 본체.
- `preprocessing_project/` = **전처리 버전관리·실험(테스트)**. 여기서 검증된 `pp_features`/`pp_catalog`/`models_bayes` 로직이 **`src/`로 채택**됨.
- `sample_project/` = 이 통합 구조의 **현재 레퍼런스 구현체**(db/·vercel_site/api/·frontend_streamlit/ 포함). 백엔드는 여기 `db/`+`vercel_site/api/`에 통합됨.
- **별도 `backend/` 폴더 없음.**
