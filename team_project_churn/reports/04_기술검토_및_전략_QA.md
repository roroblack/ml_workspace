| 모델 | Acc | Recall | F1 | AUC |
| --- | --- | --- | --- | --- |
| HistGB(튜닝) | 0.871 | 0.482 | 0.602 | **0.871** |
| HistGB + SMOTE | 0.840 | 0.663 | 0.628 | 0.867 |

## 1. ml_unified_lab에 16일자까지 반영 시 어떤 모델?

이탈 예측 = **정형(표) 데이터 이진분류** → 모델 선택은 명확:
- **주력: 그래디언트 부스팅 계열**(HistGradientBoosting / GradientBoosting) — 정형 데이터 최강
- **보조 ML**: RandomForest, LogisticRegression(해석용 베이스라인)
- **딥러닝 대표**: MLP(torch)

**16일자(LSTM/DCGAN)는 정형 churn엔 직접 부적합**하지만 이렇게 연결 가능:
- **LSTM** → 고객 **구매/이용 시퀀스**(시간순)를 쓸 때만 유효 → online retail 경로(아래 6번)와 연결
- **DCGAN/GAN** → 소수 클래스(이탈) **데이터 증강** 아이디어(실무는 SMOTE가 간단·안정)

→ 권장: churn tabular 데이터셋 등록 + **HGB(주력)+RF+LogReg+MLP**. LSTM은 "정형이면 GBM, 시퀀스면 LSTM" 비교 포인트로 활용.

## 2. 더 좋은 모델이 있을까?

- AUC 기준 HistGB 튜닝 0.871로 미세 1등이나 **사실상 천장(~0.87)**. XGBoost/LightGBM/CatBoost도 0.86~0.88 밴드(큰 차이 X, CatBoost는 범주형 강점).
- **진짜 향상은 모델 교체가 아니라**: ① 임계값 조정(0.5→0.33: F1 0.60→0.64) ② SMOTE/가중치(Recall↑) ③ 스태킹·피처 엔지니어링
- 발표 메시지: *"모델 경쟁보다 불균형·임계값·피처가 성능을 좌우"*

## 4. 추가 도입 기술

- **불균형**: SMOTE/ADASYN, class_weight, focal loss, 임계값 최적화, cost-sensitive
- **모델**: XGBoost/LightGBM/CatBoost, Stacking/Voting
- **튜닝/검증**: Optuna(ml_unified_lab 내장), Stratified K-Fold, 확률 보정
- **해석**: **SHAP**(개별 이탈 사유→리텐션 연계, 임팩트 큼), permutation importance
- **파이프라인/배포**: sklearn Pipeline(누수 차단), MLflow(실험추적), FastAPI/Streamlit 데모
- **피처 엔지니어링**: 잔액 0 여부, 나이 구간화, 상호작용, (거래데이터면) RFM

## 5. 데이터셋 출처 + 전처리

- 출처: ① 강사 제공 최우선 ② Kaggle Telco/Bank Churn ③ UCI. (현재 Bank Churn 사용)
- 전처리 표준: 식별자 제거 → 결측 처리 → 이상치 점검(IQR, 무조건 삭제X) → 범주형 인코딩 → 스케일링 → 층화분할 → 불균형은 학습단계 → **누수 방지(train에만 fit, Pipeline)**

## 6. online+retail 데이터 사용에 대한 의견

- Online Retail(UCI)은 **거래 데이터로 이탈 라벨이 없음** → 타깃을 직접 설계해야 함(관찰기간 분할 + "최근 N일 미구매=이탈", RFM 피처).
- **장점**: 실무에 가까움, 피처 엔지니어링·RFM 역량, 시퀀스화 시 **LSTM 정당 활용**(전 학습 범위 연결)
- **단점**: 라벨 정의 주관적, 시간 분할·집계 작업 多, **누수 위험**, 2일 일정엔 빠듯
- **권장**: 안전하면 Bank/Telco로 완성 + retail은 EDA/RFM 보너스. 도전하려면 retail→RFM+이탈라벨→GBM/LSTM (시간분할 검증 필수). → 상세는 `plans/C_...` 참고.
