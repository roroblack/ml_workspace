# 17-6-3. 추천 전용 데이터셋 — 5개월 풀 추출

코드: `rec_extract_5m.py` / 데이터: REES46 5개월 풀(2,069만 이벤트). 산출: `data/processed_rec/`.
배경: churn 집계 테이블(유저별 RFM)로는 아이템 추천 불가(product/category 버림) → **추천 전용 view를 원본에서 별도 추출**. 룰 §4 준수(REES46 필드만).

---

## 1. 무엇을 추출했나 (룰 §4 가중치)
이벤트 가중 **view=1 · cart=3 · purchase=5 · remove_from_cart=−1** 로 유저별 관심도 집계:
- 유저 × **category_id** 가중합 → 상위 카테고리
- 유저 × **brand** 가중합 → 상위 브랜드
- 글로벌 **product_id** 인기(콜드스타트용)

월별 순차 처리(메모리 안전, 풀데이터).

## 2. 산출물 — 위치/형태/용량
`sample_project/data/processed_rec/`:

| 파일 | 용량 | 내용 |
| --- | --- | --- |
| **rec_user_interest_5m.parquet** | 13.9 MB | 유저별 `top_category_id·cat_score·top_brand·brand_score` (**163.9만 유저**) |
| **rec_user_top_categories.parquet** | 17.2 MB | 유저 × **상위 5 카테고리**(rank·score) — 추천 후보 |
| rec_item_popularity.parquet | 12 KB | 글로벌 인기 상품 top1000(콜드스타트) |
| meta_rec.json | — | 메타 |

**규모**: 유저 1,639,358 · 카테고리 525 · 브랜드 274 · 상품 54,571.

## 3. churn 데이터와의 차이 (왜 별도인가)
| | churn 데이터(processed_5m) | 추천 데이터(processed_rec) |
| --- | --- | --- |
| 단위 | 유저 1명 = 1행(RFM 집계) | 유저 × 아이템(카테고리/브랜드) |
| 보존 컬럼 | event_type 카운트만 | **category_id·brand·product_id** |
| 용도 | 이탈 0/1 예측 | 관심 카테고리/브랜드/상품 추천 |

→ **같은 원본의 다른 view**. 원본(360MB zip)은 그대로라 두 view 모두 derived.

## 4. 활용 (룰 §4 / 05-x)
- **추천 서비스**: `rec_user_interest`(유저 관심) + `rec_user_top_categories`(후보) → 고위험 유저에게 관심 카테고리/브랜드 추천.
- **콜드스타트**: 신규/이력부족 유저 → `rec_item_popularity` 인기 상품.
- **시퀀스 추천(SASRec)**: [nextcat](17-4-0_다음카테고리_데이터셋_추출.md) 카테고리 시퀀스와 결합 가능(다음 관심 카테고리 예측).
- **DB 적재**: `user_interest` 테이블([17-6-1](17-6-1_백엔드_DB_변경사항.md))에 운영 대상 유저만 적재(대용량은 파일 유지).
