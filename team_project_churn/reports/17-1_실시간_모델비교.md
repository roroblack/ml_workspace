## 1. 실험 설계 — "왜 이번엔 DL이 유리해야 하나"

[17-0]에서 본 것처럼, 실시간 예측은 **단일 시점 스냅샷이 아니라 매일 슬라이딩 창**으로 이뤄진다.
그래서 **각 유저의 로그를 매일 흘리며** 표본을 만든다:

- 평가일 t 마다 **직전 14일 창**을 구성
- **라벨 = (t+1 ~ t+7) 무활동이면 이탈(1)** ← 실시간 슬라이딩 라벨
- 같은 창에서 **(a) 시퀀스 `[14,3]`** 와 **(b) 집계 피처**를 동시에 생성
- 누수 차단: t까지 발생한 로그만 사용 / **user-level 75:25 분할**(유저가 train·test에 섞이지 않음)

표본: **24,711개 (user-day), 이탈률 87.6%, 3,854명**.

**핵심 가설**: 단일 스냅샷에선 recency가 *유저당 숫자 하나*였지만, 슬라이딩에선 recency가
**"14일 창 안 어디에 활동이 있는가"라는 순서 신호**로 바뀐다 → 시퀀스를 통째로 보는 **DL이 집계 ML보다 유리**해야 한다.

이를 **ablation**으로 분리한다:
`counts_only`(볼륨만) → `counts+recency`(recency 숫자 추가) → `sequence`(시퀀스 모양 전체).

## 2. recency가 어떻게 "달라졌나" — 수치화 ★

### 2.1 recency가 분포를 가진 신호가 됨
단일 스냅샷에선 recency = 유저당 고정값 1개였지만, 슬라이딩에선:

> **recency 평균 6.04일 · 중앙 6 · 표준편차 4.10 · 범위 0~13일**

즉 같은 유저도 시점마다 recency가 0→13으로 움직이는 **시변(time-varying) 신호**가 됐다.

### 2.2 recency 단조성 — 멀어질수록 이탈률 급등
| 마지막 활동 후 경과(창 끝 기준) | 표본 | 이탈률 |
| --- | --- | --- |
| 0일(오늘 활동) | 2,451 | **69.4%** |
| 1–2일 | 4,027 | 80.9% |
| 3–4일 | 3,542 | 86.8% |
| 5–6일 | 3,365 | 90.0% |
| 7–13일 | 11,326 | **93.5%** |

→ recency 한 축만으로 이탈률이 **69%→94%로 단조 상승**. 실시간 라벨에서 recency가 지배적 신호임이 확인.

### 2.3 활동량을 고정해도 recency가 따로 작동 (볼륨과 분리) ★핵심
"활동을 많이 했다"는 볼륨 신호와 별개로, **언제 했는가**(recency)가 이탈을 가른다:

| 활동량 구간 | 표본 | recency ≤1일 이탈률 | recency ≥5일 이탈률 | 차이 |
| --- | --- | --- | --- | --- |
| 하 (n_events 1) | 11,649 | 90.3% | 96.4% | +6.1p |
| 중 (n_events 1–3) | 16,942 | 87.4% | 95.1% | +7.7p |
| **상 (n_events 3–410)** | 9,595 | **59.4%** | **87.7%** | **+28.3p** |

→ **활동량이 많은 유저일수록 recency의 영향이 폭발적**(+28p). 볼륨만 보면 "활발한 고객"이지만,
그 활동이 **창의 앞쪽에 몰려 있고 최근이 비면** 이탈 임박 — 이건 *집계 카운트로는 안 보이고 순서(시퀀스)로만 보이는* 신호다.

## 3. 모델 비교 결과 (test, user-level holdout)

| 입력 | 모델 | ROC-AUC | PR-AUC |
| --- | --- | --- | --- |
| **counts_only**(볼륨만) | LogReg | 0.7281 | 0.9372 |
| | GBM | 0.7227 | 0.9355 |
| | MLP | 0.6976 | 0.9275 |
| **counts+recency**(숫자 추가) | LogReg | 0.7377 | 0.9404 |
| | **GBM** | **0.7473** | 0.9453 |
| | MLP | 0.7355 | 0.9406 |
| **sequence**(시퀀스 전체) | LSTM | 0.7479 | **0.9466** |
| | GRU | 0.7467 | 0.9460 |
| | **Transformer** | **0.7500** | 0.9461 |

**ablation 사다리 (각 단계 최고)**
- counts_only 0.7281 → **+recency 0.7473 (+1.9p)** → **sequence 0.7500 (+0.3p)**

## 4. 해석 — 가설은 맞았다, 다만 정직하게

1. **예상대로 DL이 최상위.** 최고 성능은 **Transformer 0.7500**, LSTM 0.7479 가 뒤를 잇고, **세 DL이 모두 counts_only ML 전부를 능가**. PR-AUC도 DL이 최고(0.9466). → "시계열이 확실히 들어가니 DL이 더 잘 나온다"는 가설 **방향 확인**.
2. **그러나 마진은 얇다(+0.27p).** GBM에 **recency 숫자 하나만 줘도 0.7473**으로 DL 무리를 거의 따라잡는다. 왜? 이번 라벨이 **"향후 7일 무활동"** 이라 *마지막 활동까지의 거리(recency scalar)* 가 신호의 대부분을 이미 요약하기 때문.
3. **큰 도약은 counts→+recency(+1.9p)**, 작은 도약은 +recency→sequence(+0.3p). 즉 **"recency가 중요해졌다"는 압도적으로 사실**이고(2장), **"시퀀스 모양이 recency 숫자 너머로 주는 추가 이득"은 이 라벨에선 작다**.
4. **언제 DL 마진이 커지나** → 라벨이 *순서에 민감*할 때. 단일 recency 숫자로 요약 안 되는 **세션 단위 이탈(라벨 A)·전환 경로·이벤트 순서** 라벨에서는 [11]에서 본 것처럼 DL이 GBM을 분명히 앞선다(게임 라벨 A: Transformer 0.725 vs GBM 0.638). 이번 7일-무활동 라벨은 그 중간으로, **DL이 이기되 근소**.

> 결론: **"시계열을 넣었더니 recency가 시변 순서 신호가 됐고(2장 수치), 그 결과 DL이 최상위(3장)"** — 가설대로다. 다만 7일-무활동 라벨은 recency scalar로도 잘 요약돼 마진이 얇다. **마진을 키우려면 순서 의존 라벨(세션·전환경로)로 가야 한다.**

---

## 5. 다음 실험 제안
1. **순서 의존 라벨로 재실험**: 세션 단위 이탈 / "장바구니→구매 미완" 같은 경로 라벨 → DL 마진 확대 검증.
2. **창 길이·예측 지평 스윕**: L=7/14/28, H=3/7/14 로 recency-요약성 vs 시퀀스-이득의 트레이드오프 곡선.
3. **시퀀스 입력 강화**: 일별 카운트 → 시간 간격(inter-event gap)·category 임베딩 step feature 추가(정형에선 무용했던 임베딩[16]이 *시퀀스*에선 유효한지).
4. **시간 분할 교차검증**: 현재 user-holdout → 앞 시점 train / 뒤 시점 test 로 더 엄격히.
5. **앙상블**: GBM(+recency) + Transformer 스태킹으로 두 신호(요약 recency + 순서) 결합.
