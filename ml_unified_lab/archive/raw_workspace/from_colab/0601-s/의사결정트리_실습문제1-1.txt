# 문제 1. 현재 모델 성능 분석 ===============================
현재 생성된 모델의 다음 성능지표를 출력하시오.

* Accuracy
* Precision
* Recall
* F1-score
* Confusion Matrix




Accuracy : 0.725
Precision : 0.7237047722081982
Recall : 0.725
F1 : 0.7243338616585424
Confusion Matrix :
[[113  27]
 [ 28  32]]




### 코드
```
from sklearn.metrics import accuracy_score
from sklearn.metrics import precision_score
from sklearn.metrics import recall_score
from sklearn.metrics import f1_score
from sklearn.metrics import confusion_matrix

acc = accuracy_score(y_test, predictions)

prec = precision_score(
    y_test,
    predictions,
    average='weighted'
)

rec = recall_score(
    y_test,
    predictions,
    average='weighted'
)

f1 = f1_score(
    y_test,
    predictions,
    average='weighted'
)

print("Accuracy :", acc)
print("Precision :", prec)
print("Recall :", rec)
print("F1 :", f1)

print(confusion_matrix(y_test,predictions))
```

### 질문에 대한 답을 작성하시오 : ---------------------------------------

1. Accuracy의 의미는?

전체 갯수 중에 맞춘 갯수 비율을 의미
이전의 결과를 예로 들면 전체 데이터 중 72.5 프로는 정답을 맞췄다는 의미

2. Precision과 Recall 차이는?

각각 정밀도 와 재현율을 의미

Precision 	: TP / (TP + FP)
			정밀도 :
			정답이라고 모델이 예측한 값 중 (정답과 정답으로 예측했는데 틀린 합)
			에 진짜 정답 (1) 인 것이 얼마나 있느냐를 봄
			여기서는 돈을 갚을 사람으로 예측한 사람들 중에 진짜 갚은 사람들의 비중

Recall		: TP / (TP + FN)
			재현율 :
			맞춘 것과 정답인데도 오답이라고 한 것의 합에서 정답을 찾은 비율로
			정답 검거율을 의미함
			여기서는 갚을 수 있는 고객을 얼마나 찾았나를 의미
			
			

3. 은행 대출 심사에서는 Recall이 중요한 이유는?

대출을 해줘야 하는 우량고객인데 거절한 것까지 포함한 Recall 비율을 알면 실제 대출 상환률이 높은
고객을 확보할 수 있는 것에 대한 좋은 지표가 되기 때문에 중요

## 질문 ------------------------------------------------
Entropy와 Gini 차이는?

학습데이터 등 데이터를 뽑을 때
Gini : 무작위로 뽑을 때 잘못 분류될 확률 (ex. 우량고객 100프로 뽑히고 나머지 0프로)
	(1 - (확률의 제곱))
Entropy : 얼마나 무질서한지를 확인 (분포)
	(-시그마(확률 곱하기 로그 (확률) )

지니가 연산식상 더 빠르고 (N^2) 엔트로피가 더 느림 (n승까지 나감)
결과는 엔트로피가 더 잘 분산됨. (균형잡힌 트리를 만듬)
쓰는 목적은 같음 두다 데이터를 고르게 분산해서 좋은 학습을 하기 위함

(기본값 : Gini)

### 질문 -------------------------------------------------
One-Hot Encoding이 유리한 이유는?

지난 수업에서 진행한 마지막 실습에서와 같이 각 숫자로 라벨링이 진행되었으나 해당 숫자 분류의 의미만을
가지고 숫자 자체의 크기에서는 의미가 있지 않은 경우 크기비교에 대한 학습이 진행되지 않을 수 있게 함.
원핫인코더는 모든 라벨을 0,1 참 거짓만 가지는 테이블로 분류하기 때문. 

단, 크기에 의한 오분류 실수가 없을 경우에는 지금과 같이 정확도가 같게 나올 수 있음.
또한 원핫인코딩이 되서 테이블 수가 늘어남에 따라 비교할 문제가 많아지고 이로 인해 노드의 수가 늘어나서 외히려
지금 같은 같거나 낮은 결과가 나올 수 있음


다른 로지스틱 회귀와 같은 경우는 정확도가 향상하는 걸 볼 수 있음

로지스틱 회귀 정확도
원핫인코더 적용 전 : 0.7150
원핫인코더 적용 후 : 0.7250
